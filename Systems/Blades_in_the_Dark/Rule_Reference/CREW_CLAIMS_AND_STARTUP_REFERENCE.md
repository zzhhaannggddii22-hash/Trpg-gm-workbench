# Blades in the Dark｜Crew Creation、Claims 与组织经营参考

> system_id: `blades_in_the_dark`  
> 交叉核验：官方 Crew 页面与 Full Player's Kit v8.2 六张 Crew Sheet。  
> 本文为自写规则摘要；不复制 Crew Sheet 原图或完整商业规则书。  
> 运行时只加载当前 Campaign 选定的 Crew Type、已拥有 Claims、Upgrades 与 Cohorts。

## 1. Crew 的规则身份

Crew 不只是背景组织，而是长期成长与城市关系的正式规则实体。Crew Type 决定：
- 主要业务类型，以及常见 Score / XP 触发点；
- 可选 Crew Special Abilities；
- 起始专属 Upgrades；
- Hunting Grounds 的业务偏好；
- Claim Map 的常见成长路线。

Crew Type 不禁止从事其他犯罪活动。它定义组织最常做、最容易获得 Coin 与 XP 的业务，不是行动类型限制。

## 2. Crew Creation｜组织创建

依次完成：

1. **Choose Crew Type**：选择 Assassins、Bravos、Cult、Hawkers、Smugglers 或 Shadows。
2. **Initial Reputation & Lair**：选择 Ambitious、Brutal、Daring、Honorable、Professional、Savvy、Subtle、Strange 之一，或自定义；确定巢穴地点与性质。
3. **Hunting Grounds**：选择组织日常经营的约三至四个街区（可与巢穴不在同一地区）。确定目前控制该区的派系，并选择：
   - 支付 1 Coin，换取活动空间；
   - 支付 2 Coin，取得对方 +1 Status；
   - 不支付，取得对方 -1 Status。
4. **Preferred Operation**：从该 Crew Type 的 Hunting Grounds 业务列表中选择一个偏好业务。
5. **Special Ability**：从 Crew Sheet 选择一项起始 Crew Ability。
6. **Crew Upgrades**：Crew Type 已预选两项，玩家再选择两项，总计四项起始升级。若选择 Cohort，按 Cohort 创建程序补齐。
7. **Upgrade Faction Changes**：GM 确定两个受影响派系：
   - 一个派系帮助组织取得升级：+1 Status；可支付 1 Coin 提高为 +2。
   - 一个派系因升级利益受损：-2 Status；可支付 1 Coin 降低为 -1。
8. **Favorite Contact**：从组织联系人中选一名长期盟友/朋友/犯罪伙伴。确定一个与联系人友好的派系（+1 Status）与一个敌对派系（-1 Status）；可按规则将关系强度提高至 +2 / -2。
9. **Initial Resources**：Tier 0、Strong Hold、0 Rep、2 Coin。组织专属起始升级、起始同伙、Crew Sheet 上已预选内容依所选版本核对。

## 3. Hunting Grounds 与 Preferred Operation

### BLD-CRW-HUNT-01｜偏好业务奖励

当 Crew 准备在自己的 Hunting Grounds 执行所选 Preferred Operation 时：
- 相关 Gather Information Rolls 获得 +1d；
- 获得一个免费的额外 Downtime Activity，可专门为该行动作准备，例如发现机会、获取所需资产或寻找合适客户。

这个奖励与通常的每人 Downtime Activities 次数分开记录，不应漏掉，也不能挪作无关的其他活动。取得 Turf 后，Crew 可以扩大 Hunting Grounds 的区域和/或业务类型。

## 4. Generic Crew Upgrades

| Upgrade | 规则摘要 |
|---|---|
| Boat House | 取得一艘船、码头与储物棚；第二级可改善船只护甲与载货能力 |
| Carriage House | 取得载具与马厩；第二级改善护甲与运输能力 |
| Cohort | 招募一个 Gang 或 Expert；新 Cohort 花费 2 个升级格，为 Cohort 增加新 Type 也花费 2 格 |
| Hidden Lair | 巢穴位置与外观隐蔽；被发现后可花 2 个 Downtime Activities 与等于 Crew Tier 的 Coin 迁移隐藏 |
| Mastery | 花费 4 个升级格，解锁 PC Action Rating 上限 4（未解锁前通常上限为 3） |
| Quality | 每项升级提高一种 PC 物品类别的品质：Documents、Gear、Implements、Supplies、Tools、Weapons |
| Quarters | 巢穴提供居住处；无此升级时 PC 需在外住宿，存在暴露风险 |
| Secure Lair | 巢穴具有锁、警报与陷阱；第二级加入对抗灵体的奥术防御 |
| Training | 在相应 Downtime Training 活动中，选定 XP Track 记 2 XP 而非 1 XP |
| Vault | Coin 储存上限提高至 8；第二级提高至 16；可用隔间关押俘虏 |
| Workshop | 巢穴具备修补、炼金与研究工具；可在巢穴内进行 Long-Term Projects |

专属升级只对相应 Crew Type 可用，必须按实际 Crew Sheet 核对，不应把一个组织的 Rigging、Elite Cohort 或其他专属升级跨类型调用。

## 5. Crew Advancement 与 Coin 相关字段

- Crew XP 轨填满后，组织可取得一项 Crew Special Ability 或两个 Upgrade boxes（依规则/表单执行）。
- 每次 Crew Advance 后，每名 PC 获得 Stash = Crew 当前 Tier + 2。
- Vault 容量限制只作用于 Crew Treasury 的 Coin，不与 PC 个人 Stash 混记。
- 所有升级、Tier、Rep、Turf、Hold、Coin、Vault、Heat、Wanted 与 Faction Status 变化都要保留来源事件。

## 6. Claims｜权利地图

### BLD-CRW-CLAIM-01｜Claim Map 的用途

每种 Crew Sheet 都有自己的 Claim Map。它展示该 Crew Type 的典型成长路线，从中央的 Lair 节点出发，通常沿连接路径逐步取得 Claims。路径是默认路线，不是绝对限制。

玩家可尝试夺取地图上的其他 Claim，甚至地图之外的特殊 Claim；但这类行动需要额外发现/调查，且始终特别困难，需要异常充分的努力。不要把“能选择地图上任一 Claim”误读为“跳过路径无额外成本”。

### BLD-CRW-CLAIM-02｜Seize a Claim

1. 玩家指定想夺取的 Claim。
2. GM 为该 Claim 确定位置、描述和当前控制它的 Faction；必要时给玩家多个可行选项。
3. 若不沿地图既定连接路线，需要先通过 Gather Information / 调查发现相应机会。
4. 将夺取行动作为普通 Score 运行。
5. Score 成功后，Crew 取得 Claim，原控制派系失去该 Claim。
6. 夺取通常是对原控制派系的重大攻击：通常 -2 Status；若有敌对派系受益，可能对其 +1 Status。
7. Crew 持有 Claim 期间，持续享受该 Claim 的规则收益；失去后收益立即消失。

### BLD-CRW-CLAIM-03｜Claim 丢失与 Lair

- 敌对派系可能尝试夺回 Crew 的 Claim。Crew 可以防守，或在情境允许时协商。
- 失去 Claim 后，立即失去该 Claim 的全部收益。
- 若 Crew 的 Lair 被夺走，Crew 暂时失去所有 Claims 的收益；必须通过 Score 恢复原巢穴或建立新巢穴。
- Claim 不只是被动奖励，也会改变派系关系、Score 机会和城市势力结构。

## 8. 运行时 Claim / Crew State

```yaml
crew:
  type: "<one of six>"
  tier: 0
  hold: strong
  rep: 0
  turf: 0
  coin: 2
  vault_capacity: 4
  reputation: "<chosen>"
  lair:
    location: "<district>"
    status: active
  hunting_grounds:
    district: "<district>"
    methods: []
    preferred_operation: "<one type>"
    controlling_faction: "<faction_id>"
  abilities: []
  upgrades: []
  contacts:
    favorite: "<npc_id>"
  claims:
    - claim_id: "<claim>"
      holder: crew
      location: "<place>"
      original_faction: "<faction_id>"
      benefits: []
  cohorts: []
faction_status:
  - faction_id: "<id>"
    status: 0
```

Claim 事件最小记录：
- claim_event_id；
- Claim ID、原控制派系、当前地点；
- 所属 Score / 夺取或失守原因；
- Faction Status 变化；
- 开始生效与失效时间；
- Crew 当前可用收益。
