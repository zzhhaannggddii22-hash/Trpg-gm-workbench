# Triangle Agency｜常规规则调用路由

> System: `triangle_agency` · Ruleset: 用户指定的《三角机构》中文 v22
> Status: RUNTIME INTEGRATION BASELINE
> Scope: 将系统规则知识接入 Preflight、备团、现场裁定、资源处理与收束；不复制规则原文，不改变规则权威层级。

## 1. 目的与默认行为

本文件是 Triangle Agency 系统规则的运行分派入口。GM 不应在每次规则问题出现时重新从 497 页 PDF 开始，也不应把整套规则库每次全部载入。

**默认路径：先读结构化工作资料，再按当前行动依赖补足完整条文。** 正常查询优先使用本目录的规则协议、专题执行文件、基础规则速查、疑点记录和规则索引。PDF 是原始源文件与视觉核验后备，不是日常检索入口。

规则资料按职责分层：
1. **运行协议 / 专题执行文件**：提供已整理的触发条件、执行顺序、边界与记录要求。
2. **基础规则笔记 / ARC 与能力资料 / GM 研究参考**：提供规则内容定位、常用机制和执行提示。
3. **规则导航索引**：定位主题、完整条文位置和关联规则。
4. **上游中文 v22 Markdown 母稿**：日常需要完整上下文时优先回查的原文载体。
5. **PDF 页面**：仅在图表、表单、轨迹、视觉布局、遮挡、跨页结构、OCR/Markdown 提取疑点或来源争议时回查。

高层级原文与用户明确批准的适用桌规优先于整理笔记；整理笔记不得自行升级成官方勘误或新桌规。

## 2. 按阶段与触发条件调用

| Prep Rule Validation | 本路由、专题协议、疑点记录、模组原文 | 必须核验实际运行依赖的机制、模组特例、初始资源、装备、能力资格与关键例外；在首次 Preflight 前关闭 |

## 3. 机制级分派表

### 现场行动与检定
- Ask the Agency：玩家提出现实改写时，核对效果、可信因果链、相关 Quality、事实是否已确立及失败后果。
- Anomaly Ability：每次调用具体能力时，核对角色 ARC/解锁、完整能力条文、Trigger/Cost、Quality、范围、持续时间、成功/失败和例外。
- Conflict Resolution：识别直接冲突迹象后切换独立冲突流程；不得调用普通 6d4 QA/Burnout/Chaos 结算器。
- QA / Burnout / Triscendence / Stability：沿用适用的系统专题与 Campaign Binding；桌裁仅在其登记的 Campaign/范围内有效。
- Harm / Life Insurance / Death：伤害发生、承受或防护时核对 Harm、QA 防护例外、装备/能力减免与死亡条件。

### 异常与任务压力
- Anomaly lifecycle、Focus / Impulse、Domain / History / Appearance：备团时建立可运行的异常行为模型；现场异常行动或域界效果变化时按相关条文核验。
- Chaos Pool / Chaos Effects：按 [Chaos Runtime Protocol](./03_CHAOS_RUNTIME_PROTOCOL.md) 处理生成接入、有效机会识别、效果选择、Domain 成本、世界状态落实与任务结束清零。生成计算由掷骰结算模块提供，不在本协议重复计算。
- Default Failure：作为 Triangle Agency 的被动默认裁定原则，已由基础规则资料承载；不列入逐行动规则检索路由，不要求每次行动重新读取或显式执行检查清单。
- Loose Ends / Weather Events：异常逃脱、事件影响分部、天气触发或模组结束时，核对产生条件、数值、作用范围和持续后果。
- Mission Outcome：区分 Captured / Neutralized / Escaped 等规则定义的结果；不要将任务结束统一简化成成功/失败。

### 人物与组织
- NPC / Relationships / Factions：初次登场、重要交涉、关系变化、派系行动时核对人物知识来源、动机、关系、资源与规则赋予的能力。
- Morning Meetings / Life-Work-Power：进入晨会或相关场景时调用对应结构；不要把所有 Session 强制变成固定晨会流程。

### 角色成长、装备与边界
- ARC / Competency / Reality / Anomaly：能力调用和成长选择前核对当前角色真实轨迹、前置、解锁状态与适用范围。
- Requisitions / Gear / Supplies：购买、领取、使用、消耗、转移和充能变化时核对资格、价格、限制与记录。
- Work/Life Balance / Time / Retirement：时间支出、轨迹标记、退休门槛和终局触发按对应协议与实际表单状态处理。
- Playwall：仅由实际标记且确实印有代码的轨迹格授权；只读取精确授权文档。专属骰子机制仍受 `PLAYWALL_DEFERRED_REGISTER.md` 限制。
- Content Controls / Open Table：新战役或内容边界变化时确认；不需要每个行动重复询问。

## 4. 每次规则调用的最小判定

1. 识别当前 Campaign Binding、系统版本、适用桌裁及角色/能力资格。
2. 将行动映射到本路由的机制和专题资料。
3. 读取专题执行协议与基础笔记；同时读取该机制相关的疑点/裁定记录。
4. 仅当专题未覆盖关键条件、引用不完整、规则争议或高影响结果需要完整上下文时，回查上游 Markdown 母稿的完整相关章节。
5. 仅当涉及视觉信息、表格/轨迹、遮挡、OCR/提取疑点、跨页结构或 Markdown 与原始页面冲突时，回查 PDF 对应页面。
6. 核对角色当前 ARC、实际解锁、装备、资源、Runtime 和模组状态。
7. 输出/执行时区分 SOURCE、APPROVED_TABLE_RULE、REFERENCE_NOTE、GM_INFERENCE、UNKNOWN；记录需要长期保留的裁定或修订。

## 5. 何时必须回查完整原文 / PDF

### 必须回查完整条文（优先 Markdown）
- 当前专题资料只提供摘要，未覆盖会改变结论的触发条件、目标范围、持续时间、成本、失败后果或例外；
- 新发现的规则争议、相互冲突的条文或用户要求核对原文；
- 新模组首次使用此前未验证的关键机制；
- 规则版本变化、上游 Markdown 提交变化或来源完整性不明；
- 涉及死亡、关键资源、永久成长、退休、任务结局等不可逆或高影响结果，且专题协议未明确覆盖。

### 必须回查 PDF 页面
- 轨迹图、角色表、Playwall 代码位置、图表、版式或空间布局本身决定结果；
- 页面遮挡、缺字、OCR/Markdown 提取错误或跨页结构有争议；
- Markdown 与 PDF 页面可见内容不一致；
- 用户明确要求核对 PDF 页面或物理页码。

**不构成回查 PDF 的理由：** 普通规则问答、已经由专题协议完整覆盖的掷骰/资源/幕间流程、为了确认自己“还记得规则”、或单纯因为资料来自 PDF。

## 6. 资料复用与版本控制

- 同一次 Preflight/Action Context 中，已读取且版本、Blob、范围仍匹配的静态规则资料可以复用；不得因多个流程入口引用同一规则而重复读取。
- 新 Session 重新确认系统绑定与动态状态，但不因此重读整套规则原文。
- 上游规则版本或 Markdown 提交发生变化时，标记受影响专题资料待复核；不得继续将旧整理稿视为已验证最新。
- 规则专题资料缺少内容时记录缺口并按需补充，不用模型记忆补齐。
- 历史 ZIP 仅用于追溯历史整理状态，不作为日常规则查询入口。

## 7. 当前资料状态与明确边界

- 基础规则速查：已存在。
- Playwall 解锁与幕间完整性：已有专题执行协议。
- Module Closeout：已有通用协议与 Triangle Agency 适配器。
- Chaos：已有 Triangle Agency 专属运行协议；其通用集成架构遵循 `Systems/SYSTEM_RULE_RUNTIME_INTEGRATION_PROTOCOL.md`。当前协议仍需行为验证。
- Dice Resolution：系统专属协议文件存在，但当前文档标记 DESIGN / 未启用；通用 Roll Routing 与本地参考适配器不能替代真实生产 Runtime 集成。
- Playwall 专属骰子效果：DEFERRED；不影响现有 Playwall 解锁、文档读取和非骰子效果处理。
- ARC/角色能力与完整 Playwall 文档：按角色当前授权精确读取，不建立全量玩家可见知识副本。
- 尚未整理成专题执行文件的规则：依靠本路由与规则索引定位；高频且确实影响运行的领域再逐项沉淀，不为追求文件齐全而批量复制全书。

## 8. 维护与反馈

当运行中发现规则笔记缺失、错误或难以调用：
- 先记录实际问题、触发场景、当前资料覆盖和缺口；
- 判断是索引缺失、专题协议缺失、角色状态缺失、版本差异还是原文歧义；
- 只补充能降低未来重复检索或裁定风险的内容；
- 需要新增桌裁时必须由用户确认，并写明 Campaign、版本、适用范围和来源；
- 不把一次临时裁定自动推广为全战役规则。
