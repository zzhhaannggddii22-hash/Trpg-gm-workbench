# GM 运行专题：Hope / Fear、GM Moves 与 Spotlight

> 适用规则集：Daggerheart Core Set  
> 规则基准：Official Daggerheart SRD v2.0（2026-08-25）  
> 状态：RESEARCHED / DESK-READY DRAFT；10 项 GM 专项桌面模拟已完成，仍待完整 Core Rulebook 对照与实际短场景验证  
> 本文性质：原创运行研究与流程整理，不替代规则正文。

## 1. 目的与核心判断

Daggerheart 的主持节奏不是“玩家行动—GM惩罚”，而是通过 Hope / Fear 的结果倾向、Spotlight 转移和 GM Moves，让行动持续改变局势。

运行时必须分清三个层次：

1. **骰子结果**：决定行动成败、Hope/Fear 资源变化及聚焦是否转移。
2. **GM Move**：GM 对当前虚构局势作出的叙事回应，可以是信息、人物行动、危险变化、代价或敌人行动。
3. **Fear 支出与敌人 Spotlight**：GM 用 Fear 购买额外主动权、额外敌人聚焦或特定 Fear Feature；它不是每次 GM Move 的统一成本。

把三者混成“恐惧结果=GM免费攻击一次”会显著缩窄系统的叙事空间，也会导致战斗节奏僵化。

## 2. Action Roll 结果与聚焦处理

| 结果 | 行动结果 | 资源变化 | 聚焦处理 | GM 响应基调 |
|---|---|---|---|---|
| Critical Success | 自动成功并获得额外收益 | PC 获得 1 Hope、清除 1 Stress；攻击另处理暴击伤害 | 视为 Hope 结果，通常留在玩家侧 | 让玩家描述成功，并给予额外机会/优势 |
| Success with Hope | 成功 | PC +1 Hope | 留在玩家侧 | 展示世界如何回应成功；不必为了“轮到 GM”强行插入 Move |
| Success with Fear | 成功，但伴随代价/复杂状况 | GM +1 Fear | 转给 GM | 认可成功，再呈现与当前情境相称的轻度代价或复杂状况 |
| Failure with Hope | 未达成意图 | PC +1 Hope | 转给 GM | 失败仍改变局势；引入较轻后果、障碍或新信息 |
| Failure with Fear | 未达成意图且局势恶化 | GM +1 Fear | 转给 GM | 以更强烈后果推进危险，但仍须符合已建立的 fiction |

重要区分：

- **总值**决定成功或失败；Hope / Fear 两骰的相对大小决定结果倾向。
- Critical Success 是 Hope 结果，不应再额外按 Fear 结果处理。
- Reaction Roll 不生成 Hope / Fear，也不触发额外 GM Move；不可把 Action Roll 的资源逻辑套到 Reaction Roll。
- 每次 Action Roll 都应让场景发生变化；变化可以是信息、位置、时间、关系、资源、危险或机会，不等于每次都造成伤害。

## 3. 何时执行 GM Move

当 PC 出现以下情况时，GM 应考虑作出 Move：

- Action Roll 掷出 Fear；
- Action Roll 失败；
- PC 做出会产生后果的行为；
- PC 给出必须立即回应的 Golden Opportunity；
- 玩家把焦点交给 GM，等待下一步发展。

GM Move 不等于攻击，也不等于必须花费 Fear。选择时先问：

1. 当前最重要的虚构事实是什么？
2. 谁正在追求什么目标？
3. 哪个后果已经由玩家行动、场景危险或既有倒计时建立？
4. 这次回应会让局势产生什么新变化？
5. 玩家是否有机会理解并回应危险？若没有，是否有充分理由采用 Hard Move？

常见 Move 方向：

- 展示世界对行动的回应；
- 让 NPC 按动机行动；
- 提出问题并把答案纳入世界；
- 透露不受欢迎的真相或新的危险；
- 预告场外威胁；
- 让 PC 标记 Stress；
- 改变环境、位置、路线或时间压力；
- 展示附带损害；
- 聚焦敌人；
- 清除敌人的临时状态；
- 让重要人物/物品被捕获或失去；
- 让玩家角色的目标、关系或背景受到牵动。

不要把列表当作轮盘随机抽取。Move 必须回应当前局势，而非从清单里挑一个与场景无关的惩罚。

## 4. Soft Move 与 Hard Move

**Soft Move**：呈现将要发生的危险、迹象、压力或机会变化，让玩家有机会采取行动、改变路线或回应。

**Hard Move**：更直接地兑现后果，PC 没有机会先中断、改变或预判结果。

适用时机仍要结合已建立的危险、玩家是否看见警告、机会是否关闭，以及规则结果。

**严重度与回应窗口是两条不同的轴：**
- 严重度由行动结果决定：Success with Fear 与 Failure with Hope 都是次要后果；Failure with Fear 是重大后果。
- 回应窗口由 Soft / Hard Move 决定：Hope 结果默认使用 Soft Move，Fear 结果默认使用 Hard Move。
- 因此，Success with Fear 可以是“次要但直接”的后果；Failure with Hope 可以是“较轻且留有回应窗口”的后果。不要把 Hard Move 自动等同于重大伤害，也不要把 Soft Move 自动等同于无代价。

## 5. Fear 经济：收入、上限与支出

### 收入与上限

- GM Fear 上限为 12。
- PC 掷出 Fear 结果、队伍休息或特定能力/效果可令 GM 获得 Fear。
- Short Rest 与 Long Rest 的 Fear 增量按休息规则处理；不得用“每次休息统一 +1”替代骰子程序。
- Fear 会跨 Session 保留。
- **Campaign 初始化 Fear**：Campaign 开始时，GM 获得每名 PC 1 Fear。此项已在官方 SRD 2.0 第 86 页（Using Fear）核实。

### 支出

Fear 可用于：
- 抢夺 Spotlight 并执行 GM Move；
- 执行额外 GM Move；
- 让额外 Adversary 获得 Spotlight；
- 使用 Adversary Fear Feature；
- 使用 Environment Fear Feature；
- 按规则为敌方掷骰加入 Adversary Experience。

关键成本规则：

- PC 当前持有 Spotlight 时，GM 花费 1 Fear 可打断并抢夺 Spotlight；由 Action Roll 失败、Fear 结果或其他规则触发自然交给 GM 的 Spotlight 不收这笔抢夺费用。
- GM Turn 内首次将 Spotlight 交给一个 Adversary 不额外收费；普通规则下每次额外 Adversary Spotlight 支付 1 Fear。
- **例外：明确写明会立即 Spotlight 一个或多个 Adversary 的 Spotlighting Feature，除非其文本另有要求，通常不额外支付 Fear。** 这类特性不能在其授予的 Spotlight 尚未结束时继续链式触发另一项 Spotlighting Feature。
- Relentless (X) 提高同一 Adversary 在一个 GM Turn 内可获得 Spotlight 的次数上限，并明确要求按常规支付额外 Spotlight 的 Fear 成本。
- 额外 GM Move 支付 1 Fear；Adversary / Environment Fear Feature 按其卡面支付独立成本。抢夺 Spotlight、普通额外 Spotlight、额外 GM Move 与 Fear Feature 的费用分别记账；但若某项 Feature 本身就授予 Spotlight，不得在缺乏规则依据时再叠加一次通用 Spotlight 费用。具体例外见 DH-I-020。
- 不需要 Fear 的普通 GM Move，不应伪造资源成本。
- Fear 达到上限时，超额收入不应继续累积成隐藏债务。

### 场景预算参考

官方 SRD 2.0 第 87 页给出不同场景的 Fear 支出参考区间（从轻微场景 0–1 到高潮场景 6–12）。在本工程中，它只作为**备团预算参考**，不是强制消费配额。主持时优先根据实际场景强度与玩家生成 Fear 的速度调整，不为了花完预算而制造无关后果。

## 6. Adversary Spotlight：敌人获得聚焦后能做什么

当 GM 已获得 Spotlight，并决定让某个敌人行动时，该敌人通常选择一项符合其能力与位置的行动：

- 移动至 Close 并进行标准攻击；
- 移动至 Close 并使用一个 Adversary Action；
- 清除一个临时状态；
- 在战场上冲刺至 Far 或 Very Far；
- 执行虚构情境要求且符合规则的其他行动。

执行约束：

- 先看敌人 Motives & Tactics、位置、目标、可用能力与状态，再决定行动。
- Action、Reaction、Passive、Fear Feature 的触发时机不可互换。
- Relentless (X) 等特性可能改变同一 GM Turn 内某个敌人可获得 Spotlight 的次数；按 Stat Block 逐条执行。Relentless 明确按常规支付 Fear；其他 Spotlighting Feature 按其自身文本与 DH-I-020 区分处理。
- 多个敌人不是自动同时行动。额外敌人 Spotlight 需要按规则支付 Fear。
- 敌人攻击、敌人能力、环境效果的结算，继续调用对应 Rule ID；不要在 GM Move 流程中跳过攻击/伤害/Reaction 规则。

## 7. GM Turn 的最小运行流程

1. **接收聚焦**：确认是何种触发让 Spotlight 来到 GM。
2. **读当前局势**：检查位置、敌人动机、已预告危险、Countdown、目标与资源。
3. **选回应类型**：普通 GM Move、敌人 Spotlight、环境 Move，或不立即追加行动而先呈现结果。
4. **核对 Fear**：只有确实需要抢夺/追加 Spotlight 或启用 Fear Feature 时才扣除；逐项支付。
5. **执行并结算**：按对应规则处理攻击、伤害、状态、移动、Stress、HP、Armor、Countdown 等。
6. **更新状态**：记录资源与场景变化；不重复结算已支付的 Fear 或已触发的效果。
7. **交还聚焦**：GM Turn 结束后把 Spotlight 交回 PC 一侧，让玩家决定下一步。

## 8. 常见主持错误与修正

| 错误 | 为什么有问题 | 修正 |
|---|---|---|
| 每次掷出 Fear 都直接攻击 | 把 GM Move 缩减为伤害 | 从动机、场景目标、压力、信息与机会中选择回应 |
| Success with Fear 被叙述成行动失败 | 抹掉了玩家成功取得的成果 | 先确认成功，再添加代价/复杂状况 |
| 每次 GM Move 都扣 Fear | 混淆叙事回应与资源支出 | 只有规则明确要求的支出才扣 |
| 先抢 Spotlight，再把这次费用算作 Fear Feature 成本 | 违反额外成本说明 | 分开记账 |
| Fear 一直囤积到场景结束 | 放弃资源作为节奏工具的作用 | 有意义的窗口出现时主动支出 |
| GM Turn 里让所有敌人轮流行动 | 擅自引入固定敌方回合 | 逐个敌人 Spotlight，并核对额外支出与特性 |
| Hard Move 没有预告且直接夺走关键选择 | 玩家无法理解风险或作出回应 | 先建立可读信号；仅在已成立的严重后果下兑现 |
| 为了消耗 Fear 临时生成援兵 | 让资源支出凌驾于场景因果 | 只使用已埋设、可解释或合理进入场景的威胁 |

## 9. 运行前后检查

### GM Move 前
- [ ] 玩家行动是否成功？先确认成功部分。
- [ ] 是否有 Fear / 失败 / Golden Opportunity / 不可避免后果等触发？
- [ ] 当前 Move 与 NPC 动机、敌人战术或环境机制是否一致？
- [ ] 后果强度是否与已告知的赌注相称？
- [ ] 是否需要 Soft Move 反应窗口？
- [ ] 是否真的需要支付 Fear？支出项目是否分开计算？

### GM Turn 后
- [ ] 伤害、HP、Stress、Armor Slots、Conditions、Countdown 是否正确更新？
- [ ] 敌人是否按自身特性获得了正确次数的 Spotlight？
- [ ] Fear 是否只在对应触发/支出时增减？
- [ ] 聚焦是否交还玩家？
- [ ] 新局势是否提供了明确可行动的机会？
