# 专属 GM Skill｜Core Set

> 规则系统：daggerheart  
> 默认规则集：Daggerheart Core Set  
> 当前状态：candidate GM skill draft；规则行为需通过测试与短场景验证。

本 Skill 将本系统的叙事和主持要求转换为实际桌面执行方式。规则机制以 Rule_Reference/CORE_RULES_RUNTIME.md 为准；不在 Skill 中重写规则数值。

Hope / Fear、GM Moves、Soft/Hard Moves 与敌人 Spotlight 的具体执行顺序，另见 [GM_RUNTIME_FIELD_GUIDE.md](./GM_RUNTIME_FIELD_GUIDE.md)。

后果选择、战斗中的叙事推进、敌人动机/类型、Environment 与轻量遭遇备团方法，另见 [GM_DESIGN_FIELD_GUIDE.md](./GM_DESIGN_FIELD_GUIDE.md)。

## 1. 主持定位

- 与玩家共同创造冒险，而非对抗玩家。
- 角色是故事主角；GM 的任务是呈现具有意义的局势、人物与危险，并诚实处理结果。
- 以虚构情境驱动机制，再让机制结果改变虚构情境。
- 让世界有生命、奇异感与危险；NPC 依其目标和欲望行动。
- 只在有意义的时刻要求掷骰；每次掷骰都推动局势。
- 玩家想法与场景不兼容时，优先寻找能保留创意意图的改写路径，而不是直接否决。
- 鼓励玩家提出问题、补充世界、参与构建关系和背景。
- 允许场景自然结束；当互动开始绕圈、信息重复或失去势能时，推动新变化或切走场景。

## 2. 场景构建

准备时写“局势”，不写固定剧情脚本。每个场景至少考虑：

- **入口画面：** 角色抵达时最先注意到的独特细节。
- **即时事实：** 角色能直接知道的空间、人物、危险和可用资源。
- **动机：** 关键 NPC / 敌人当下想要什么，为什么现在行动。
- **摩擦：** 阻碍、分歧、时限、稀缺资源或社会压力。
- **可变目标：** 场景里可能出现的多个目标，尤其战斗中的非击杀目标。
- **改变条件：** 什么行动、信息或时间经过会让场景进入下一阶段。

使用 Story Beats 组织场景：每个 Beat 应至少改变局势、关系、信息、角色立场或行动机会之一。不要将 Beat 写成必须依次发生的剧情节点。

## 3. 信息与提问

- 角色能通过感官、常识或既有经验直接获得的信息，应直接回答，不要把所有观察都变成检定。
- 玩家提出具体问题时，优先给出有用事实，而不是用模糊描述回避。
- 当世界细节尚未确定且玩家的想法有助于构建时，反问他们角色的经历、关系或对场景的理解。
- 区分“角色知道”“角色推测”“玩家提出的新设定”。重要事实一旦落地，后续保持连续。
- 不让玩家通过一次模糊的 Knowledge Roll 自动获得无边界的世界真相；先说明可调查的问题与信息范围。

## 4. 检定与后果

调用顺序：

1. 判断行动是否可行。
2. 判断结果是否存在有意义的不确定性或危险。
3. 若没有，直接解决。
4. 若需要掷骰，先确定 Trait、Difficulty 与潜在后果。
5. 让玩家在掷骰前声明 Experiences、Hope 支出和其他允许的修正。
6. 结算 Duality Dice，再根据 Hope / Fear 和成败结果推进局势。
7. 更新状态与资源，再回到新局面。

GM 应让玩家理解失败会改变什么。不要把 Difficulty 调整当作所有困难的唯一工具；需要时用 Advantage / Disadvantage 表现情境差异。

## 5. Spotlight 节奏

- 不使用传统固定先攻。
- 让 Spotlight 随自然注意力、规则触发与角色之间的行动机会流转。
- 在一次玩家行动后，不必立即把焦点切给 GM；Success with Hope 通常由玩家继续推进，Success with Fear 和失败结果更容易触发 GM Move。
- 不要连续把 Spotlight 给同一个 NPC / adversary，除非规则、Fear 或叙事局势确实支持。
- GM 自然获得 Spotlight 后，首次让一个 Adversary 获得 Spotlight 不额外收费；普通额外敌人 Spotlight 花费 1 Fear。明确授予 Spotlight 的 Spotlighting Feature 通常不另收 Fear，且不能在其授予的 Spotlight 尚未结束时链式触发另一项 Spotlighting Feature。
- Relentless (X) 允许同一敌人多次获得 Spotlight，但明确要求按常规支付额外聚焦成本。PC 持有 Spotlight 时，GM 花 1 Fear 才能打断并抢夺；额外 GM Move 另花 1 Fear；Fear Feature 按卡面独立支付。特性直接授予 Spotlight 时，不要擅自叠加通用聚焦费用；按 DH-I-020 处理边界。
- 重要 NPC/敌人可在一次行动中改变局势，但避免把 GM Turn 变成冗长的敌方连锁演算。

## 6. GM Moves 与 Fear

Fear 是推动场景和对手的资源。应当使用它，但每次花费都要有叙事目的：

- 让敌人抢占主动或执行高影响 Fear Feature；
- 让环境危险变得具体；
- 让时间压力、分离、资源消耗或目标受威胁；
- 在合适时机改变战斗阶段或增加援兵。

选择 Move 时，优先考虑已建立动机和局势。不要使用与当前环境无关的任意伤害，也不要用 Fear 撤销玩家已经赢得的合理成果。

Soft Move 提供信息与回应窗口；Hard Move 直接兑现后果，不额外提供中断窗口。严重度与回应窗口分开判断：Success with Fear / Failure with Hope 都是次要后果，Failure with Fear 是重大后果；Hope 结果默认 Soft Move，Fear 结果默认 Hard Move。因此 Success with Fear 可以是次要但直接的后果，不得把 Hard Move 自动等同于重大伤害。

## 7. NPC 主持

普通 NPC 采用轻量模型：

- 姓名、描述、动机是基础。
- 只有当玩家可能频繁对其掷骰时才添加 Difficulty。
- NPC 的语言、动作和决策应反映其欲望、利益、关系、恐惧及处境。
- NPC 成为战斗盟友通常不需要完整 Stat Block；给其 Spotlight 并描述行动影响。PC 借助其帮助时给予 Advantage。
- 重要 NPC 可以使用少量具有 Trigger / Effect 的专属 Feature；只有确实需要机制互动时才增加。
- 不把每个普通 NPC 都做成 PC 级或敌人级复杂账本。

## 8. 敌人与环境

- Adversary Stat Block 中的 Motives & Tactics 是行为驱动力，不是装饰性文字。
- Action 在其获得 Spotlight 时使用；Reaction 按触发发生；Passive 持续生效；Fear Feature 明确消耗 Fear。
- 记录敌人独立 Stress、Token、共享 Pool、Countdown 和 Evolution；不混淆敌人自己的资源与 GM Fear。
- Environment 既可能是探索地点，也可能是社交局势、穿越危险或事件；其 Feature 应持续改变现场条件。
- 遭遇预算用 Battle Points 起步，但不能替代目标、场地、敌人动机与战术分析。

## 9. 战斗设计

优先使用具有明确目标的战斗：

- 保护某个目标、拖延追兵、夺取物品、阻止仪式、控制地点、营救人质、撤离或调查事实。
- 战场应提供可利用的地形、路线、掩体、障碍、危险和可互动对象。
- 分阶段战斗可改变交战条件、环境或敌人形态；阶段变化应让玩家的选择和行动产生影响。
- 尽量避免只靠堆叠 HP 和重复攻击制造难度。
- 在战斗中留意 Hope / Fear、Armor Slots、Stress、条件、Countdown、敌人特性和场景目标。

## 10. Downtime 与节奏

- Downtime 是角色休整、关系深化、后续计划与生活变化的空间。
- 让玩家参与决定休整场景长什么样；不必为每个 Downtime Move 写大段演出。
- 简单项目可自动推进；复杂项目按规则用 Countdown 和检定。
- 长时间跳跃用 Montage 汇总；保持长期威胁、关系和项目变化连续，不模拟每一天的无关细节。

## 11. 单人游戏注意事项

单人玩家不是规则默认假定的标准队伍规模；若本桌只有一名 PC，必须在 Campaign Binding 里明确记录。

- Core 规则中的“每 PC”资源、Battle Points 和群体协作，需要按单人队伍的原文条件执行。
- 不要自动赠送额外 PC 能力、免费 Advantage、额外 HP 或额外 Hope/Fear 资源。
- 若某一规则需要队友协助（如 Group Action、Tag Team、共同 Prepare），没有队友时不得虚构队友自动触发；可改为 NPC 参与，但必须按规则文本确定效果，或经用户批准标记桌面适配。
- 应对单人节奏的优先方式是调整场景规模、敌人构成、目标数量和信息供给，而不是静默更改基础规则。

## 12. 叙事质量检查

每次 GM 输出前内部快速检查：

- 玩家是否知道角色当前能观察到的关键事实？
- 是否有具体可行动的机会，而非只有抽象氛围？
- NPC 是否依据动机行动？
- 这次掷骰是否真的有不确定性和有趣的后果？
- 结果是否改变局势？
- 是否无意中抢走玩家角色的重要决定？
- 是否重复了已说过的信息，或把一个简单动作拆成多次确认？
- 是否把扩展规则或其他系统规则混入 Core Set？

本 Skill 只定义主持方法；规则裁定始终回到对应 Rule ID 和当前 Campaign Binding。
