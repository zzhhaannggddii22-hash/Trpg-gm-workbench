# WWN Site Tags 运行手册

状态：结构与用途已核验 Free Edition；本文件不复制书中约 200 个具体 Tag 名称及其创作性条目。

## 1. Tags 是什么

Tag 是地点的主题特征或关键观念。它不是完整剧情，也不是强制随机事件；它提供一组能让地点具备个性、张力和可用冒险素材的提示。
通常为一个兴趣点选取两个 Tags，将两者综合解释。两个通常足够；只有确实需要时才继续增加。

## 2. 四类 Site

| 类型 | 典型对象 | 主要生成用途 |
|---|---|---|
| Community | 城市、村庄、部族、流亡群体 | 社会结构、当地权力、问题、潜在委托 |
| Court | 王廷、贵族圈、教团核心、权力集团 | 派系关系、权力斗争、内部危机 |
| Ruin | 遗迹、地下城、古代设施 | 探索主题、危险、遗留物、场所特征 |
| Wilderness | 荒野、边境、自然区域 | 地理环境、居民、危险、隐秘地点 |

不要把 Court 简化成“城堡地点”；它指围绕某个权力中心运作的社会场域。

## 3. 五类 Tag 素材

Tag 以五类素材提供构建线索：

- **Enemies**：阻碍目标、制造危险或对 PC 怀有敌意的人/势力。
- **Friends**：潜在盟友、求助者、联系人或可合作对象。
- **Complications**：令地点、人物或目标陷入麻烦的矛盾、压力与异常。
- **Things**：有价值、可争夺、可利用或可被寻找的对象、资源、秘密。
- **Places**：具有主题辨识度、适合发生行动的具体场所或环境。

不同 Site 类型会以各自适配的表格与语境呈现这些内容。生成结果不是要全部塞进场景，而是供 GM 在构建冒险时选择。

## 4. 组合流程

1. 确定地点类型和它在当前冒险中的用途。
2. 为地点选取两个 Tags。
3. 分别阅读两组素材，不急于生成完整剧情。
4. 根据当前需求选择素材类别：需要对手时取 Enemies，需要联系人时取 Friends，需要麻烦时取 Complications，需要目标/奖励时取 Things，需要场景时取 Places。
5. 将两个 Tag 的提示综合成同一地点的事实；允许一方解释另一方、相互冲突或共同指向一个问题。
6. 把选出的素材转成可观察信息、人物意图、行动机会与可能后果。
7. 仅保留当前冒险会用到的条目；其余作为以后可调用的备选。

## 5. 从 Tag 到可玩的地点

每个实际采用的素材至少要回答一个问题：
- PC 能看到、听到或发现什么？
- 谁希望什么事情发生？
- 什么阻止了它？
- PC 可以采取哪些不同类型的行动？
- 行动成功或失败会改变什么？

如果一个 Tag 只产生氛围形容词，需再把它具体化为人物、资源、行为、地点或矛盾。不要把抽象主题直接当作线索或任务。

## 6. 重要解释规则

- Tag 的意义取决于 Site 语境。同一主题放在寺庙、犯罪组织或边境村庄里，表现可以完全不同。
- 某些 Tag 自带危机；应把危机改写成 PC 能介入的情境。
- 描述性 Tag 没有现成危机时，可以用它强化另一个 Tag 的问题，或推演其在现实压力下的极端表现。
- 两个 Tag 足以形成一个地点的基础风格；大型王廷可以由多个 Court 分别构建，再考虑彼此关系。
- Tag 提供灵感，不替代因果核验。两个随机结果不应强行拼成逻辑不通的剧情。

## 7. AI Runtime 适配（非官方）

建议将 Tag 素材作为按需检索库，而不是每次开团全部展开：
- 地点建立时只保存两个 Tag 标识及简短主题摘要；
- 生成挑战时才检索所需的素材类别；
- 生成 NPC 时从 Friends / Enemies 提取角色职能，再独立塑造个性；
- 将 Complications 视为可变化的压力状态，而非自动发生的事件；
- Things 应明确所有权、位置、价值或用途；
- Places 应能支持具体行动和空间关系。
禁止在公开仓库复制 Free Edition 的具体 Tag 描述、完整表格条目或其设定化文字。可保存自创 Tags，沿用通用的五类组织结构。
