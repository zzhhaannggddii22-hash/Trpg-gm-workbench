# Bower Street｜玩家可见信息闸门（运行协议）

> 适用：SESSION 01 起，每一次面向玩家的 GM 回复。
> 目的：阻止 GM-only 资料、尚未取得的线索和 NPC 未披露的信息进入玩家视角。
> 本文件是轻量运行检查，不替代规则裁定，也不要求每轮向玩家展示检查过程。

## 每轮回复前的三步检查

### 1. 来源检查：这句话从哪里来？
将拟呈现的信息快速归入以下一种：
- **TABLE CANON**：本桌已经实际发生，且玩家角色确实看到、听到、读到或被告知。
- **IMMEDIATE OBSERVABLE**：角色此刻凭正常感官或已声明的行动可以直接观察到的环境信息。
- **NPC DISCLOSURE**：NPC 在当前场景中确实说出/表现出的内容；必须满足该 NPC 的知识范围与披露条件。
- **RULE RESULT**：由玩家实际行动触发、按规则裁定后产生的结果。
- **GM-ONLY / UNDISCLOSED / INFERENCE / UNKNOWN**：不得作为玩家已知事实呈现。不得因为它出现在模组索引、Prep、地图、真相档案或历史摘要中，就把它说成角色已知。

### 2. 知识权限检查：角色凭什么知道？
逐项问：
1. 本场或既往 CANON 中，是否有明确的获取行动和来源？
2. 若来自 NPC，该 NPC 是否知道；当前是否满足披露条件？
3. 若来自文件、照片、设备或现场，角色是否实际取得并检查了它？
4. 这句话是否把 GM 的地点索引、人物对应、隐藏机制、异常真相或后续分支提前翻译成了玩家提示？

只有前三项存在明确依据，且第四项为否，才可作为已知信息陈述。

### 3. 表达检查：不要把后台答案伪装成引导
- 不主动点名玩家尚未发现的关键地点、人物身份、物件用途、隐藏机制或正确路线。
- 不用“建议你去 X”“X 是核心地点”等方式，把 GM-only 重要性包装成角色建议。
- 玩家询问某地点或事实时，只回答角色已知的部分；未知部分明确说“目前没有获得这方面的信息”，不要借解释之名补充后台答案。
- 可以提供真正中性的行动可能性，但不得只挑选隐藏真相相关的选项，或给某个未发现地点额外权重。
- 对信息是否已披露拿不准时，默认不披露；先回查本场 Session Log / Player Notes / Runtime State。

## 发生泄露时的处理

1. 立即停止扩展解释，不再用泄露信息继续引导。
2. 标记泄露内容为 **GM 回复失误，不构成角色获得信息**；不写入玩家线索、调查笔记或角色知识。
3. 保留原本模组真相与世界状态，不因口头纠正而改写后台事实。
4. 在本场运行记录中登记泄露事件及修复边界，供复盘；不得假装玩家没有读到这段文本。若泄露已经实质破坏谜题，需与玩家协商是否继续、回滚或调整体验。

## 本场已知基线（简报结束时）

以下仅列出本桌实际简报已披露的玩家信息：
- 任务发生于 Ternion City 的 Sycamore Heights 社区，目标街道为 Bower Street。
- 机构截获一通来自 Justin Hamamoto 的报警电话；电话发生于一周前，机构于昨晚截获。
- Justin 在电话中报告妻子失踪，表达了时间与记忆上的困惑，录音提前中断。
- Sycamore Heights 周边宠物失踪报告增加，集中在 Bower Street；张贴寻宠启事的多数居民不记得自己贴过。
- 一张寻宠启事显示黑猫左眼上方有白斑，地址为 1058 Bower Street。
- 任务目标是调查 Bower Street 的异常活动、查明失踪原因，并依现场情况处理异常。
- 已告知附加任务：获得最多居民友好挥手、与动物建立友好关系、避免财产损坏及相应奖惩。
- 任务车辆已安排，目的地为 Sycamore Heights；玩家可自行选择调查入口。

以下内容**不在上述已知基线中**：各门牌对应的住户身份（除简报明确提及的 Justin 外）、1063 的住户身份、任何地点的隐藏重要性、异常 Domain 的范围与位置、受害者名单、地下室情况、隐藏线索和异常真相。除非之后通过合法行动实际取得，不得披露。

## 轻量记录要求

每次回复无需输出检查清单。仅在 Session Log 记录新的披露事件：
- 新信息；
- 获取方式/来源；
- 信息性质（观察、NPC 陈述、文件、规则结果）；
- 是否已进入玩家知识。
不重复记录已经披露且没有变化的信息。
