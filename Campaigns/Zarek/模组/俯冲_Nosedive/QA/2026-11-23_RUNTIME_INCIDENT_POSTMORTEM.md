## 2. 对照证据：模组原文与错误输出

- Cass Gilmore 是 27 岁女性（she/her），文案撰稿人，住在 Foxglove Apartments 五楼两居室；妻子 Lisa 同住但初次场景不在家。
- 特工抵达时，Cass 在屋内喊“进来”，因为她以为是来一起在家工作的朋友。

- 她正用贴满贴纸的笔记本电脑为客户做文案校对。
- 她的“车门电击”说法是谎言；真实经过与她和 Mimi 的争论有关。隐藏内容需遵守模组设定的信息门槛。
- 官方初始线索没有音频维修工作室、待修设备、设备所有人/委托人、R&D 回收设备或送检客户支线。

### 实际错误

作废尝试中，主持者：
- 将 Cass 的性别/身份及首次出现方式演错，先后补写了与原文不符的前台、住户信息和场景；
- 把她改写成在二楼“Gilmore Audio Repair”工作的维修人员；
- 补造工作台、老式音频设备、万用表、异常电压读数、设备客户与设备所有权关系；
- 继续编造 R&D 上门回收设备、接收证明、客户通知、客户来电与该客户自身遭遇电击；
- 把这些新增内容当作已成立的线索链，继续推进后续地点和行动。

上述内容均标记 NON-CANON。玩家提出的“把设备送检”等行动发生在 GM 已经错误建立设备之后，不构成对整条虚构支线的追认。

## 3. 根因分析

### 已确认的流程缺陷

1. **首次出场缺少运行时事实锁。** 备团虽含 Cass 的真实经历，但首次接触时没有强制回读模组原文对应段落并核对身份、住所、同住者、动作、外貌、工作和物件。
2. **Runtime Quick Reference 缺少受害者入口卡。** 快速索引指向详细文件，却未把首个高概率场景的必要事实压缩到现场入口；运行时依赖摘要和上下文记忆。
3. **NPC Ledger 对外围受害者记录过薄。** Cass 的关系与隐藏经历有记录，但没有完整的第一场景表现卡和显著物件。
4. **旧运行协议约束不足。** 原行动闭环主要检查玩家声明的行动；没有明确规定 GM 自己创造的重大事实、命名 NPC 初次出场和场景起始条件同样必须经过事实核验。
5. **未及时停止错误扩写。** 即使后续对话围绕设备、客户和 R&D 回收继续发展，也没有回查模组原文；局部叙事连贯性取代了来源一致性。
6. **状态文件不同步。** 模组 README 与首次 Preflight 保留“尚未开团”，而 Quick Reference、Runtime State、Session Log 已写“Session 01 开始”。开场准备、活动状态和记录没有统一校验。
7. **Session Log 未真实反映运行与异常。** 正式日志仍停留在机构简报，未记录后续实际发生的错误过程，也未在首次严重偏离时触发回滚。

### 可能的生成误差机制（推断，不视为已证实内部过程）

最可能的局部联想链是：电击伤 → 电气设备；R&D → 设备检测；原文的 copyediting client → 被误解为设备客户/所有者。随后生成内容彼此呼应，形成看似连贯的维修调查线。我们无法直接观测模型内部形成错误的具体过程，因此此项只作为解释性假设。
