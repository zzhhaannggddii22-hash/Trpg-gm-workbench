## 3. 规则核对

### Domain Benefits

依据主规则印刷页 156、158、161：

- 标价 1、2、3 的效果在 Domain 内免费。
- 标价高于 3 的效果，池内实际支出为表价 ×3。
- 例如 4→12、5→15、8→24、10→30、30→90。
- 低于 3 的个性化效果另有“无限使用”的明确文字；不得自动把这一频率解释扩展到恰好 3 点的效果。
- 之前的 C/3 反向算法与向上取整提案已撤销，不再是待用户决定的桌规。

### 涟漪枪

依据主规则印刷页 21：

- 对任务目标异常直接、无遮挡瞄准，可以永久中和目标。
- 使用涟漪枪处理任何非任务目标用途，触发 3 次 Demerits。
- 因本模组固定 Scheduler 为界面、登记簿为本体，必须在射击前把这一区别说明给玩家。
- 登记簿本体清晰可见时，允许按真实视线直接瞄准，不能临时更换本体。

### 任务结果

依据主规则印刷页 22、31 与 134：

- Captured / Neutralized / Escaped 分开结算。
- 任务结果、报告奖励、可选目标、最终申诉、任务评优必须按规则顺序处理。
- 单特工任务评优仍待玩家决定是否采用官方顺序或经过确认的单人适配。

## 4. 主持执行表的风险控制

- 不用唯一 NPC 或唯一文件锁定调查。
- 不把普通办公行为变成技能检定。
- 不用 Scheduler 代替异常本体。
- 不把停止新派单当作救出所有员工。
- 不把局部救人当作收容异常。
- 不把撤退视为自动任务失败，也不把暂离视为正式 Escaped。
- 不把预备中的故事结果写成既成事实。
- 不使用尚未完整定义的自创混沌效果。
- Kill 与 Overwhelm 属于高危效果；实际使用前必须结合角色卡、资源状态、规则成本和清晰预警检查。
