# 高级模型备团 QA｜交接与验收协议

> 用途：将第一轮备团交给可用的高能力模型进行独立、对抗性质量审核。它是 Prep QA 的执行协议，不替代《12_PREP_DESIGN_AND_SECOND_PASS_REVIEW.md》或《13_PREP_TO_RUNTIME_HANDOFF_STANDARD.md》。

## 1. 适用与时序
- 优先用于高复杂度模组、长调查链、重要失踪/失联人物、显著 GM 扩写、多个 NPC/派系相互作用，或前次复盘暴露过同类问题的模组。
- 对简单低风险模组可跳过；必须记录跳过原因。
- 如执行，必须在该模组第一次 Session Preflight 之前完成。第一次 Preflight 一旦执行，Prep QA 窗口关闭；之后发现的问题进入运行纠错或复盘，不补做事后 QA。
- 高级模型是独立挑错者，不是第二位 GM，也不负责替代主持者做最终裁定。

## 2. 交接包最小内容
交接者只提供本轮审查所必需的 GM-only 备团材料：
1. 模组名称、作者/版本、合法来源及可用原文范围。
2. 用户指定的系统规则版本、必要规则摘录/定位与桌面约定。
3. SOURCE / TABLE CANON / GM ADAPTATION / GM INFERENCE / UNKNOWN 分类说明。
4. 事件真实时间线、异常/敌对机制、关键地点与结局条件。
5. 重要 NPC 的目标、知识边界、行动能力、关系和当前状态。
6. 调查链：起点、节点、节点功能、独特回报、替代路径、失败/中断后果和收束条件。
7. 单人桌与当前角色适配、玩家可能偏离预设路线时的响应依据。
8. Runtime Quick Reference 草稿及明确待核问题。

不默认交付：完整 Session Log、玩家私密交流、无关战役历史、其他项目资料、密钥/凭证或第三方受版权保护全文。审查需要某项额外资料时，先指出具体缺口，由项目负责人决定是否提供合法且必要的摘录/定位。

## 3. 高级模型审查任务
要求审查者站在反方立场找错，不要替备团作者合理化：
- **来源与事实**：逐条抽查关键事实是否有可追溯来源；识别推断冒充原文、未知被填成事实、桌面扩写冒充官方设定。
- **规则准确性**：核对系统版本、触发条件、目标类别、例外、成本、持续时间、结算顺序与资源变化；无依据处标 UNKNOWN。
- **因果闭合**：检查异常能力是否足以解释线索、伤害、人物失踪、物品变化和时间线。
- **调查结构**：找单点依赖、软锁、无回报长支线、不可发现线索、无收束条件及不合理的唯一解。
- **NPC 模拟**：检查动机、知识、权限、资源、行为、台词、衣着、生理状态与环境一致性；标出无意矛盾。
- **路线压力测试**：至少选择 3 条有代表性的非预设路线/失败路线，检查世界能否合理响应，不要求穷举。
- **单人桌适配**：检查人数假设、行动经济、搭档权限、机构支援边界与角色能力适配；不得擅自降低规则风险或暗改机制。
- **信息隔离**：检查玩家简报、便笺和可见素材是否泄露 GM-only 真相。
- **运行效率**：检查现场索引是否能快速定位唯一权威资料；重复记录是否可能漂移。

## 4. 固定输出格式
审查报告必须按以下结构交付：
1. **阻断问题**：若不修复会造成规则错误、核心事实冲突、调查软锁、重大因果漏洞或剧透泄露。
2. **重要建议**：不必阻断开团，但可能影响公平性、节奏、可信度或连续性。
3. **已通过项目**：指出具体文件/段落和审核依据，不写泛泛赞扬。
4. **资料缺口与 UNKNOWN**：说明缺什么、为何影响判断、如何合法补齐。
5. **非预设路线压力测试**：列出测试路线、可能结果、依赖事实和仍存风险。
6. **修订清单**：按优先级列出文件、具体修改、理由与验收条件。
7. **QA 结论**：PASS / PASS WITH RISKS / FAIL，并说明依据。

## 5. 项目负责人处理审查结果
- 审查意见不是自动指令。主持者逐项回到规则原文、模组来源和已确立 CANON 核实。
- 阻断问题修复后，更新权威备团文件，并在 QA 记录中写明修订位置与证据。
- 对不采纳建议，记录理由；对资料不足事项保持 UNKNOWN，不猜测补齐。
- 不因报告写了 PASS 就自动完成 Preflight；QA 和 Preflight 独立。
- 只有最终采用的改进进入备团权威资料；模型的未验证设想不得写成模组事实。

## 6. 验收清单
- [ ] 交接包只含本次审查必要的 GM-only 备团材料。
- [ ] 原文来源、规则版本和事实分类清楚。
- [ ] 重要调查链有回报、替代路径、失败后果与结束条件。
- [ ] 重要 NPC 与异常因果完成一致性检查。
- [ ] 至少 3 条代表性非预设路线完成压力测试（不适用时说明原因）。
- [ ] 阻断问题全部修复或明确暂停开团。
- [ ] 玩家侧资料完成剧透隔离检查。
- [ ] QA 报告和修订记录已归档。
- [ ] 若执行 QA，确认它发生在第一次 Preflight 之前。

## 7. 可复制的交接任务书

请你担任本模组的独立 Prep QA 审查者，而不是共同 GM。以用户指定的系统规则版本和模组原文为最高依据，审查我提供的 GM-only 备团资料。不要编造原文未支持的机制、数值、事实或页码。请主动寻找规则错误、因果断裂、NPC 行为/知识矛盾、调查软锁、无回报长支线、单人桌适配问题、非预设路线响应缺口及玩家侧剧透泄露。至少测试三条代表性非预设路线。按“阻断问题、重要建议、已通过项目、资料缺口/UNKNOWN、路线压力测试、修订清单、QA 结论”输出。对每个问题注明文件位置、证据、影响和建议修复；区分来源事实与推断。没有证据就保留 UNKNOWN，不要用常见 TRPG 经验覆盖本系统规则。
