# 凯西 TRPG GM 系统优化方案

**实施顺序：先让凯西在该停的时候停下，能带着正确状态回来，再缩短玩家每次等她回应的时间。** 保留现有通用 Skill → 系统绑定 → Campaign → 模组 → Session 架构、绿黄红路由、首次出场卡、关键规则原文核验和可选 Prep QA。改动集中在三个交接点：哪条记录有权改变哪种事实，何时从普通互动升级核验，以及新对话如何判断一次保存完整且可用。

## 3. P0 可靠性阻断项

### P0-1　区分陈述与客观事实，并隔离已传播的错误〔必须〕

**证据。** `ND/01_GM_PREP.md` §3.3 和 `ND/03_NPC_BEHAVIOR_LEDGER.md` L65–66 标明车门解释为谎言，`ND/08_RUNTIME_STATE.md` L133、`ND/04_CLUE_AND_SOURCE_LEDGER.md` L69、111 却把触碰及受电写入当前事实。`ND/09_PLAYER_NOTES.md` 的车辆表也会影响恢复。现有 `G/08_CLUE_AND_SOURCE_LEDGER.md` 区分来源，`G/03_SESSION_LOG_TEMPLATE.md` L56–86 接收变化，保存时仍能丢失“谁说”“谁知”“所言是否成立”。

**设计及修改位置。** 在 08 线索规范、03 日志模板、Runtime 模板、09 文件夹规范中使用同一组字段。重要命题记 `claim_id / 命题 / 性质 / source_ref / 根来源或父命题 / state`，重要认知变化另记 `角色 / 观察或转述等方式 / 事件 / 接收者 / 披露条件`。性质使用既有 SOURCE、TABLE CANON、GM ADAPTATION、GM INFERENCE、UNKNOWN。NPC KNOWLEDGE 和 PLAYER-KNOWN 分别记录某角色对该命题的关系。只在有独立依据及授权的范围内新增或修订客观命题，保留旧推断和更正理由。原文和桌上已发生的矛盾应并存为“原文约束＋已呈现事件＋争议”，不能删一方。来源根未知、闭环引用或证词只佐证同一说法时，停止提升可信等级。

**迁移。** 从车门命题、CLUE-ND-10 至 16 与四名本桌新增人物出发，逐一追踪 NPC／Name Index／Session／Runtime／Notes／交接／人物副本。保留它们实际出场和对话的事实，分别标记准入状态及派生关系。任何能澄清公开便笺的改写也需保护秘密，不能把后台更正直接发给玩家。

### P1-3　保存一次增量，发布完整检查点〔可靠恢复必须。自动化可选〕

**设计。** 用现有 Session Log 尾部记录 `event_id、base_rev、已呈现/待回应、变更对象、前后值或序号、依据、可见范围`。无长期影响的寒暄不写磁盘。重大资源/结算、公开新承诺、首访已呈现及不可逆行动及时记。普通变化在自然边界汇总。把批次号、影响范围、最后事件、各权威/必要视图的预期修订以及发布标记放进 Runtime 检查点。流程如下。

1. 读取基线修订并给操作一个可重用的事件号。先记录已发生事件和是否已向玩家输出。只有已确认的玩家选择才能进入结算。写入结果未知先查该事件号，已存在时读回原结果。

4. 恢复先核最新完整批次，再看其后已呈现/待合并事件、失配视图与玩家选择。任何一方写入失败都标“保存未完成”，从日志重放缺的变更或请求缺失的最新回应。无法判断是否已经公开时保留争议，不能用旧快照重演、重复发奖或把未选择的动作演完。无写权限时给获授权者一份明确标“待持久化”的交接增量，经回读确认前不得声称已保存。

**成本、风险和验证。** 保存时回读有耗时。把批量校验放在边界、只同步变动字段。等待保存和玩家看到上一个回复要分开计时，不能隐藏积压。测试六个故障点：事件写前/后中断、角色卡成功而 Runtime 失败、玩家视图失败、回执丢失后重试、双写旧版本。要求能辨别未完成、相同事件最多结算一次、每次恢复保留已呈现节点和待办。失败后回退派生视图/路由版本，不抹掉已公开经历。对应 H-REC-01、RT-06/08/09/11/17。

| 红色：明确质疑规则、伤害/任务成败/关键资源、不可逆后果。新增威胁/主要目标 | 区分规则型和结构型。前者取权威条文和当前状态，后者取原文/契约/独立依据，两者重合时都做。先核可行与代价→玩家决定→按序结算一次 | 简洁说明可知的选择、代价、何时需要骰子与依据。严重风险尚未核实时不流式输出定论 |
| T0：继续会放大事实、规则、隐私或模组身份损害 | 立即停止受影响叙事，保存现场，按 P0-2。仅“首次出现”“未知”不足以判 T0 | 简短告警和真实选项，绝不把后台原因作为戏剧揭晓 |

同一轮需要的两份互不依赖、权限允许的资料可一次定向取回。规则定位→原文→版本校对属于有先后关系的步骤。已有快照能回答时不先宣告“正在检查”，不开场回顾、不输出三色标签及内部审计。正常渲染对白和动作，允许情绪转折或重要场景自然展开。先通过相应闸门再输出可依赖的叙事。自然语言压缩须保持玩家当下观察、行动结果和下一步选择，具体栏位见 §8 的质量门槛。

**成本、风险和验证。** 预计减少普通轮工具往返、重复推理提示和无关输出。服务排队、思考时长和解码吞吐需单测。已加载不全或错误分级会导致“快而错”，优先升级。在含普通负例的盲测试中分别统计必须升级的召回与无故升级率。详见 B1–B3、B7。高思考偏好是默认设置，模型路由实验见 §7。所有候选档位均须通过同一质量门。

## 5. P2 体验优化与 P3 长期扩展

### P2-1　缩短重复说明，保住人物的选择和场景的可玩信息〔体验优化，可在合成桌并行〕

**证据及位置。** `ICE/06_POSTMORTEM.md` L48–52 涉及重复对话、多线失衡及资料成本。`G/CHARACTER_SIMULATION_SKILL.md` §§2–7、`G/NARRATIVE_PRESENTATION_SKILL.md` §§5、18 已有知识边界和代述限制。`ND/11_NARRATIVE_PRESENTATION_MATERIALS.md` L92、97 的手机与首访卡 L121 有冲突，后续 Session 提及归还但不能补出取回过程。F-33 还暴露“简报里有”与“玩家听到了”的差异。

**设计。** 只为本场有影响的人物调入当前目标、压力、上一轮承诺/关系变化、知道与能透露的边界。L0 用即时功能与眼前反应，长期 L2/L3 保留独立判断和拒绝空间。将叙事素材限定为表现候选，涉及持有物、受伤、关系、已知信息或新目标即回到字段所有者。对重复问题简述已说过的内容，留足新态度、动作和语气。相同信息从真正独立的来源再次获得，可以有新价值。公开简报记录实际传达的目标、可选奖励与可感知代价。对话常规过渡可按玩家明确意图压缩，承诺、暴露身份、冒险、耗资和新决定须还给玩家。

**收益、风险与验证。** 可减少解释性输出和 NPC 跨轮重复，而有效的对白可能更长。避免“一句动作＋一个问题”的固定句式，也不要以人物独特口癖代替知识一致。用熟人/陌生人、同一问题复问、关系改变、拒绝外围调查等盲样本，查泄密、擅代玩家决定、动作反馈缺失、台词重复，并比较场景与人物评分。曾训练的一个 L1 样本不足以支持全人物推广。对应 AT-04/08、RT-04/08/18、B7。

### P2-2　让规范修订与训练成果进入实际调用点〔维护必做，训练推广可选〕

**证据及位置。** 07 有两个 §12，13 有两个 §9。核心原则 L88 断链，训练计划 L93–97 与 L208 审题口径不同。10/11 专项规范缺显式文件名入口。人物档案 README L9、11 重复同一索引。02 §G 的无条件二审措辞可能使低风险 Prep 多做一轮。`G/Training_Logs/2026-11-24_NPC_DIALOGUE_AND_CONVERSATIONAL_FLOW.md` L78–90 明说只有一个 L1 样本。详见验收 A-01 至 A-05、A-07、A-10。

**设计。** 流程每个阶段只保留一个权威段，其他入口只留触发语与链接。旧章节保留可定位的历史指向，修复当前导航。历史 Preflight 以勘误链接到现地址，禁止伪造历史通过。12 与 13 统一标可选 QA，02 步骤4只在启动后执行。10（研究适配）及 11（应请求的专项审查）进目录并标触发条件。沿用训练 T1 候选，绑定适用情景、反例、用户反馈和复测编号。候选通过不同层级人物、不同场景与冷恢复后，仅将有效动作和触发位置反馈主 Skill／专项 Skill，留举例与长期解释在训练库。训练计划与 `CAPABILITY_TRANSFER.md` 继续区分个人风格、系统特例和通用能力。

**成本、风险和验证。** 重点收益是减少维护分叉及无条件二审。删除的 1,625 字符不能证明延迟改善。过度清理会断旧交接链接或丢失独立性纪律。用根/旧章节/独立 Handoff 三路导航回同一规则。给低风险模组走一次“跳过可选审核、仍做本次 Preflight”，给高风险样本走一次审前闭环。复测 A-03/04/05/07 与 RT-14/16/18。若旧客户端仍依赖原锚点，先保留跳转。

### P3-1　采用轻量系统接入契约，逐系统做差异适配〔第二套真实系统接入前必须〕

**证据及位置。** `Systems/README.md`、`G/05_MODULE_AND_SYSTEM_REGISTER.md` §§系统登记/战役登记与根协议 §7 已有接入框架。ID `triangle_agency` 与目录 `Triangle_Agency` 需显式映射。主流程 02 L66–68 出现 Sanctioned Behaviors 等专属检查。只有一个真实系统，不能以现有表现推断可运行另一个系统。

**设计。** 系统注册表从 ID 明确链接物理路径，强区分 candidate/active/archived。通用层拥有行动风险、来源/权限、恢复和审计。系统层拥有版次、术语、行动判定接口、资源/伤害/奖励、核查来源、专属 Preflight。Campaign 仅声明绑定与批准例外。通用层只询问“有哪些玩家可见目标和触发条件”，由 TA 适配返回相应目标、QA、伤害和奖励项。无需其他系统模拟 QA 或采用统一数值轨道。

**接入顺序。** 候选研究 → 系统 README 和权威版本 → 规则定位与未决入口 → 专属 Preflight 和机制样例 → 合成桌正/反例 → 独立 Campaign Binding → 明确启用。版本升级重跑有依赖的样例与一份旧存点恢复。无法证明兼容则保持旧桌固定版本。两个差异最大的机制、同名术语相反的测试系统以及同系统两张桌规不同的桌须交叉验证。模拟通过只能证明隔离用例，通过真实新系统的资料核查和独立主持验证后才能声称支持它。

**成本、风险和验证。** 每接一套系统需补少量映射和样例，日常 TA 轮无需读取其他系统。避免为未来假想规则抽象所有字段。验证路径大小写、跨目录读取 0 次、错系统裁定 0 次、未接入系统正确留在研究态。对应 H-RULE-01/02、A-06/09、RT-05/13/16。

### P3-2　按变更范围检查工程健康〔人工清单建议采用，工具化可选〕

**证据及位置。** 验收 §6.1 发现 156 次标准 Markdown 本地链接中有两个目标不存在。词法可达 93/126 是下界，不能把其余文件视作孤儿。改07、13及多系统迁移时出现多套章节和旧路径。末次训练修订留下旧入口。

**设计。** 复用 `G/04_EVALUATION_FRAMEWORK.md`、训练索引和模块登记的变更复核位置，按动过的对象检查相关入口。改普通链接只查目的地/大小写/锚点。改模板查一份旧存点、一个半写存点。改规则版查受影响的条文/桌规/人物能力。改公开投影查两位不同知情人。改路由查三入口及三档回放。记录变更、消费者、回归编号、结果与最后核查版本。能人工重现再考虑轻量检查器，检查器只在变更后运行，绝不插入每个普通轮次。

## 7. 把响应速度拆成可观测成本

用户关心从发出行动到读到回应，再到读完一场互动的等待。以下时间点用同一单调时钟。不同机器的服务端分解按请求 ID 对齐，时钟不能对齐时分别报告。

| 时间或计量 | 如何记录 | 哪种改动可能影响它 |
|---|---|---|
| 提交 `t0`。服务端首 token `t_model`。首个非空玩家可见字 `t_visible`。首段**有效行动反馈** `t_useful` | 分别报告模型调用自身的流式首 token 延迟、用户 TTFT＝t_visible−t0、有效首字等待＝t_useful−t0。隐藏思考、工具提示、进度语与“让我看看”不能计有效反馈。有多个模型调用逐次记 | 排队、网络、历史组装、检索往返、输入预处理/预填充、思考、缓冲与渲染都可能在首字前发生。隐性成因没有服务端遥测只能记 UNKNOWN |
| 末个可见字 `t_end`，持久化核对完成 `t_saved` | 完整回复＝t_end−t0。另报保存完成耗时和玩家下一步可安全行动的时间。分开记录首字前后工具调用，工具失败也计 | 压缩重复说明、减少多轮请求或隐藏审计输出可能缩短总时长。把保存延后未完成不算工作完成 |
| 输出 token、可见字符与持续生成 | 分别记输入/缓存命中/输出/可见/推理 token（仅接口提供时）。单段连续可见流的输出速率按首末 token 之间的 token 间隔数除以时间，计算为 `(N−1)/(t_last−t_first)`，N≥2。工具停顿另报。全程可见字符/秒仅作体验代理 | 解码受模型、硬件、负载、服务批处理、档位与采样等影响。输入变短可减预填充或检索，实际解码速率的变化要在相同输出任务上测。平台把若干 token 合成一块时只报告流块/可见吞吐估计 |
| 读写与上下文 | 记录唯一文件、调用次数、来源修订、片段、重复字符、线上传输字节、返回给模型的字符及每轮实际 prompt token。单独统计新加入的资料 token/字符与保留历史量。标记缓存命中、压缩与新窗口 | 批量读取减少往返，切片减少返回量，两者不必相伴。并发 I/O 记区间并集和依赖关键路径，不把相互重叠的时间相加。源文件下载一次仍可能整份喂给模型 |
| 人物与场景有效信息 | 盲评行动结果、可感知细节、关系和声音连续性、选择空间、必要风险/规则说明 | 去除复读可减少输出 token，删掉风险、人物回应或真实选择会制造虚假收益。自然长回复与同长度测试均保留 |

**模型与 Thinking 策略。** 第一轮 A/B 固定用户偏好的较高思考、同一模型与同一部署，单独检验工程收益。之后才在用户可选的环境做第二个实验因素：用短普通互动考察较轻档的首字与人物反馈。规则冲突、不可逆结果用审慎档检验正确率。Prep QA 在首次 Preflight 前按风险选同模型二审或授权的独立 GM-only 草稿审核。Session 后审计可在收束后集中做。任何档位若错过升级信号、破坏角色表现或新对话恢复不合格，就不启用该路线。使用同一模型不同提示不能称为跨模型通过。无手动批准的切换、无流式接口、无可用第二模型等情况分别标 NOT TESTABLE。正式游戏 LOG、玩家私密资料与其他桌的人物档案不自动转交模型。跨模型性能实验用合成夹具。稳定前缀缓存若宿主支持可作独立实验，命中率以平台返回为准。它不承担来源核验和状态持久化。

## 8. 配对基准、量化目标与记录方法

### 8.1 可重跑的对照

1. **定版本。** A 固定本文主分支 SHA，B 固定未来候选修订。先保留一套只读事故夹具测试是否应停，再以一套无争议的合成存点对比相同的正常工作量。另设缺旧字段、失配版、失效链接、源不可用和半写存档。两侧同时提供相同输入权限及原文。不得拿 A 持续主持与 B 迅速报错的时长相除。
2. **定输入与答案。** 给每题预设玩家意图、系统版本、可用资料、可见角色、秘密、必要事实/例外、可选而非强制的解法、骰面或玩家 QA 决策、各自应有的持久化结果。保留多种合法表达。参考答案与敏感后台依据只给评测者，运行实例看不到。普通/高风险、应暂停/应成功均有正反例。对含私有素材的复现仅在授权范围内本地完成。
3. **配对重放。** 同一模型/档位、工具权限和延迟条件、上下文窗口、采样、流式设置、设备与输出任务。能固定随机种子则固定并记录，不能则多次独立运行。随机交错 A→B 与 B→A，分离冷/热文件缓存与模型前缀缓存。无法清缓存时记“命中未知”。另安排独立新对话从存点恢复及一次新模型交接。长对话分别测固定相同历史前缀（隔离工程差异）及各自连续演进（测累积效应）。
4. **样本与统计。** 先每场景做 5 个配对排查夹具与观测错误。正式判断按每个主要场景／模型档位至少 30 对，覆盖至少 10 种输入、每种 3 次。长对话按整条对话、NPC 按整段互动配对，不能把同一串的 40 轮算作 40 个独立样本。报告配对差/比、中位数、样本数、失败/超时数、缓存分层和按夹具聚类的区间。至少 100 个可比较样本再用 p95 做正式尾部门槛。小样本尾部仅描述，区间跨过目标则结论“收益未证实”。可靠性零失败同时报告分子/分母，不能解释成真实错误率为零。
5. **两组输出实验。** 一组自由回复，以相同有效信息、选择和角色反应比较。另一组为同语义、相近可见输出量（如 token 数差 ≤10%）的配对，另以固定文字续写/流测试估解码，不把固定文字成绩当作主持成绩。自然输出不设硬截断。报告全样本及长度分层，不删超长/失败样本来制造优势。
6. **门槛顺序。** 先看事实、规则、保密、玩家选择和正确暂停是否通过，再看叙事质量，最后看速度与维护成本。候选路径失败则保留安全旧路径或暂停，基线有 T0 的分支不能作为正式服回退目标。

### 8.2 七类基准

下表均为**拟议目标**，没有实际延迟基线。时间 SLO 的基准 A 取同场景同档位且完成相同工作的样本，同时公布全部请求的成功率、超时和尾部。时间指标记为 A 的比值以便不同部署复用。取数预算超出要记录原因并保留必要核验。文件数按不同源路径，段数和实际调用次数另外计。已在快照中的数据计新读取 0。

**指标算法。** 正确率＝正确项/应核项，另列答对、错答、正确暂停及无故暂停。绿轮无故升级率目标 ≤5%，分母只含确实可安全直接回应的样本。红/结构性触发漏检率目标 0。B6 同时报告语义增量字符、实际重写的文件/字节和工具往返。若宿主每次保存都全文件重写，增量变小不能冒充磁盘写入减少。B6 重复独立写权率＝（同一作用域当前字段的可写槽位数−不同字段数）/可写槽位数，目标 0。另报视图实际重复字符，已标历史、可重建快照不计第二写权。B7 命题污染率＝无依据升格的命题数/被测需区分层级的命题数。语义重复由盲评者标注是否只是重说已有信息且未增加立场、情感、行动或证据。分母为零记 N/A。有效首字和总时长若 p50 达标且有足量尾部样本，p95 另要求 ≤1.05A。未达则报告例外并检查尾部检索阻塞。解码加速只有同输出/同配置的独立吞吐对照确实提高才能宣称。

**保护人物和玩家。** 两位不知道版本的评阅者分别以 1–5 分评“NPC 动机与知识一致”“对白有回应且自然”“场景给出可感知、可行动的细节”“玩家行动产生反馈且重要决定仍在玩家手中”。1 表示明显断裂或代玩家决定，3 表示行为合理且有反馈，5 表示回应具体、角色延续、为多种选择留下空间。质量目标为四项候选平均分均 ≥3.5、各项相对 A 配对均差 ≥−0.25。报告不确定区间与分歧，分差超过 1 分复核并保留原评分。泄密、偷改 CANON、代承诺等硬失败独立计数，不能被平均分抵消。可让玩家在独立测试样本中盲选更愿意继续的回复并记录理由，主观偏好不代替事实和规则判定。

### 8.3 无接口环境的最小记账格式

每个运行保存一行测量记录，GM-only 答案另存。最低字段为 `fixture_id | A/B修订 | 模型/档位 | seed或UNKNOWN | 窗口/冷暖/顺序 | turn_id | 真风险/分配风险 | 读文件数/段数/字符/版本 | 工具开始与结束 | t0/t_visible/t_useful/t_end/t_saved | input/cached/output/reasoning_tokens | 可见字符 | 核验、错误、盲评分 | 失败/超时`。存档测试加 `base_rev/event_id/写入字符/回读修订`。密钥、玩家私谈和未授权日志不进入共享样本。

只有聊天界面时，用同设备录屏或秒表从发送、第一处可见正文、第一处有效反馈、最终正文停止、确认存档五个点人工标时，保留计时分辨率和网络状态。文件读数用可见工具轨迹或人工检索记录，无法看到的后台调用标 UNKNOWN。输出只数可见字符，不能由中文字数猜 token。推理 token、缓存和服务端 TTFT 无观测则留空。没有流式输出则将可见首字与完成合并记录，服务端首 token 记 NOT TESTABLE。实际助手是否每轮加载完整 Skill、是否缓存命中、现有冷恢复成功率、首字及吞吐收益在本环境均无可发布的性能测值。

**正式使用的判定。** 工程负责人应先收到可复查的 P0 消缺证据与独立冷恢复结果。与某桌相关的系统绑定、关键来源、有效场次卡、装备用量、关键规则和本次 Preflight 均须可信，阻断条件按作用域处理。对《俯冲》还须完成有效分支的污染隔离、派生记录核查，区分原作、桌上经历、未执行计划、未授权的结构性扩展及后台真相。GM-only 与实际公开版本分别复核。将风险与可选处置告知玩家，由玩家决定继续、暂停或结束。即使玩家选择继续，也须核准可恢复的节点和剩余影响，再等待明确开始指令。任何 P1 延迟 SLO、P2 审美评价或 P3 新系统接入均不能关闭 T0。可选训练、缓存与第二系统也不构成当前桌额外开团前置条件。

**不值得先做的优化。** 当前只有一套系统、一张正式桌，按实体/章节/版次定位已足够，尚无证据支持全仓向量数据库、每轮多个模型开会、将全部历史转成事件数据库或整库统一 JSON。保留自然语言原文、既有文件夹和手工恢复通道。也不建议每轮扫契约七项、给每个路人建档、预写所有分支、让固定字数限制所有场景、用快模型先发一句再补核验，或为了“整洁”重写所有历史结案。只有实际基准显示明确瓶颈，并通过同一可靠性和叙事门槛后，才值得引入更重的实现。
