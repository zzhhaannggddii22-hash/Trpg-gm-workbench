# GM Runtime P1 性能与执行效率验证计划

- 状态：P1-0C DEFERRED BY USER；P1-0R ISOLATED HARNESS PASS；P1-1 PERFORMANCE PHASE AUTHORIZED WITH EXPLICIT RESIDUAL RISKS
- 建立日期：2026-11-24
- 前置基线：P0 第三轮 CONDITIONAL PASS；P1-0 目标环境基线于 2026-11-24 判定未通过（4 FAIL、1 PARTIAL）
- P0 基线提交：12ab4f2f57138592e00f613ac78b926a6137bcc6
- 原则：先证明目标环境可靠地执行，再测它执行得多快。性能不得用可靠性折损换取。

## 1. 目标与非目标

### 目标
1. 建立目标 ChatGPT 环境下可复现的 GM 运行可靠性基线。
2. 分离模型推理、资料检索/读取、状态持久化、上下文装配与用户可见输出的成本。
3. 比较完整 Preflight、健康 CONTINUE、按需回查、T0 审计等不同路径的实际成本。
4. 找到重复读取、过度上下文装载、冗余检查和无效输出等可优化环节。
5. 确认优化前后规则、事实、权限、状态和玩家能动性不退化。

### 非目标
- 不以文件字节数推算 Token。
- 不把本机 Python/CLI I/O、80ms 故障注入、子进程启动时间当成 ChatGPT 推理时延。
- 不把规范文件存在等同于模型在真实对话中会执行。
- 不在性能测试中改动正式 Campaign 或牺牲叙事质量。
- 不把一次性测试结果直接外推为所有模型、账户或 Thinking 档的普遍表现。

## 2. 阶段门槛

### P1-0｜目标环境可靠性基线（先做）

在目标 ChatGPT 对话环境中分别完成：
- REG-14：无历史新 Chat，从权威文件包恢复已呈现场景，验证不重播入口/最近回复。
- REG-17：无历史新 Chat，面对 Runtime、Session Log 与 Handoff 冲突，验证以权威来源识别争议并阻断受影响行动。
- REG-11：至少三个连续真实用户/模型轮次，观察首次偏移识别、T0 冻结和后续保持冻结。
- E13 下游路由：同一状态同时包含允许继续的 THREAD 与仍 OPEN 的争议分支；对每个玩家行动分别判断是否在 allowed_thread 内。
- 字段级导出：通过目标环境实际可用的玩家便笺/摘要/导出入口执行混合权限负例。

记录实际模型、账户/产品环境、可见 Thinking 档、工具入口、文件获取方式、是否有历史上下文、每轮原始输入/输出、实际读写和恢复方式。手动上传/下载与模型自主读取必须分栏记录。

门槛：REG-14、REG-17、REG-11 和 E13 路由不得出现硬失败；字段导出不得泄露 GM-only。若某能力在目标环境不可用，标 NOT TESTABLE，不得用本机子进程替代。

### P1-0R｜残余持久化故障补测（已完成：隔离文件系统故障注入）

已使用合成 Runtime State、Session Log 与 PREPARE manifest，在独立临时目录中执行三种进程崩溃注入：
1. Runtime dispute marker 写入并完成落盘后，进程立即终止，Log 尚未追加；
2. Log incident marker 写入并完成落盘后，进程立即终止，Runtime 尚未写入；
3. PREPARE manifest 已落盘，进程在两个目标写入前终止。

冷恢复由新进程执行：读取 PREPARE 与两个目标，按 batch_id、event_id、event_revision_id、payload_fingerprint 核验身份；只补齐缺失的争议/审计 marker，不重放领域事件。每个场景再执行一次恢复，检查幂等性。

结果：三种场景均 PASS。恢复后 Runtime/Log 各恰有一条对应 marker；checkpoint 保持原 revision；领域状态未改变；event 仍未应用；批次保持 INCOMPLETE，分支保持 DISPUTED，can_advance=false。详见 [P1-0R 故障注入报告](../Acceptance_Reports/GM_RUNTIME_P1_0R_FAULT_INJECTION_REPORT_2026-11-25.md) 与 [可重复执行脚本](../Acceptance_Test_Fixtures/P1_0R/p1_0r_fault_harness.py)。

证据边界：这是本机隔离文件系统/进程崩溃模型的协议测试，不是 ChatGPT 产品端或 GitHub Connector 底层存储的故障注入；不覆盖并发写入、持续性磁盘不可写、主机级断电、文件系统损坏或真实宿主持久化语义。上述项目留待地基质量阶段处理。

### P1-1｜隔离台架性能测量

准入前置：P1-0R 隔离故障注入已完成；用户明确要求先做性能优化。P1-0C 暂缓不等于通过，P1-0 历史失败继续公开保留。本阶段允许进行受控性能基线测量与单变量优化，但结果只能称为“当前目标环境/固定配置下的性能观察”，不得宣称 Runtime 全面可靠或 P1 可靠性验收通过。

固定模型/账户/Thinking 档与固定合成资料包。优化期间保留 T0 识别与告警、来源边界、玩家已知信息权限、关键状态与规则核验；不得用删掉这些硬约束制造虚假的性能收益。

| 路径 | 场景 | 测量目的 |
|---|---|---|
| A | 完整 NEW START / Preflight | 冷启动资料读取与上下文装配成本 |
| B | 健康 CONTINUE 绿色互动 | 最低成本日常主持路径 |
| C | CONTINUE 黄色重要行动 | 按需读取与状态更新成本 |
| D | 红色规则核验 | 权威规则读取、核对和裁定成本 |
| E | T0 识别与告警（临时模式） | 风险识别、告警生成与最小范围暂停成本；不测完整事故审计/恢复 |
| F | 部分写入恢复（隔离夹具） | P1-0R 已完成协议验证；如测耗时，只报告本机工程侧耗时，不代表产品推理/宿主 I/O |

每条路径至少重复 5 次；顺序随机化或交替，避免把网络/排队波动误认为方案差异。固定语义输入、资料版本、期望输出结构和状态初值。记录失败样本，不得只保留最快成功结果。

## 3. 采集指标与证据等级

### 用户/产品可见指标
- 首个有效内容延迟（TTFC）：从提交到首个有语义的回复内容；与 UI 动画/占位符区分。
- 完整回复延迟：从提交到回复完成。
- 若产品可见：模型/Thinking 档、使用量、Token、工具调用与限额信息。
- 运行中是否出现重试、拒答、工具失败或状态恢复。

若没有精确时间戳，使用同一设备的手动计时并标记为估算；不要伪装成平台遥测。

### 工程侧指标
- 文件读取次数、读取字节、读取文件清单、重复读取次数。
- 实际工具调用次数及每次工具耗时（若可观察）。
- 状态写入次数、写入字节、读回次数、失败/重试次数。
- 上下文装配清单：文件路径、版本/哈希、纳入原因、是否重复。
- 输出长度可记录字符/字数，但不推算 Token。

### 证据等级
- E1：平台直接显示或导出的指标。
- E2：工具真实调用轨迹/文件读写证据。
- E3：用户侧手动计时或观察。
- E4：模型估算或推断，只能作为备注，不能支持量化结论。

不同等级不得混合平均。尤其不得把 E2 文件 I/O 时间和 E3 用户端完整回复时间相加后称为模型推理时间。

## 4. 测试控制

每次运行建立唯一 run_id，并保存：模型与产品环境说明；固定测试输入、测试夹具版本和初始状态哈希；权威资料读取清单及文件版本；用户输入、完整助手输出和工具调用轨迹；每项测量的起止定义、数值、证据等级；最终状态、读回结果、断言与异常；网络/排队/客户端异常等混杂因素。

对比方案时一次只改变一个因素，例如完整读取 vs 经过验证的索引/按需读取、健康快路径 vs 完整检查、简洁输出 vs 当前默认输出。不允许同时更换模型、Thinking 档、资料包和输出要求后归因于某一项优化。

## 5. 优化候选与约束

优先验证：
1. 权威文件索引和精确读取路径是否减少重复读取；
2. Preflight 是否只装载当前桌面必要资料；
3. Runtime 快照是否足以支持绿色互动，黄色/红色行动能否准确按需回查；
4. 保存时是否只写变化字段，避免重复写入；
5. 事件信封、争议与权限信息能否复用已核验结构，减少重复整理；
6. 玩家可见输出是否减少重复解释，但保留行动反馈、风险、信息和选择。

每个优化都要做前后对照，并重跑相关 P0 回归断言。任何可靠性、事实准确性、信息权限或玩家能动性退化，立即回退该优化。

## 7. 进入正式 P1 结论的条件

本轮允许开展受控性能优化，但正式目标产品性能结论仍须满足：指标定义和证据等级明确；各路径有足够重复样本，包含失败与异常；性能比较没有混淆模型推理、工具 I/O、客户端等待和人工计时；优化后相关可靠性检查没有新增退化。

在 P1-0C 未复验前，所有结果必须标记“地基质量尚有未关闭风险”；不得把性能改善等同于可靠性改善，也不得把本机隔离台架数据换算成 ChatGPT 推理时延。
