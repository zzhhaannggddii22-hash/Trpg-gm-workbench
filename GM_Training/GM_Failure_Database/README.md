# GM Failure Database｜独立记录入口

> 一件问题一份 Markdown。仅在用户主动登记、查看或更新时读取命中的材料。通常在跑团后复盘调用，日常主持沿现有工作流执行。Session Log、训练日志、事故复盘与验收报告继续保存各自的原始经过。

## 1. 调用

- `记录 GM Failure：<一句话描述实际发生了什么>`。当前上下文只有一个明确事件时，允许只说 `记录 GM Failure`。事件缺失或指代不明时，只请用户指出是哪一件。
- `查看 GM Failure：<Failure ID>`。按文件名定向读取并返回实际状态与关联证据。
- `更新 GM Failure：<Failure ID>，<补分析、修复实施或回归证据>`。读回原条目，增量更新事实、证据及状态，保留此前的观察和结果。

登记时先保存用户描述的实际观察，注明它是报告、直接记录或可核验证据。原因未知直接记 `UNKNOWN`。发生时间、来源、规则系统、战役和严重程度按当时掌握的信息填写。知道预期与依据时一并记入，之后也可以补充。

## 2. 写入、读回与重复事件

- 使用调用确认的存储位置。正式记录目录为 `GM_Training/GM_Failure_Database/Records/`，首条真实且获准保存的记录产生时才创建。仓库只有读权限时，在允许的本地对应路径保存。无法写入时给出待落盘的 Markdown，明确该条尚未保存。合成验收材料只用单独的临时目录。
- 先按明确的 Failure ID 或来源定位查找同一条。来源定位可用日志路径、Session 轮次、Benchmark Run ID 加用例与轮次，或其他稳定标识。同一事件再次登记时使用已有 ID，追加新证据。已知是同一问题的复现或复验也更新原记录。独立事件使用新 ID，相似但尚未确认属于同一问题时可留关联。
- 新事件以登记地日期分配 `GMF-YYYYMMDD-NN`，从当天已占用编号之后的下一个序号开始，至少两位。例如 `GMF-20261125-01`。登记日期和实际发生时间分开。创建 `<Failure ID>.md` 前再次检查文件名，出现冲突时重新查询来源与编号，避免覆盖其他条目。预期是新建时使用不会覆盖现有文件的写入方式。
- 写入后从文件读回，核对 ID、实际观察和当前状态，再向用户返回已保存的准确路径。更新时追加日期、前后状态和证据位置。内容出现并发变化时先读出新版本并合并有依据的补充。

## 3. 最小记录

一句观察能建档。初始状态为 `DISCOVERED`，系统或操作者负责 ID、登记时间和已知来源。其他细节按必要程度追加。

```markdown
# <Failure ID>｜<一句话标题>

- 登记时间：<含时区>
- 状态：DISCOVERED
- 来源：<已知类别与定位，或 UNKNOWN>

## 实际观察
<一句话，注明直接记录或用户报告。可附证据引用及预期表现。>

## 原因推测
UNKNOWN

## 修复措施
待补

## 验证结果
待补
```

可补充发生时间，来源类型（真实跑团、Benchmark、模块训练、工程测试或其他），规则系统 ID／精确版本、战役／模组、预期行为与依据、主要类别、严重程度及相关文件。系统中立使用 `system-neutral`，适用范围未知时用 `UNKNOWN`。

主类别选规则执行、事实与连续性、NPC、叙事与场景、调查与线索、玩家行动响应、状态、工程与工具或其他。严重程度按需要区分 Critical、Major、Minor 或 UNKNOWN。关键事实、规则、权限失效或关键行动作废可考虑 Critical，需实质返工可记 Major，局部影响可记 Minor。

分析时区分有证据的流程缺陷和可能原因。修复段分别记提议与实际实施位置或版本。验证段记日期、环境、具体判据、结果、证据定位和覆盖范围。完整交互继续引用原日志或原报告。

## 4. 更新与关闭

| 状态 | 进入条件 |
| --- | --- |
| `DISCOVERED` | 已登记实际观察或注明来源的用户报告，原因可以 UNKNOWN。 |
| `ANALYZED` | 已明确预期或影响并完成初步分析。记录拟议措施时仍处于这一阶段。 |
| `FIXED_PENDING_VERIFICATION` | 已取得实际实施的证据，等待原失败对应层级的回归。静态资料变更只支撑该层级的结论。 |
| `CLOSED` | 已用对应环境与判据完成可复核验证，记下通过证据、关闭日期与范围。 |
| `BLOCKED` | 记录实际阻碍、此前状态和可恢复条件。条件具备后按已有证据回到适当阶段。 |

出现回归失败或关闭后的明确复现时，追加结果到原条目并回到分析。验证范围窄于原事件时，写清已证实的部分，待取得对应范围的回归结果再关闭。用户要求关闭时，先读回验证栏和相应证据。

## 5. 可选关联

Benchmark 来源可写 Run ID、用例 ID@修订及轮次／判据。回归时也可引用已有用例、实际跑团证据或工程复测。已有 Failure ID 时，新测试报告可以反向链接。两份材料分别保存自己的证据和结论。Failure 可单独登记、更新与关闭，跨场景训练目标继续由 [开放训练问题清单](../Training_Logs/OPEN_TRAINING_BACKLOG.md) 管理。
