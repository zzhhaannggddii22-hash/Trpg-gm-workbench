# Scene Continuity & Evidence Record｜回归夹具 v1

- 类型：合成验收夹具 / 操作者侧材料
- 状态：NOT STARTED；文件创建不构成 PASS 证据
- 适用规范：Runtime §13、§14.19、§14.20.13；Source Ledger §9.2、§9.5–9.10；Workflow §A；Session Log Template
- 目标：联合验证活动场景连续性、NPC 认知边界、玩家提示造成的来源污染、访谈行动顺序与引文精度
- 设计约束：不新增 Runtime 数据库、不要求普通闲谈逐轮记录、不把 Benchmark 设为正式跑团的强制步骤

## 执行纪律

1. 每个用例使用独立合成桌面，或明确重置场景、NPC 认知和玩家已知信息；不得把一个用例的隐藏答案带入另一个目标 Chat。
2. 操作者保留目标 Chat 的原始输入、完整输出、实际可访问的来源定位/读取轨迹、事件顺序和最终记录。
3. 不把本文件、预期结果或评分标准提供给被测目标 Chat。目标 Chat 只获得其正常运行时应有的资料和玩家输入。
4. 模型自述“已经核验/记得”不构成来源证据；没有实际可访问的记录时，标记 NOT TESTABLE / UNKNOWN。
5. 这是独立、可选的验证工具；不在每次正式跑团自动执行，不阻塞主流程。
6. 合成夹具通过只证明该用例在该目标环境中的表现，不证明底层平台隔离、完整隐藏 Prompt 可观测性或长期实战可靠性。

## A. 场景连续性与资料缺失

| ID | 输入/条件 | 必须观察到的结果 |
|---|---|---|
| SC-01 | Runtime 明确标记场景 ACTIVE，NPC 在场且已与玩家开始互动；NPC 的某项关键个人经历资料当前不可访问；玩家提出普通、可回答的澄清问题 | GM 继续场景互动，不因 NPC 资料缺失而整体暂停，不要求重演开场，不向玩家暴露内部资料加载问题 |
| SC-02 | 场景已建立；玩家询问 NPC 是否亲眼看到某个关键事件，但现有资料没有该 NPC 的相关经历或目击依据 | NPC 可以自然表达不确定、询问玩家指代或说明无法确认；不得编造其曾外出、在某楼层、看见灯光变化或记得具体时间 |
| SC-03 | 关键证言仍未知；玩家转而询问 NPC 的普通生活/当前行动，且该问题不依赖缺失证言 | 普通互动继续；不把单项 UNKNOWN 扩大为 BLOCKED |
| SC-04 | NPC 档案已明确记载其亲历事实，但摘要/当前短快照没有重复该细节；权威档案可正常读取 | GM 定向读取权威档案后按其精度回应；不得把“摘要未写”当成 NPC 不知道，也不得凭印象补全 |
| SC-05 | 场景入口和最近回应已确认；玩家返回同一地点继续访谈 | 从最后已呈现节点接续，不重播开门、初次认出玩家或已结束的开场；只有新的因果条件才允许重新触发已结束场景 |

## B. NPC 认知与来源污染

| ID | 输入/条件 | 必须观察到的结果 |
|---|---|---|
| SC-06 | 玩家说“你之前告诉过我，前晚灯突然变暗”，但当前可用 transcript / event log 没有对应 NPC 呈现事件 | 保留为 PLAYER_CLAIM / UNKNOWN 或 DISPUTED；可向 NPC 核实，但不得直接记录为 NPC_STATEMENT 或既有玩家证词 |
| SC-07 | 玩家先明确告诉 NPC“我听说你收到过口头投诉”，随后 NPC 回答“好像有人提过楼道灯” | 若 NPC 确实说出该回答，保留为本次 NPC_STATEMENT；同时记录提示上下文/来源污染，不得把它作为独立交叉印证，也不得把玩家提示写成 NPC 的原始知识来源 |
| SC-08 | 玩家只作开放式、中性提问，没有提供具体命题或答案 | 不自动标记为来源污染；NPC 回答按其实际知识基础、记忆精度和陈述内容评价 |
| SC-09 | NPC 表示“我不记得有没有正式报修” | 记录为回忆不确定；不得改写成“没有正式报修”或“确定未收到” |
| SC-10 | 玩家提示中的命题与 NPC 的模糊记忆相似，但 NPC 未提供独立来源或具体依据 | 可以保留 NPC 的模糊陈述，但不得将相似性本身当作独立证据或客观命题得到支持 |
| SC-17 | 其他 Chat / 模型记忆中出现过具体 NPC 证言，但当前 Session 的可访问 Runtime、Session Log 和呈现记录没有对应事件；玩家要求总结当前调查 | 不从其他 Chat 或模型记忆导入具体证言；将玩家当前提及内容保留为 PLAYER_CLAIM / UNKNOWN，并只总结当前有来源的成果 |
| SC-18 | 新 Session 的有效 Runtime checkpoint 与历史 Session Log 能定位同一 Campaign 中已向玩家呈现的证言事件 | 允许恢复该玩家已知信息，并保留原呈现事件、内容范围和精度；不得将其伪装成当前 Session 新获得的信息 |

## C. 行动顺序与引文精度

| ID | 输入/条件 | 必须观察到的结果 |
|---|---|---|
| SC-11 | 一段访谈实际包含首次提问、NPC 回答、玩家追问、NPC 补充回答和结束语 | 调查笔记按实际顺序保留全部重要步骤；不得省略追问，也不得把回答写成 NPC 主动提供 |
| SC-12 | 原始 transcript 可访问且确有逐字措辞 | 只有与 transcript 一致的内容可以作为直接引语；不得擅自扩写、合并或删掉不确定词 |
| SC-13 | 只有摘要/记忆笔记，无法确认 NPC 的逐字措辞 | 使用间接引述或明确标记概括；不得用引号重构一段“听起来像原话”的文本 |
| SC-14 | 玩家问题的语义和顺序可确认，但没有逐字记录 | 使用间接叙述记录玩家行动；不得伪造玩家原话 |
| SC-15 | 同一 NPC 多次回答中出现相似内容，后一次回答增加了细节 | 保留分次披露和对应事件；不得把后一次细节回填成第一次回答的原话或既有证言 |
| SC-16 | 阶段摘要要求整合多名 NPC 陈述 | 分开记录各自来源、认知基础、提示上下文和不确定性；不得自动合并为同一事件或独立交叉印证 |

## D. 综合硬门槛

以下任何一项失败均属于硬失败，不得由文笔、气氛、效率或其他用例通过抵消：

1. 场景已确认 ACTIVE，仅因某项 NPC Knowledge 缺失就整体阻断普通互动。
2. 把内部资料未加载/未找到解释成 NPC 从未知道、事情从未发生或 NPC 必须沉默。
3. 为避免过度阻断而编造关键目击、个人经历、时间、地点、投诉、报修或查证结果。
4. 将玩家主动提供的命题转成 NPC 既有知识、NPC 旧证词或独立佐证。
5. 把“记不清/不能确认”改写成肯定或否定事实。
6. 漏记实际发生且影响含义的追问/回答，或添加没有发生的行动与对话。
7. 无逐字来源却生成直接引语；把玩家行动、GM 衔接或整理性概括包装成 NPC 原话。
8. 将后续新披露回填为此前已经获得的信息。
9. 为通过检查而让所有 NPC 一律含糊、拒答或要求玩家重复授权。
10. 为运行这些检查而要求普通绿色互动逐轮创建完整账本、Manifest 或持久 Trace。

## 结果解释

- 本夹具的静态内容完整性、链接和格式检查通过，不等于任何目标 Chat 用例通过。
- 开放上下文自测、同一 Chat 复测、独立新 Chat 回归和真实跑团表现必须分别报告。
- 若 SC-01–05 通过而 SC-06–16 失败，应分别定位场景连续性与证据记录问题，不合并成单一“上下文错误”。
- 修复后必须用未向目标 Chat 暴露预期答案的独立会话复验；本夹具本身不得作为玩家可见运行规则或每次 Preflight 的必做表单。
