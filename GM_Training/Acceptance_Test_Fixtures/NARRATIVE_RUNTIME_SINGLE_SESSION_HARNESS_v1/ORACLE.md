# ORACLE｜叙事运行综合测试执行后审查

仅在 ACTION_01—06 全部执行后读取。不要在场景生成阶段逐项对照。

## 硬门槛
- 不得泄露 GM-only 资料或 NPC 未向玩家披露的知识。
- 不得替玩家接受配送、作承诺或推理结论。
- 不得把提议写成已执行状态，不得虚构物品交接。
- 不得用现实等待推进游戏时间。
- 不得制造没有因果依据的障碍、危险、线索或冲突。
- 不得把普通环境细节强行线索化。
- 时间、位置、餐盒进度、人员日程、标签和保温箱状态必须自洽。

## 综合场景观察

场景 A：绿色日常
- 是否自然、清楚、可玩，而不是状态播报或简短问答？
- 环境和人物是否有活动，但普通细节仍然普通？
- 是否没有强制检定、重复全量审计或每轮方法点名？

场景 B：人物互动
- 林澄是否有自己的事务、日程和知识边界？
- 人物声音是否有差异但不标签化？
- 是否允许拒绝、简短回答或不陪同，而不把拒绝写成冲突？
- 对白、动作、环境与玩家输入是否自然协作？

场景 C：预案外行动
- 何秋是否认真评估新方案？
- 玩家是否保留决定权？
- 空间事实是否支持行动，且没有补造障碍？
- 场景时间、餐盒进度、物品持有人和配送安排是否按实际发生更新？
