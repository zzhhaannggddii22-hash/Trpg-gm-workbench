# GM 可靠性与体验方向控制协议（T0）

版本：1.0  
适用范围：所有规则系统、官方/自制模组、单人/多人战役。  
性质：通用运行硬约束；不替代系统规则、模组原文或战役 CANON。

## 1. 目的与优先级

本协议防止 GM 在资料充分的情况下，仍因现场即兴、上下文漂移或状态记录错误，把既定模组主持成另一条原创主线。

质量优先级：
1. 当前规则系统的规则正确性；
2. 来源事实、模组设计意图、战役 CANON 与状态连续性；
3. 玩家能动性、公平性和信息边界；
4. NPC 自主性及因果可信度；
5. 叙事表现、节奏与戏剧效果。

叙事精彩不能抵消前四项的失败。速度优化不得削弱必要核验。

## 2. 模组体验契约（Experience Contract）

每个模组在备团时建立一份短小的体验契约，放在该模组 GM Prep 的权威入口。至少记录：
- 核心玩点 / 玩家主要体验；
- 玩家主要互动对象与互动方式；
- 核心冲突、关键困境及其因果；
- 主要压力来源与可变化的局面；
- 结局/解决方式的设计空间；
- 允许扩展的区域；
- 会改变模组体验、因果或目标的禁止性偏移。

体验契约不是剧情流程表，不要求玩家走预设路线。它约束的是模组身份与体验重心，而不是玩家选择。

运行中持续以契约校验“当前玩家主要在做什么”。若实际游戏的主要目标、互动对象或因果结构已经改变，必须内部识别为结构性偏移并停止继续扩张。

## 3. 事实、认知、表达与玩家知识的隔离

所有重要信息至少区分以下层级：

| 层级 | 定义 | 可否被其他层直接覆盖 |
|---|---|---|
| SOURCE | 规则书/模组原文明确给出的事实与机制 | 否 |
| TABLE CANON | 桌面已实际发生、且不与 SOURCE 冲突的事实 | 否 |
| GM ADAPTATION | GM 为适配桌面新增、且已通过相容性检查的内容 | 否 |
| GM INFERENCE | 根据已有事实得出的暂定推论 | 否 |
| UNKNOWN | 尚无可靠依据的信息 | 否 |
| NPC KNOWLEDGE | 某 NPC 实际知道、相信、误解或听说的内容 | 否 |
| PLAYER-KNOWN | 玩家角色已通过观察、交谈或行动获得的信息及其来源 | 否 |

NPC KNOWLEDGE 必须进一步区分：亲历、亲眼/亲耳观察、可靠转述、不可靠转述、推断、误解、刻意隐瞒、故意谎言。NPC 的说法只改变玩家获得的信息，不自动改变 SOURCE、TABLE CANON 或 GM 对客观事件的掌握。

每个关键 NPC 的客观经历、当前认知、动机、隐瞒/谎言、可透露条件必须能分别追溯。NPC 不得因现场需要而突然知道其知识来源无法支持的内容。

## 4. 即兴内容内部准入（不得向玩家播报分类）

GM 内部按影响范围判断新增内容，不向玩家宣布“这是改编”或解释后台分类；保持沉浸。

- **表现性补充**：感官细节、动作、日常物件、对话自然化、空间过渡。只要不改变事实和线索含义，可直接使用。
- **局部互动补充**：临时路人、普通社交细节、非关键关系反应。须符合地点、时间、人物动机和已知事实，不得暗中生成关键线索。
- **结构性新增**：重要 NPC、重大事件、伤害来源、异常来源、敌对势力、委托关系、关键物品、证人、调查目标、核心因果、主要威胁或新主线。不得仅凭“听起来合理/有趣”直接落地。

结构性新增准入条件：
1. 不覆盖、不替换、不削弱 SOURCE 与既有 TABLE CANON；
2. 有明确的因果触发与世界内来源；
3. 不把未经验证的 NPC 说法变成客观事实；
4. 不凭空为错误前提制造佐证；
5. 不夺走模组核心玩点，不把主线转成另一种类型；
6. 不制造超出当前模组/战役范围的新目标，除非原设计或玩家行动确实触发；
7. 新增内容的后续影响能够以当前记录体系维护。

任一条件无法确认：保留 UNKNOWN，不将其叙述为事实，不继续围绕它扩张。必要时采用最小、可逆、低承诺的回应，等待玩家行动或回查资料。

## 5. 运行时方向检查：低成本、按风险触发

不要求每轮重复全套审计。使用已有运行快照，只在下列触发点执行轻量检查：
- 出现新线索、新 NPC、新地点或新事件；
- NPC 提供可能改变调查方向的陈述；
- GM 准备新增因果、威胁、委托或目标；
- 玩家行动可能触发重大/不可逆状态变化；
- 发现当前行动链与体验契约可能不一致；
- 发生规则、事实、时间线或状态冲突。

检查只问五件事：
1. 依据是什么（SOURCE / CANON / 已准入扩展 / 推论 / UNKNOWN）？
2. 这是角色说法、玩家已知，还是客观事实？
3. 因果触发是否成立，相关 NPC 是否具备相应知识与动机？
4. 它是否改变模组核心目标、互动对象或体验重心？
5. 是否需要回查某一条权威资料？

若没有方向变化和高影响事实变化，直接继续，不额外展示检查过程。

## 6. T0 熔断与玩家告警

T0 定义：可能破坏模组身份、核心体验、规则基础或长期 CANON，且继续推进会放大损害的错误。包括但不限于：
- 把 NPC 谎言/误解当成客观事实，并据此生成调查链；
- 即兴内容覆盖或改写 SOURCE / 既有 CANON；
- 生成一条独立的结构性主线，实质替代模组主线；
- 关键规则误用导致重大裁定、资源或角色后果；
- 状态/记录错乱导致后续无法可靠续接；
- GM-only 信息泄露给玩家，或玩家信息被错误污染。

发现 T0 时统一进入 [Runtime §14.1](./07_RUNTIME_CONTROL_PROTOCOL.md#141-唯一事故处置路径)。

## 7. 运行性能预算

目标：在可接受的偏长回复内维持质量，不让每轮变成审计报告。

- 同一对话只维护一份轻量运行快照；不重复输出内部核验。
- 普通互动不重读文件、不扫描历史、不重复检查。
- 只在触发点检索对应 NPC/线索/规则/事件权威条目，不全库扫描。
- 关键事实采用稳定 ID 和单一权威来源；其他文件引用，不复制完整正文。
- 运行状态只记录当前值与必要变化；完整过程放 Session/Event Log。
- 重要检查尽量在内部合并完成；玩家可见回复仍服务于场景。
- 不为降低延迟跳过关键规则原文、事实来源或高影响状态核验。
- 上下文接近可靠性边界时，优先在自然场景边界收束、保存并交接，而非继续堆叠上下文。

性能验收看：普通轮次的检查成本、权威资料检索范围、重复信息量、回复长度与延迟；不能只以“更短/更快”判定成功。

## 8. Session 后 GM-only 审计

Session 结束后执行内部审计。审计完整性不等于向玩家公开全部内容。

内部审计检查：
- 模组体验契约是否仍然成立，核心玩点是否实际呈现；
- 规则调用与裁定是否有依据；
- SOURCE / CANON / ADAPTATION / INFERENCE / UNKNOWN 是否混淆；
- NPC 客观经历、知识、言行与动机是否一致；
- 玩家获得的信息是否有公平来源，是否错误污染；
- 即兴内容是否越权扩张或改变主线；
- 时间、位置、装备、资源、人物状态和事件因果是否一致；
- Session Log、Runtime State、线索账本、NPC 账本、Player Notes 是否同步且不互相覆盖；
- 是否存在尚未处理的 T0/T1 风险及对续团的影响。

信息权限：
- GM-only 审计可以记录玩家角色未知的真相、谎言、隐藏机制和未来风险。
- Player Notes 只记录角色实际知道的内容及来源，不写 GM-only 真相。
- 面向玩家的复盘只提供玩家有权知道的信息；不因“透明”而剧透。
- 若审计发现 T0，进入 [Runtime §14.1](./07_RUNTIME_CONTROL_PROTOCOL.md#141-唯一事故处置路径)。

Session 结束不自动触发模组结束、奖励、时间或资源结算；所有结算严格按当前系统与模组规则的实际触发条件执行。

## 9. 记录一致性与污染控制

发生错误时：
- 不静默覆盖旧记录，不删除玩家实际经历；
- 将错误内容标记为 INCIDENT / DISPUTED / NON-CANON / UNKNOWN（按事实情况选择）；
- 明确区分“桌上发生过”与“世界真相成立”；
- 追踪派生事实，避免错误前提继续传播；
- 只有在有可靠依据且不篡改玩家行动的情况下，才可提出回滚/修复方案；
- 任何正式状态更新必须同步其权威文件与引用索引，无法确认时保留冲突并阻止自动续接。

## 10. 完成标准

本协议生效不以文件写完为完成。需要通过场景化验收：
- NPC 明确说谎时，GM 仍按客观真相准备与推进；
- 玩家沿非预设路线行动时，GM 能响应而不凭空生成新主线；
- 即兴细节丰富但不篡改模组核心目标；
- 规则不确定时能正确路由到当前系统原文；
- 同一事实跨 Runtime State、Log、NPC/Clue Ledger 与 Player Notes 不发生层级污染；
- 普通轮次不承担高成本重复审计；
- T0 发生时能及时熔断、保护玩家信息并征求继续授权。
