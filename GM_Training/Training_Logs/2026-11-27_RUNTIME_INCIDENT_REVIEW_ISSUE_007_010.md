## 2. ISSUE-007｜资料不完整时过度阻断分析与调查推进

- 项目编号：ISSUE-007（GitHub #41）
- 等级：P2
- 真实表现：玩家要求根据社区登记记录进行按周整理、时间线和趋势分析。GM 因数据不足而过度收缩，未充分利用已有记录给出有边界的观察和下一步调查建议，导致推进停滞。
- 正确行为：先界定可用数据、覆盖范围、分母和缺失项；分开直接观察、有限推断和未知；不伪造精确数字，但仍交付资料实际支持的定性判断与可行动的后续查询。
- 现有规范：Runtime §12.7 已明确规定不完整数据下的证据约束分析；§14.20.13 已规定单项知识缺口不得冻结整个场景。
- 阶段判断：规范覆盖基本充分，问题更像执行失效；是否同时存在资料路由/上下文装配问题，仍需后续样本定位。
- 自测证据：既有 ISSUE-007–010 单会话自测报告记为 PASS；该样本为合成数据，且基线为旧提交，不证明真实 SESSION 02 已修复。
- 状态：OPEN。真实场景需观察 GM 是否主动完成有限分析，而非把推理工作推回玩家。

## 3. ISSUE-008｜Chaos Pool 变化未被持续记录

- 项目编号：ISSUE-008（GitHub #42）
- 等级：P1
- 真实表现：Chaos Pool 发生变化后，没有在同一轮稳定记录变化原因、前值、增减量、后值与当前余额；历史缺口又不足以还原时，不能猜测补账。
- 已落地约束：Runtime §4.1 现要求资源流水采用准确字段、前值、变化量、依据、后值和应用状态；关联字段分别记账，未知前值不得推算伪装成已核验余额。
- 本次进一步明确：资源变化必须在同一轮裁定中完成流水、余额更新和玩家可见说明，不得拖到 Session 结束；若前值待核，只记录已确认增量，并只暂停依赖该余额的后续行动。
- 状态处理：Bower Street 历史普通 Chaos Pool 余额仍为 UNKNOWN / NEEDS RECONCILIATION。不能用开局 0、曾临时报出的 +5 或其他旧快照推算最终余额。
- 自测证据：既有单会话自测报告记为 PASS WITH LIMITS；只验证同一回复中的数值闭环，不证明外部持久化、跨 Session 恢复或真实资源账本一致。
- 状态：OPEN。后续真实资源变化必须即时记录，并在 Session/Runtime 保存后定向回读。

## 4. ISSUE-009｜VHS 对话中的无依据空间陈述与机制提示

- 项目编号：ISSUE-009（GitHub #43）
- 等级：P1（疑似，按原 Issue 状态保留）
- 真实表现：VHS 影像女孩的部分第一人称回答包含未经来源支持的空间经历；同伴角色也曾给出缺少角色可见依据的机制解释。
- 边界：玩家提出“这里是什么地方”是正常调查问题，不应把玩家提问本身当成泄露。问题在于 GM 生成了缺少依据的回答，并可能借 NPC/同伴台词把 GM 推断送入玩家频道。
- 现有规范：Runtime §14.19 已规定玩家可见断言和推断前提必须通过接收者权限过滤；Bower Street 08_PLAYER_FACING_GATE.md 已明确 NPC 第一人称台词也是事实断言，不能临时补写房间、门、出口、被困原因或异常机制。
- 阶段判断：不是缺少一份信息闸门，而是闸门在真实演绎中没有稳定执行。不能把 NPC 台词当作事实豁免，也不能用暗示、比喻或同伴推断变相泄露。
- 纠正边界：未经支持的陈述标记为 GM 回复失误，不升级为角色知识、线索或 CANON；保留玩家确实看过该文本的事实，不假装没有发生。
- 自测证据：既有合成单会话自测记为 PASS；尚不足以替代对完整 SESSION 02 对话与呈现锚点的复核。
- 状态：OPEN，等待完整来源复核与后续真实互动证据。

- 历史 Chat 检索必须如实报告实际取得的是完整逐轮记录、用户提供文件、Session Log、摘要还是检索片段。授权不等于平台自动提供访问能力。

### 7.2 写作自习到真实 GM 能力的迁移

当前记录不把一次口头“已应用”当作真实跑团能力提升证据；稳定性仍需真实 Session 验证。
