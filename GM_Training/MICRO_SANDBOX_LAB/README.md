# GM 微型箱庭实验室（Micro-Sandbox Lab）

> 版本：0.1  
> 状态：初始原型；训练效能与运行可靠性尚未验收  
> 归属：GM_Training（跨规则系统通用）  
> 性质：可玩的微型 TRPG 场景 + GM 综合训练与观察工具

## 1. 项目定位

微型箱庭实验室是一组规模受控、目标明确、路径开放、可独立游玩的 TRPG 场景。玩家进入一个边界清晰的小空间，知道自己想完成什么；GM 负责模拟空间、人物、物件和局势，让玩家通过自由行动改变场景。

它同时承担两项职责：

1. **游戏本身**：每个箱庭都应当是一个有趣、完整、允许玩家自由尝试的小型游戏，而不是披着游戏外衣的考试题。
2. **GM 训练**：在连续互动中观察场景呈现、NPC 自主性、行动理解、因果推演、信息公平、节奏与状态连续性。

设计参照是“兽人与饼”一类小规模、目标直观、解法开放的互动场景。只借鉴设计原则，不复刻其具体人物、文本或谜题。

## 2. 与现有 GM 工作台的关系
### 1.1 好玩优先：实验室的首要设计原则

微型箱庭必须首先是一场值得参与的游戏。测试与实验是设计和运行它的方式之一，最终目标仍然是创造有趣的 TRPG 体验，并借此观察 GM 能力。不得把玩家当作测试工具，也不得把枯燥的能力测试包装成游戏。

这条原则高于固定场景模板和训练便利性：

1. **先有玩家体验，再有观察目标**：先确定玩家会经历什么、为什么愿意投入、有哪些值得做出的选择，再考虑哪些 GM 能力会在自然互动中得到检验。
2. **每个场景都应有自己的玩法与体验重心**：可以围绕探索、推理、逃生、社交博弈、潜入、求生、谈判、恐怖或其他体验构建，不要求所有场景都采用同一种目标结构或互动节奏。
3. **测试融入游戏，不驱动玩家**：训练目标在幕后观察。不得为了触发某项能力、检定或观察指标而强行制造事件、风险或玩家行动。
4. **规模受控不等于玩法单调**：微型指的是体验范围和准备成本可控，不意味着只能有一个简单任务、固定数量的 NPC 或单一解法。场景结构应服从其玩法目标。
5. **允许多元的好玩**：不同类型的场景可能分别依靠好奇、推理、紧张、恐惧、策略、社交、创造性解决问题、情感投入或意外发现产生乐趣，不预设唯一的趣味标准。

### 1.2 场景设计的起点

设计新场景时，优先回答以下问题；它们是设计提示，不是必须逐项打勾的公式：

- 玩家扮演什么角色，为什么此刻愿意参与？
- 玩家眼前有什么目标、处境或值得探索的问题？
- 主要玩法循环是什么：探索与发现、搜集与推理、伪装与交涉、规划与逃生，还是其他？
- 玩家有哪些有意义的选择，选择会如何改变局势？
- 场景会提供哪些有辨识度的情绪或体验时刻？
- 场景如何自然收束，并让结果回应玩家的行动？

密室逃脱、暴风雪山庄、恐怖逃生、舞会间谍任务等都可以成为原型方向，但只是例子，不构成封闭类型清单。避免反复用同一结构换皮。

### 1.3 好玩性的观察与评价

好玩具有多元性和主观性。现阶段不建立单一趣味总分，也不把玩家满意度压缩成一个数字。先通过不同类型的场景和真实游玩反馈积累证据，再逐步形成适合不同玩法的评价语言。

复盘时可结合场景类型观察：玩家是否主动投入；选择是否有意义；探索、推理或互动是否带来发现；局势是否对行动产生可信回应；节奏和压力是否符合预期；是否出现惊喜、紧张、成就、情感投入或值得回味的结果。并记录玩家实际表现与反馈，不以 GM 自评代替体验证据。

### 1.4 双重验收

每次运行分别回答两个问题：

- **游戏体验**：这是不是一场值得玩的游戏？乐趣来自哪里，是否符合该场景的体验目标？
- **GM 表现**：GM 是否可靠地创造、主持并回应了这场体验？

两者都重要，不能互相抵消。场景可以很好玩但暴露规则、事实或连续性硬失败；也可以执行稳定却缺乏吸引力。两类结果必须分别记录。

- 本项目位于 `GM_Training/`，属于跨系统通用训练资产。
- 不归入 `Systems/Triangle_Agency/`，不绑定某一套规则。
- 不属于任何正式 `Campaigns/`，所有场景、角色和结果默认均为 NON-CANON。
- 不替代 GM 稳定性验收、盲测、真实跑团或正式模组 Prep QA。
- 当前 GM 项目的第一优先级仍是稳定性与执行可靠性。微型箱庭是可控训练和娱乐补充，不得挤占稳定性修复资源。

## 3. v0.1 的规模约束

初期场景刻意保持小巧：

- 一个主要活动区域；
- 一个玩家明确知道的主要目标；
- 通常 1–3 名重要 NPC；
- 约 3–6 个值得注意或可以互动的对象；
- 一组清楚的空间关系和物理事实；
- 约 10–25 分钟的典型游玩长度，但不强制计时或赶剧情。

规模是控制复杂度的工具，不是限制玩家行动的围栏。玩家提出合理的场外行动时，GM 应如实处理其可行性，不得为了维持箱庭边界而无理由封锁世界。

## 4. 设计原则

1. **目标明确，手段开放**：玩家知道自己要做什么，但不被告知标准解法。
2. **小空间，真世界**：场景有限，但 NPC 有自己的动机、知识、顾虑和事务；物件有稳定属性。
3. **可观察、可互动**：关键条件应有公平的观察或询问路径，不依赖猜 GM 心思。
4. **因果先于戏剧**：NPC 与环境按既定事实运行，不为制造冲突临时改变事实。
5. **允许普通结果**：玩家可以成功、失败、绕路、放弃、闲聊，甚至什么特别的事也没发生。
6. **玩家不负责配合测试**：玩家自由行动；训练目标在幕后观察。
7. **不预制分支树**：备团准备世界状态、人物动机、物理约束和可见信息，不写死玩家逐步走法。
8. **短小但完整**：宁可一个小场景有真实互动和收束，也不靠增加地点、NPC、线索堆出复杂度。

## 5. 场景类型

每个场景指定一个主要体验重心，可附一个次要重心：

- **社交型**：关系、利益、信任、误解、交涉与人物自主性。
- **探索型**：空间、观察、物件、环境变化与线索公平。
- **怪谈型**：异常规则、感知、信息揭示与不确定性。
- **问题解决型**：明确困难、有限条件、多种可行办法与因果推演。
- **危机型**：时间、风险、局势变化和压力下的判断。

类型用于选择训练观察点，不是强制情节公式。混合类型可以存在，但 v0.1 每个场景只设一个主要重心。

## 6. 训练与游戏的分离

每次运行分成两层记录：

- **玩家体验层**：玩家目标、场景呈现、实际行动、世界响应、结果与收束。
- **GM 观察层**：硬性稳定性检查、叙事表现观察、失败证据、未知项和改进假设。

GM 不向玩家播报评分维度，不因测试需要诱导玩家行动。训练记录不得把模型自评伪装成玩家体验证据。

### 硬性稳定性观察

优先检查可明确判断的行为：

- 是否维持空间、物件、人物位置与状态；
- 是否保持 NPC 动机和知识边界；
- 是否正确理解玩家意图，没有替玩家决定；
- 是否按已建立事实推演行动后果；
- 是否区分观察事实、NPC 说法、推断与未知；
- 是否没有无依据添加结构性事实或强推路线；
- 是否准确记录场景状态与结束时结果。

任何严重硬失败都单独记录，不能被叙事表现或总分抵消。

### 叙事体验观察

记录场景是否清晰、自然、有吸引力，NPC 是否令人信服，节奏是否舒适。审美评价以定性观察为主，不强行伪装成精确量化指标。叙事训练现阶段仍为“初步通过”，单次箱庭表现不能升级长期能力结论。

## 7. 规则系统绑定与实验室简易规则

默认不自动套用三角机构或其他正式系统的专属机制。每次运行应明确当前使用的是纯叙事裁定，还是 Micro-Sandbox Lab 的简易实验规则。

### 7.1 Micro-Sandbox D10（实验室专用）

用户指定的极简规则如下：

- 对真正不确定且有戏剧价值的行动，先根据行动本身确定难度阈值 X。
- 掷 1D10；结果**大于 X**即成功。
- 玩家采取的合理行动、准备、工具、环境优势或他人帮助，可以降低实际阈值 X。
- 当 X ≤ 1 时自动成功，不再掷骰。
- 检定应当很少使用；普通、明确或失败不产生有意义变化的行动不检定。
- 不为了展示规则、训练骰制或制造失败而强行要求检定。

阈值修正应由行动与场景条件支持，不应成为事后迁就玩家或任意惩罚的工具。失败后果应根据当前场景的事实、风险和行动方式裁定；本规则暂不规定统一的失败后果表。

**隔离要求：** 这套 D10 仅属于 Micro-Sandbox Lab 的实验规则。不得自动迁移到 D&D、COC、Triangle Agency 或其他正式 Campaign；正式跑团始终遵循其绑定的 system_id、规则版本与桌面约定。

如果某次箱庭明确选择不使用 D10，则按纯叙事裁定运行，并在记录中注明。

## 8. 标准运行流程

1. 选择场景并确认玩家可见目标。
2. 建立场景起始快照：地点、人物、物件、时间/环境状态。
3. 向玩家呈现可感知的开场，不泄露 GM-only 信息。
4. 玩家自由行动；GM 按人物动机、空间事实和行动条件响应。
5. 只在真正不确定且有意义时调用当前规则或明确说明风险，不为了训练强制检定。
6. 目标达成、玩家决定离开或场景自然结束时收束。
7. 分开记录玩家体验、硬性检查、叙事观察与待验证假设。

## 11. 后续演进

先用少量原型验证这种训练形式是否既好玩又能提供有效证据。初期建议覆盖社交、探索、问题解决三种不同重心；在没有实际运行证据前，不扩大规模、不建立复杂工具链。

场景有效性与 GM 能力结论分别记录：一个场景好玩，不等于 GM 已稳定掌握能力；一个场景适合测试，也不自动意味着它是好游戏。
