# 微型箱庭与实际跑团的双向能力迁移协议

> 版本：0.1  
> 状态：工作协议；待后续多场景与真实 Session 验证  
> 适用范围：跨规则系统通用 GM 能力  
> 不改变任何 Campaign CANON 或具体系统规则

## 1. 核心关系

微型箱庭与实际跑团不是两套互不相干的训练，也不是把同一场游戏缩小/放大。两者承担不同职责：

- **微型箱庭：可控实验环境。** 用较少变量观察某项能力在连续互动中的表现，尝试修正方法，并检查其副作用。
- **实际跑团：综合实战环境。** 检验多项能力能否在真实玩家、正式规则、模组约束、长期状态和不可预测行动中协同工作。
- **GM 工作台：能力中枢。** 保存可复用方法、证据、缺陷和验证计划，决定哪些方法可进入通用运行规范。

微型箱庭表现良好，不等于正式跑团能力已经通过；真实 Session 中一次成功，也不等于方法已经稳定。

## 2. 双向迁移

### A. 微型箱庭 → 实际跑团

1. **观察**：从箱庭实际互动中提取具体行为证据，而不是只记“气氛不错”或“NPC 很生动”。
2. **抽象**：把有效表现写成可复用方法，明确触发条件、执行方式、预期效果、适用边界和反模式。
3. **登记候选**：先进入通用 GM 能力/训练记录，保持 CANDIDATE 或 NEEDS_FIELD_VALIDATION，不因一次箱庭运行就直接宣称掌握。
4. **备团适配**：将候选方法转成 Preflight/Prep 中可调用的准备要求。例如准备 NPC 当前目标与知识边界、空间锚点、可观察信息、行动约束和可变化状态；不得把箱庭角色或解法搬进正式模组。
5. **实战应用**：在不违背系统规则、模组事实、CANON 和玩家能动性的前提下自然使用，不为测试而诱导玩家。
6. **实战验证**：在 Session Log 中记录具体行动、GM 响应、玩家可观察结果、状态变化、用户反馈和副作用。
7. **复盘晋级**：只有跨不同场景/模组的证据支持，才更新通用 Skill 或稳定运行方法；同时检查是否损害规则、公平、节奏、连续性或其他既有能力。

### B. 实际跑团 → 微型箱庭

1. **发现真实问题**：优先从真实 Session 中定位影响体验或可靠性的具体缺陷，例如 NPC 变成线索机器、空间位置混乱、预案外行动处理僵硬、开场目标不清、风险告知不足或节奏失衡。
2. **剥离战役专属内容**：保留能力问题的结构，移除专属 NPC、模组秘密、角色经历、规则机制、CANON 和任何不应跨战役复用的信息。
3. **构造最小复现场景**：只加入重现该问题所必需的地点、人物、物件、目标和状态；不把玩家原来的行动改写成唯一正确答案。
4. **隔离变量**：一次优先观察 1–3 个相关问题。场景仍须是完整、可玩的游戏，不得把玩家当作测试工具。
5. **尝试修正并做变体**：改变人物、地点或行动方式，检查方法是否真正可迁移，而不是只记住某个场景的解法。
6. **回写通用能力**：把经箱庭复现和修正的方法作为候选能力或缺陷修复方案，再回到其他真实场景验证。

真实跑团是问题来源和最终验证场；箱庭是复现、拆解和练习环境。不得为了让箱庭容易测试而改写真实 Session 的历史。

## 3. 证据与晋级等级

| 等级 | 证据 | 可作出的结论 |
|---|---|---|
| E0 | 设计假设、预案、未运行场景 | 仅为待验证设计 |
| E1 | 单次箱庭或专项练习中的可观察表现 | 该方法在此样本中出现 |
| E2 | 多个不同箱庭/场景中重复出现，且至少检查过一种边界或反例 | 候选方法具有初步可迁移性 |
| E3 | 在真实 Session 中被实际使用，并有具体事件与玩家反馈/可观察结果 | 已获得实战证据，仍需观察稳定性 |
| E4 | 跨不同真实场景或模组反复有效，未引入严重副作用，且综合能力没有退化 | 可考虑纳入稳定通用规范 |

证据等级不是总分。任何硬性失败（规则系统错用、事实篡改、权限泄露、剥夺玩家决定权、严重连续性错误等）必须单独处理，不能被较高叙事表现抵消。

用户反馈、GM 自评、可观察行为、规则/模组依据和独立审查应分开记录。文档更新本身不构成能力成长证据。

## 4. 迁移时的边界

- **只迁移方法，不迁移内容。** 箱庭 NPC、地点、道具、任务、解决方案和事件结果均为 NON-CANON。
- **系统机制不跨域。** 箱庭实验规则不能自动进入 D&D、COC、Triangle Agency 或其他正式系统；正式团按当前 system_id 和规则版本执行。
- **玩家体验优先。** 不为观察某项能力而诱导、限制或惩罚玩家行动。
- **实战优先于训练假设。** 如果某个训练方法在真实 Session 中损害体验或与规则/模组冲突，应修订或撤回。
- **训练不得污染战役。** 从真实团抽取案例时必须做内容去标识化和专属信息剥离；不得把真实战役的隐藏事实带入其他场景。
- **保留反例。** 不只收集成功案例；记录方法在哪些条件下不适用、何时应该不调用。
