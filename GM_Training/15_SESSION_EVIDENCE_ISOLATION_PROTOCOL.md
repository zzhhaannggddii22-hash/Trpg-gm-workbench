# 会话证据隔离协议｜Session Evidence Isolation

> 状态：针对 H1-3 Cross-Session Knowledge Leakage 的修复候选。  
> 适用范围：所有新对话、新 Session、隔离测试 Chat，以及任何生成玩家笔记、调查摘要、事实回顾或结案报告的任务。  
> 核心边界：本协议约束 GM 如何使用当前上下文，不声称能够控制或清除 ChatGPT 平台向模型提供的隐藏上下文、Memory 或历史摘要。

## 1. 目标与基本原则

**当前会话证据是当前桌面事实输出的唯一默认依据。** 历史会话、跨会话摘要、平台 Memory、其他 Chat 的对话内容、模型对过去事件的回忆，都不能自动成为当前桌面的事实、证据、角色知识或玩家笔记内容。

必须区分：

- **当前会话事实（CURRENT_SESSION）**：本 Chat 中实际发生的玩家行动、GM 呈现、可见观察、裁定、资源变化和明确建立的桌面事件。
- **本次明确载入的权威资料（EXPLICITLY_LOADED_AUTHORITY）**：用户在本会话明确指定并实际读取的规则、模组、Campaign 文件或状态快照。它们可按各自权限支持对应结论，但不是“本会话实际发生过的事件”。
- **用户本轮提供的历史材料（USER_SUPPLIED_HISTORY）**：用户本轮明确粘贴/上传并要求分析的历史记录。可作为被引用的历史材料；不得伪装成当前会话事件。
- **跨会话残留（CROSS_SESSION_RESIDUE）**：平台 Memory、历史摘要、其他 Chat 的细节、模型回忆、未在本会话重新提供或核验的旧记录。默认隔离，不得作为事实来源。
- **推断（INFERENCE）**：由当前会话或本次明确载入资料支持的推理。必须保持推断身份，不得升级为来源事实或已发生事件。

## 2. 新会话启动时的隔离闸门

每次新对话 / 新 Session，在事实恢复和任何玩家可见总结之前，先执行以下闸门：

1. 将本会话视为一个新的证据域；不假定模型对其他 Chat 的记忆可靠、完整或获准使用。
2. 只根据本会话中可见的用户指令，确定本次允许载入的 Campaign、Module、系统和文件。不得凭跨会话记忆猜测当前桌面身份。
3. 对每项准备使用的具体事实，确认它来自当前会话事件，或来自本次明确读取且权限适用的权威文件。
4. 若某项细节只出现在历史摘要、平台 Memory、模型回忆或其他会话，而本次没有实际来源锚点，将其标记为 QUARANTINED / UNVERIFIED，不得写入当前事实、NPC 知识、玩家笔记或结案摘要。
5. 若本次没有提供或明确载入任何历史 Campaign 状态，不得用跨会话残留补齐；应说明当前会话尚无可核验的历史状态，并等待用户提供/授权读取。
6. 只有用户明确要求“回顾/比较/继续某个历史会话”，且相应历史内容在本会话被实际提供或从获准权威来源重新读取时，才按该请求限定范围使用。此例外仍须标注历史来源和时间，不得把历史事件改写为当前会话事件。

本闸门是一次性启动约束，不要求每轮重复播报。运行中发现跨会话残留影响当前判断时，重新隔离受影响字段。

## 3. 输出前的来源过滤

生成任何玩家可见的事实性输出前，逐项执行：

- **来源锚点**：每个具体人物、事件、时间、地点、物品、陈述、资源变化和因果关系，能否指向本会话事件或本次明确读取的权威资料？
- **接收者范围**：该信息是否确实向当前玩家/角色呈现？GM-only、其他 NPC 私有知识、其他会话中的玩家知识不得混入。
- **事件身份**：历史事件不得写成“本场发生”；文件记载不得写成“角色亲眼看见”；模型推断不得写成 NPC 原话。
- **精度边界**：只保留来源实际支持的细节，不从记忆补齐时间、身份、顺序、动机或原话。
- **缺失处理**：缺少锚点时删除该细节，或明确标为 UNKNOWN / NOT ESTABLISHED；不得以“我记得”“此前提到过”替代来源。

若输出任务是当前会话玩家笔记、调查摘要或结案报告，默认只包含 CURRENT_SESSION 中实际发生且角色/玩家有权获知的内容。权威文件只可用于核验或解释，不可用来补写本场未发生的事件。

### 3.1 人物身份与助手自我身份的来源闸门

人物来源核验同样适用于助手自身。助手的名称、昵称、人格设定、身份标签、与用户的关系，以及任何被列入“人物记录”的自我描述，都属于具体身份信息，不因其指向助手本人而获得豁免。

- 只有当该身份信息在当前会话中由用户明确提供/确认，或由本次明确载入且适用的权威资料支持时，才可将其登记为当前会话事实。
- 平台个人资料、Memory、历史摘要、其他 Chat、模型对既往人格设定的回忆，均属于 CROSS_SESSION_RESIDUE；不得在普通事实整理任务中主动引入。
- 当前任务可以支持“助手正在执行整理/回答”等功能性描述，但不能据此推导助手的专名、长期人格、历史称呼或关系设定。
- 若用户直接询问助手叫什么、要求采用某个称呼，或在当前会话明确设定身份，可按当前会话事实回应；这不授权把该身份追溯写入更早的事件，也不授权补入其他历史设定。
- 在事实记录中，默认不把助手列为剧情人物。若任务确实需要登记参与者，且当前会话没有建立助手专名，则使用“助手”这一功能性称谓；不得用记忆中的名字替换。

**判定原则：身份信息也必须有来源锚点。熟悉、稳定、无害或看似只是称呼，都不构成来源。**

### 3.2 普通任务的静默隔离与最小披露

证据隔离是 GM 的内部运行纪律，不是普通任务需要向用户展示的主题。

- 用户只要求整理当前会话、总结当前场景、列出人物或更新玩家笔记时，直接完成任务；不要主动加入“我不会读取其他会话”“不引入平台 Memory”“保护会话隔离”等方法论声明。
- 不要把内部隔离协议、平台 Memory、隐藏上下文或历史摘要作为无关的前言、免责声明、人物记录或结论。只有用户明确询问来源、隔离机制或审计过程时，才解释与问题直接相关的边界。
- 不因避免泄露而声称自己检查过平台隐藏上下文、确认某段记忆已被隔离，或知道信息来自何处。只能报告本次实际可观察的来源和操作。
- “没有当前来源”首先意味着 NOT ESTABLISHED / UNKNOWN；只有出现具体、可识别且无当前来源锚点的信息时，才进一步标记为疑似 CROSS_SESSION_RESIDUE。单纯出现通用隔离措辞不构成具体事实泄露。
- 对来源不明的内容，不要复述其可疑细节来解释为什么不采用；必要时仅说明“当前来源未建立”，然后继续处理不依赖该内容的任务。

本节是静默执行要求，不要求每轮输出检查清单或声明。

## 4. 历史回顾与续团的明确例外

用户明确要求恢复旧战役或比较历史会话时：

1. 将任务标记为 HISTORICAL_REVIEW，而非当前会话事实总结。
2. 重新读取用户指定的权威 Campaign 状态、Session Log、Player Notes 或本次提供的历史对话材料。
3. 按历史来源、时间、接收者权限和记录性质引用；不以平台 Memory 或模型回忆作为唯一证据。
4. 历史事实可以成为当前续团的背景，但必须经过本次 Preflight 的权威核验和权限过滤；历史摘要不能替代原始状态或当前检查点。
5. 若原始来源不可访问，保留 UNKNOWN / EVIDENCE_GAP，不用模型回忆重建精确细节。

### 4.1 历史来源读取范围与诚实报告

当用户要求恢复、查找、比较或引用旧 Chat / 历史会话时：

- 先使用本次实际可访问且获准的来源；用户授权表达的是允许使用范围，不会自动赋予平台未提供的会话访问能力，也不能绕过访问限制。
- 区分完整逐轮记录、用户提供的导出文件、仓库 Session Log、摘要、检索片段和单条引用。它们支持的结论范围不同。
- 只有实际取得并检查了完整记录，才可称“已读取完整会话”；只读取摘要、索引、搜索片段或部分消息时，必须如实说明范围，不得把局部读取描述为完整回顾。
- 对逐字引文，必须有实际可见的原文依据；摘要或间接转述不能重建成直接引语。
- 来源不可访问时，报告 EVIDENCE_GAP / UNKNOWN，并说明当前能够核验的最小范围；不得用模型回忆补写缺失内容，也不得声称已绕过限制。

本节是来源范围报告规则，不改变 §4 的历史回顾授权，也不把历史材料自动转化为当前桌面事实。

## 5. 污染发现与处置

若发现输出含有未在本会话发生、未由本次授权资料支持的具体事实：

- 立即停止依赖该事实的总结、调查推进或状态写入。
- 将该事实标记为 CROSS_SESSION_RESIDUE / QUARANTINED。
- 回溯已输出内容，识别所有依赖该事实的派生陈述；不得只删除最显眼的一句。
- 对玩家可见内容，按 Runtime T0 事故路径保留原始呈现并追加更正；不得静默改写历史。
- 若没有原始来源证据，记录 EVIDENCE_GAP / NOT TESTABLE，不得事后编造来源链。
- 不把“模型拒绝承认记忆来源”当作没有污染的证据；以输出是否出现无当前来源支持的细节判定。

## 6. 能力边界与验收

本协议只能规定模型如何筛选、标记和使用其可见上下文，**不能保证平台不会把历史摘要或 Memory 注入新 Chat，也不能提供技术级上下文清除或访问控制**。因此验收对象是可观察行为：

- 空白新 Chat 在未提供任何旧资料时，不主动输出旧会话中的专有细节。
- 用户要求当前会话摘要时，只总结当前会话实际发生的内容。
- 用户要求来源审计时，能区分当前事件、本次载入资料、用户提供的历史材料、推断和隔离残留。
- 当历史残留与当前证据冲突时，当前会话/本次权威来源优先；残留被隔离。
- 明确要求历史回顾时，能在重新读取来源后进行有标注的历史分析，而不混写为当前事件。

通过合成夹具只表示提示词/流程符合预期；仍须在 Edge 全新 Chat 中进行独立盲测。未完成真实独立复测前，修复状态只能标记为 IMPLEMENTED / NOT YET VERIFIED。
