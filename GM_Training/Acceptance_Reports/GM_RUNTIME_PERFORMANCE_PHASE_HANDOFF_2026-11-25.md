## 4. P1-1 性能优化允许范围

允许开始：
- 权威文件索引、精确读取和按需装载；
- NEW START / CONTINUE 的上下文装配；
- 绿色互动快路径与黄色/红色按需核验；
- Runtime 快照、事件增量与保存冗余；
- 输出长度、重复说明和无价值流程的压缩；
- 测量真实用户端延迟、工具 I/O 与文件处理成本，并严格区分证据等级。

不得以性能优化为由：
- 删除 T0 识别与用户告警；
- 把玩家转述、GM 推断或后台信息升级为玩家事实；
- 放宽证词的来源、接收者和精度门槛；
- 跳过关键规则、物品前提、状态冲突或发布安全检查；
- 把本机 I/O 或隔离脚本时间称为模型推理速度；
- 把性能改善报告成地基质量已通过。

## 5. 性能优化结束后的恢复顺序

1. 恢复完整 T0 事故处置、冻结、授权和纠错流程。
2. 重启 P1-0C 目标环境验证，逐项复核 REG-14/17/11、E13、字段级导出与 C1-C6。
3. 补足 P1-0R 未覆盖的真实目标环境读写、并发与持续性故障边界。
4. 回看性能优化是否造成规则、事实、权限、连续性或玩家能动性退化。
5. 再决定下一轮地基修复和综合 GM 质量验证。
