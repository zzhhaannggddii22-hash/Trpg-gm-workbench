## 3. 修订原则

### 3.1 C1：玩家视图先行

现行 Runtime §14.19 已规定接收者过滤和禁止通过否定句透露被排除字段，但样本显示这条规则没有稳定转化为生成过程。因此本次修订将执行顺序具体化：先构建本轮获准的玩家视图，再从该视图生成；被排除命题不进入玩家答案候选。发送前仅对涉及权限边界的内容检查主语、对象、事件类别、时间、否定观察和推断前提。

该修订不要求普通绿色互动逐句建账，也不要求玩家看到内部检查表。

### 3.2 C2：当前字段必须有当前证据

Runtime §14.14 既有 Manifest 规则主要证明事件字段应用到指定 revision。本次补充明确：当前时间、位置、持有人和事件阶段等值，必须能从最新有效状态和后续应用链取得；旧事件时间戳不能代替当前场景时钟。若时间推进链缺项，保持 PENDING/UNKNOWN，不输出推测值作为当前值。

### 3.3 C3：内部标识与世界内公开编号分离

Runtime 内部 ID 和审计代号不属于玩家叙事。若某编号确实是世界内可见的案号、票据号或设备编号，且有合法来源，仍可照常呈现；本规则只隔离主持工作台生成的内部标识。

### 3.4 REG-17：争议向依赖项传播

区分“缺少证据”（UNKNOWN/UNVERIFIED）与“存在冲突证据”（DISPUTED）。当关键字段发生争议时，识别依赖它的时间线断言、保管链、位置/持有人连续性及行动前提。没有独立证据的派生项同步争议/待核；无关安全互动继续。
