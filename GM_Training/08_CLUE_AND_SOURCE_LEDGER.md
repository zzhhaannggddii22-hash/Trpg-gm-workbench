# 调查线索与信息来源账本规范

> 本文件定义 GM 内部的调查信息记录方式，不是玩家任务清单，不是线索必须依次解锁的流程，也不要求每条信息都只能有一个来源。

## 1. 基本模型：信息与来源分离

每条信息有独立的“信息 ID”；每个提供、确认或解释该信息的渠道是一个“来源记录”。同一信息可以关联多个来源；同一来源也可以在不同时间提供多条信息。

### 信息记录字段

| 字段 | 含义 |
|---|---|
| 信息 ID | 稳定编号，避免因措辞变化重复建档 |
| 信息内容 | 玩家实际获知的具体事实，不混入 GM 隐藏真相 |
| 玩家认知状态 | 未知 / 已知 / 部分理解 / 有争议 / 已纠正 |
| 首次获得时间 | 桌面时间或 Session |
| 信息性质 | 直接观察 / NPC 陈述 / 文件记录 / 推断 / 规则或机构告知 |
| 已知细节 | 玩家真正掌握的细节与限制 |
| 可支持的行动 | 玩家可据此采取什么行动（可选） |

### 来源记录字段

| 字段 | 含义 |
|---|---|
| 来源 ID | 人物、地点、文件、设备、机构或其他渠道 |
| 规范名称/别名 | 归并同一人物或地点的不同称呼 |
| 与信息的关系 | 亲历 / 目击 / 专业确认 / 转述 / 个人判断 / 记录 |
| 首次提供时间 | 来源何时向玩家提供该信息 |
| 已经问过什么 | 玩家问过的问题和来源已经回答的内容 |
| 尚可能知道什么 | 仅根据人物身份、经历、参与事件与实际机会判断；未知则留空 |
| 新增信息 | 本次接触比玩家已有信息多出的部分 |
| 可靠性/局限 | 记忆、偏见、利益、误解、证据质量等 |

## 2. 重复信息的正确处理

同一信息可以有多个来源。这不是无效重复，而是世界信息交叉、独立确认、传闻扩散或不同视角的表现。

- 玩家已经知道某装置可以自动运行，后来技术人员也说到这一点：正常呈现。若技术人员有专业解释或额外细节，再补充新增部分。
- 玩家已经从一名联系人获得 A 信息，之后另一名知情者也提到 A：可以再次获得，作为第二个来源或交叉印证。
- 玩家已经从某来源获得 A，之后再次问同一来源同一个问题：对方可以再次回答 A。按玩家这次询问的语境自然回应即可；不必重新完整描写首次发现。
- 玩家带着新问题再次找该来源：NPC 根据其知识、经历、性格、记忆和当前情况回答，可能给出新信息、补充细节、重复旧信息、表达不同观点，或确实不知道。
- 如果来源没有新信息，不为了奖励探索而临时编造；自然说明对方确实没有更多可说的内容。

## 3. 重复呈现的篇幅规则

- 首次获得：正常展开发现过程、具体信息、重要细节和当时情境。
- 不同来源再次确认：简短呈现，说明该来源也确认/提及了已知信息；只展开其独立证据、新视角或专业解释。
- 同一来源重复回答：可以简短复述，避免把玩家再次询问演成系统报错或拒绝；除非语境、态度或信息状态有变化，不重复完整段落。
- 出现矛盾：清楚呈现不同来源说法的差异，不擅自替玩家判定哪一方正确。
- 信息被纠正：保留纠正轨迹，更新玩家当前认知；必要时标注此前误解从何而来。

## 4. 不把“已知”误作“已探索完毕”

信息 ID 已经进入玩家已知索引，只表示角色掌握了这条信息，不表示：
- 某 NPC 已没有其他可说内容；
- 某地点已不可能有新发现；
- 相关主题永远不会产生新情况；
- 其他来源不能再次提供相同事实；
- 玩家不能重新询问、验证或质疑该信息。

“来源已提供过某条信息”只用于避免 GM 在没有玩家再次询问、没有新事件、没有新细节时，反复把它当作首次发现主动交付。它不是封锁来源的标记。

## 5. GM 输出时的判断顺序

每次准备呈现调查结果时，内部检查：
1. 这是新信息、已知信息的再次确认、同一来源的重复回答、信息补充、矛盾，还是纠正？
2. 玩家现在是通过什么行动/问题得到它？
3. 这个来源是否合理知道这件事？其知识来自哪里？
4. 本次新增了哪些细节、证据、解释或可信度？
5. 需要向玩家呈现多少篇幅？重复信息通常简短，增量信息重点展开。
6. 玩家角色是否已经知道该信息？不要把 GM-only 真相或玩家听到但角色没听到的内容混进角色认知。

## 6. 反例与防误用

- 不要要求玩家每次调查一个地点都必须获得新线索。
- 不要把所有来源都设计成一人发一条唯一线索的自动售货机。
- 不要把不同来源的相同陈述简单合并成“重复无效”；来源独立性本身可能有价值。
- 不要因线索已知就禁止 NPC 再次谈论它。
- 不要因玩家再次询问而重复整段说明；简短回答即可。
- 不要把玩家尚未理解的推断自动登记为已知事实。
- 不要把 GM 私有线索索引直接作为玩家可见的调查清单。

## 7. 与战役状态和 Session Log 的关系

- GM-only 线索索引保存完整信息—来源关系。
- 玩家侧便笺只记录角色已经获知且后续可能需要记住的信息，不记录隐藏来源、秘密解释或尚未发现的线索。
- Session Log 记录本场新增的信息、再次确认的信息、来源变化、纠正和未解决分歧；不必每次把完整索引抄一遍。
- 结束 Session 时更新信息索引，并检查是否有 NPC 因新事件而获得/失去某些知识。
- 发现需更正的记录时追加更正事件，保留原呈现、玩家选择和实际来源。T0 统一走 [Runtime §14.1](./07_RUNTIME_CONTROL_PROTOCOL.md#141-唯一事故处置路径)。玩家投影依 Runtime §14.8、§14.12、§14.17，投影审计留在独立 GM 通道。

## 8. 验证标准

成功运行时应观察到：不同来源可以自然确认同一事实；NPC 的知识范围与经历一致；同一来源可以在新问题/新事件下继续提供信息；重复信息简短、不冗长；没有为了填充探索而制造新线索；玩家能自行组合信息，GM 不替玩家总结唯一答案。

## 9. 关键命题的证据根与认知传播（2026-11-24）

本节只用于会影响调查方向、裁定、任务状态、玩家选择或长期 CANON 的重要命题，不要求为普通对话逐句建档。

### 9.1 命题记录
| 字段 | 用途 |
|---|---|
| claim_id | 稳定命题 ID；措辞修订不另造事实 |
| proposition | 可被支持、反驳或保持未知的具体命题 |
| nature | SOURCE / TABLE CANON / GM ADAPTATION / GM INFERENCE / UNKNOWN |
| source_ref | 直接来源事件、原文定位或证据 ID |
| root_claim_or_event | 独立证据根；转述/复制沿用原根 |
| status | SUPPORTED / DISPUTED / UNVERIFIED / REFUTED / UNKNOWN |
| scope | 适用 Campaign、Module、Session 与时间范围 |

### 9.2 陈述与认知事件
NPC 陈述独立记录 speaker、statement_event、recipient、knowledge_basis、disclosure_condition。PLAYER-KNOWN 记录玩家角色实际接收的事件、方式与可知限制；NPC KNOWLEDGE 记录该 NPC 实际亲历、观察、可靠/不可靠转述、推断、误解、隐瞒或谎言。GM 掌握的客观信息不自动成为 NPC 或玩家知识。

#### 证词呈现锚点与精度字段（P0）

当重要信息被记录为 NPC 陈述、目击证词、文件内容或玩家已知线索时，复用现有 claim/event/source 结构，至少能回答：

| 字段 | 要求 |
|---|---|
| claim_id / proposition | 本次记录的具体命题；不要把多项细节压成一个模糊句子 |
| source_kind | NPC_STATEMENT / FILE_RECORD / DIRECT_OBSERVATION / PLAYER_CLAIM / GM_INFERENCE / OTHER |
| speaker_or_source | 实际说话者或资料来源；PLAYER_CLAIM 不得伪装成其所转述的来源 |
| presented_event_id | 来源内容实际呈现给当前接收者的事件 ID；无对应事件时为 UNKNOWN |
| recipient_scope | 实际听见/看见该内容的接收者 |
| presented_content_ref | 原话、忠实摘要或精确消息片段的定位 |
| supported_details | 该呈现实际支持的时间、地点、人物、动作、顺序、数量及否定信息 |
| precision_limit | 原始表达的精度与限制，例如“约九点”“20:50 前”“未看清脸” |
| knowledge_basis | 来源为何知道这件事；不清楚则 UNKNOWN |
| status / certainty | SUPPORTED、UNVERIFIED、DISPUTED 等状态及对应确定度 |

执行边界：
- 玩家说“某 NPC 告诉过我 X”，若没有该 NPC 的实际呈现事件，只能登记为 PLAYER_CLAIM / UNVERIFIED，不能创建 NPC_STATEMENT。
- 有呈现事件也只能引用其中实际出现的内容。原话为“约九点”，不得登记成 21:08；原话为“20:50 前离开”，不得补成 20:47。
- 不能从同一事件的一个细节推导未说出的其他细节；“没有看见进入或离开”不等于“确认没有人进入或离开”，除非原话和观察条件确实支持该结论。
- NPC 陈述的呈现只证明 NPC 说过，不证明命题客观为真；真实性仍由其 knowledge_basis、独立来源和证据根决定。
- 当前轮 NPC 真正披露的新信息可正常建立新事件并进入玩家知识；不得因核验机制而阻断合法访谈或正常叙事。
- 若呈现事件缺失，先查对话/事件记录；仍缺失时保留 UNKNOWN / DISPUTED，不从 GM-only Prep、隐藏时间线或其他 NPC 的知识补写。

#### 分次披露与字段级增量（P1）

同一命题可以由同一来源在多个呈现事件中逐步披露。继续复用本节 claim/event/source 结构，不另建第二套玩家知识台账：
- 对重要命题拆分可独立变化的细节字段；每个字段记录其实际支持它的 presented_event_id、recipient_scope、presented_content_ref 与 precision_limit。一个事件未支持的字段保持 UNKNOWN / UNVERIFIED。
- 后续呈现只增加或修订该事件实际支持的字段。不得因时间字段得到精确补充，就连带补入人物身份、地点或路线；不得将后续披露回填为早先事件的原话。
- 汇总多个事件时可以合并兼容的已披露字段，但必须保留各字段的来源与披露顺序。若来源之间冲突，分别保留并标记 DISPUTED，不用 GM-only 真相静默裁决。
- 旧 Player Notes、摘要或玩家重新粘贴的记录是既有玩家投影，不是独立证据根。它们可以帮助定位旧信息；只有回溯到实际呈现事件，才能确认具体来源和内容范围。缺少锚点时保留当前可确认状态，不从后台补全。

### 9.3 独立证据与跨文件投影
- 多人重复同一说法、同一证人转述、同源照片/文件或多个文件复制同一摘要，仍只有一个证据根；除非证明来源独立，否则不提升客观可信度。
- 多个独立来源分别记录，不将独立证据压成一个模糊的已确认。
- Runtime、Player Notes、NPC Ledger 和 Handoff 是各自权限范围内的投影，引用 claim/event ID，不自行创造新的证据根。
- 历史重逢时，名称索引定位候选和比对理由，沿候选回查对应事件、时间和实际呈现。身份可暂定；只有有权确认的事件或证据支持时才合并身份记录。后续确认或改判追加当前事件，只修订有证据的字段，旧证词的归属、推断时点及当时信念造成的已发生后果保留。
- 后台更正不自动改写角色认知；角色是否获知更正，必须有实际披露事件。
- GM 先前生成的叙述本身不是独立来源或证据根，只能证明该内容曾被呈现。后续要依赖其中的事实，必须回溯到实际来源，或指向有依据且确实发生的桌面事件；不得仅以“上一轮 GM 已经这样说过”支持下一轮调查、NPC 知识或状态变化。被允许的 GM_ADAPTATION 也须保留其明确性质，不能借重复叙述升级成 SOURCE。
- 纠错采用追加更正事件，保留原说法、传播链、已呈现内容和受影响分支。

### 9.4 最小化原则
普通闲谈、无后续影响的细节和不改变认知的重复台词无需逐条编码。只有当信息可能影响行动、线索可信度、人物判断、任务目标或持续状态时才建立稳定 ID。

### 9.5 客观命题、信息获取与主体认知分离（NPC Knowledge Projection）

本节明确既有字段的语义，不另建 NPC Memory Database，也不改变 Claim / Source Ledger 的权威归属。

同一条信息在运行中至少可能涉及五个不同对象，不能合并成一个“知道/不知道”状态：

1. **客观命题（Claim）**：世界中某件事是否成立，以及现有证据支持到什么程度。
2. **信息获取（Acquisition）**：某个主体实际通过什么事件接触了哪些内容。
3. **主体认知态度（Epistemic Attitude）**：该主体目前如何判断命题。
4. **陈述（Statement）**：主体实际上向谁说了什么。
5. **行动（Action）**：主体基于自己的认知、目标与处境采取了什么行动。

#### 状态归属

- Claim 的 `status` 只描述命题的客观证据状态：SUPPORTED / DISPUTED / UNVERIFIED / REFUTED / UNKNOWN。不得用它表示 NPC 或玩家是否相信。
- Acquisition 只证明主体接触了相应内容。OBSERVED 证明观察到的现象，不自动证明主体理解了现象的原因；HEARD / READ / REPORTED 也不自动证明内容真实。
- 主体认知态度按需使用 BELIEVES / SUSPECTS / DOUBTS / REJECTS / UNSETTLED。它描述主体当前判断，不改变 Claim 状态。
- 严格意义上的 KNOWS 仅在命题为真且主体具有足够可靠的认知依据时使用。日常运行无需强迫每条信息都标注 KNOWS；证据不足时记录其相信、怀疑或接触状态即可。
- Statement 记录实际说出的内容及接收者。说出 P 只证明主体作出了该陈述，不证明主体相信 P，更不证明 P 为真。
- Action 记录真实发生的行为及其结果。NPC 相信 P 可以解释其为何行动，但不能单独证明 P，也不能保证行动成功。

证词通常包含至少两个可区分的命题：`S 说过 P` 与 `P`。接收者可以确信 S 说过 P，却怀疑 P 本身；说话者也可能相信 P、怀疑 P，或明知 P 为假仍故意陈述。不得将这几种状态压成一个 certainty。

#### 最小记录与复用

优先复用本文件已有的 `claim_id`、`presented_event_id`、`recipient_scope`、`supported_details`、`precision_limit`、`knowledge_basis` 与 `disclosure_condition`。只有当某主体的认知态度会影响其后续行动、证词、关系或持续状态时，才额外记录该态度及其依据/更新时间；不为普通闲谈逐句建立认知记录。

### 9.6 认知形成、推理与修订

NPC 的判断只能基于其实际接触的信息、可用经验/专业能力、当时注意力和合理推理能力。GM 掌握的隐藏事实、其他 NPC 的私有知识、玩家未向其披露的内容，不得作为 NPC 推理前提。

- **直接观察**：只支持观察条件实际允许看到/听到的细节；身份、原因、精确时间或未观察到的事件不得自动补齐。
- **转述/证词**：主体首先获得“某来源作出了该陈述”的信息；是否相信内容，取决于其对该来源在相关领域/情境中的判断及其他依据。
- **文件/记录**：主体可以知道文件写了什么；文件是否真实、完整、最新或被篡改，需要另行判断。
- **推理**：推断强度不得超过前提、专业能力和当时可用信息。区分普通推断、专业判断与未经支持的猜测；推断不自动成为独立证据根或客观事实。
- **矛盾信息**：保留旧判断与新依据。主体可以怀疑来源、怀疑自己的记忆、暂缓判断、接受部分细节或继续坚持；不得因为 GM 知道真相就自动选择正确答案。
- **信任**：不得用一个全局 trust_score 代替判断。必要时按对象、领域和情境描述信任依据；例如信任某人的专业判断，不代表信任其时间记忆或动机。

认知修订只更新主体当前判断，并保留形成与变化的事件轨迹。它不自动更正客观 Claim，也不抹除此前真实发生的行动与后果。后台更正只有经实际披露/观察/核验事件到达主体后，才可能改变其认知。

### 9.7 认知、陈述、行动与世界后果

NPC 的错误信念、误解、记忆偏差、隐瞒和欺骗均可作为正常虚构内容。只要其来源、行为和后果符合已建立世界、人物能力与因果条件，就不属于 GM 系统事故。

运行时遵守以下分界：

- NPC 的认知可以影响其目标选择、风险判断、陈述和行动。
- NPC 的陈述本身是一个真实发生的桌面事件；其内容仍须与客观命题分开。
- 行动能否完成及其客观后果，按世界状态、行动条件、规则和实际结算决定，不按 NPC 对结果的相信程度决定。
- 错误认知导致重要行动时，记录足以解释后续状态的认知依据、行动事件与结果；不要求记录完整内心推理。
- 后来认知被纠正，不会自动撤销已发生的交还物品、资源消耗、关系变化、时间经过或其他真实后果。只有新的实际行动或正式回滚依据才能改变这些状态。

### 9.8 记忆可用性与遗忘边界

知识获取事件与当前回忆能力不是同一回事。主体曾接触某信息，不代表任何时刻都能准确检索、复述或保持原有确信。

- 区分 **遗忘/记忆衰退**、**暂时无法回忆**、**记得内容但忘记来源**、**仍记得但不再相信**、**收到新信息后修订判断**。不得把这些情况统一写成“已不知道”。
- 回忆失败不证明原信息从未获取；重新接触信息可以形成新的获取/确认事件，但不能因此制造新的独立证据根。
- 遗忘或回忆失败不删除 Session/Event Log、来源记录、证据根或已发生后果。
- 不按固定时间自动让 NPC 忘记信息。只有时间跨度、信息重要性、重复接触、人物特征或具体情境确实影响记忆时，才在重要 NPC 的当前认知视图中反映。
- L0/L1 通常只需维护会影响当前场景的知识边界；L2/L3 才在跨场景连续性确有需要时维护记忆可用性。不得为所有 NPC 建立记忆衰减表。

### 9.9 NPC Knowledge Projection 的职责与运行边界

NPC Knowledge Projection 是由人物档案、已发生的信息获取/认知变化事件和当前状态派生出的 NPC 视角；它不是事实权威库，不是独立证据账本，也不是独立数据库。

在 NPC 回答或行动会影响调查、风险、关系或持续状态时，GM 只需快速核对：
1. 该 NPC 实际接触过哪些相关信息，来源和精度是什么？
2. 当前相信、怀疑、拒绝或尚未判断什么？
3. 其专业能力、注意力、记忆和当前处境允许其作出什么推断？
4. 它愿意披露什么，或出于什么动机隐瞒/歪曲？
5. 本次陈述/行动会产生什么真实后果，是否需要更新状态？

这是一项视角约束，不要求向玩家展示内部清单，也不要求每轮输出结构化状态表。当前 ChatGPT 环境中的 Projection 只是上下文组织与运行约束，不构成独立进程或绝对安全隔离；必须继续依赖实际来源、接收者边界和输出检查。

### 9.10 访谈顺序、提示来源与引文精度（P0/P1）

本节用于重要访谈、证词核验和后续调查笔记；不要求普通闲谈逐句编码，也不创建第二套事件或证据数据库。实际事件仍写入 Session Log，命题与来源仍复用本文件 §9.1–9.3 的字段。

#### 行动顺序与提示上下文

- 重要访谈应保留实际发生的互动顺序：玩家提出问题/采取行动 → NPC 回答 → 玩家追问/澄清 → NPC 后续回答 → 玩家结束/离开。不得省略实际发生且影响回答含义的追问，也不得补入没有发生的提问、回答或收尾。
- 玩家行动与问题是行动记录，不是 NPC 陈述。若无法确认玩家问题逐字措辞，使用间接叙述；不得为了让记录更完整而重构成带引号的玩家原话。
- 当玩家在 NPC 回答前提供了某个具体命题、事件细节或预设答案，且该提示可能影响 NPC 回答时，重要记录应引用该提示的事件/来源，并标记为“受提示影响 / 非独立印证”。NPC 的回答仍可作为本次实际发生的 NPC_STATEMENT 保存，但不得把它当成独立于玩家提示的第二证据根。
- 开放或中性提问不自动构成来源污染；只有存在具体的先行提示、诱导前提或同源转述时，才按实际情况标记 POTENTIALLY_INFLUENCED / NOT_INDEPENDENT。不能因为玩家问到了某主题，就一概认定 NPC 回答无效。
- NPC 回答的来源独立性与回答是否真实是两个问题：受提示影响不等于 NPC 撒谎，也不抹除其确实说过的话；它只限制该回答作为独立佐证的资格。

重要访谈按需保留以下最小关联：`prompt_context_ref`（此前玩家提示/转述的事件引用）、`elicitation_context`（OPEN / NEUTRAL / LEADING / PLAYER_SUPPLIED_CLAIM / UNKNOWN）、`independence_status`（INDEPENDENT / POTENTIALLY_INFLUENCED / NOT_INDEPENDENT / NOT_ASSESSED）。仅在提示上下文会影响证据评价时填写；普通对话不强制增加字段。

#### 直接引语与整理性叙述

- **VERBATIM_CONFIRMED：** 当前可访问的逐字对话记录/录音转写明确支持该措辞，方可使用直接引号。允许修正纯排版错误，但不得改写语义、确定程度或细节。
- **FAITHFUL_PARAPHRASE：** 只能确认回答含义、要点或顺序，不能确认逐字措辞时，使用间接引述或明确标注“概括/整理”，不得保留为 NPC 原话。
- **RECONSTRUCTED_UNVERIFIED：** 依据记忆、摘要或多个片段拼出的近似文本，不得作为直接引语发布；需要留存时应标注无法逐字核实，并改为最小范围的间接叙述。
- 不得把玩家的提问、GM 的衔接说明、整理性概括或从多次回答合并出的内容放进 NPC 引号。
- 不得为了让 NPC 显得更明确、更配合或更有戏剧性，删掉“好像”“不确定”“记不清”“不能保证”等限制词；不得将概括性语句包装成完整原话。
- 一段回答包含多个可分离的确定程度或事实细节时，应保留其原有边界；无法确认某个细节是否说过，就不把它放进引号，也不从其他会话或 GM-only 资料补全。

#### 摘要与回顾

阶段摘要可以压缩重复内容，但必须保留关键行动顺序、NPC 回答的确定程度、提示污染和引文精度。摘要不得把后续访谈中新披露的内容回填成此前已取得的证词；不得把“玩家曾这样说”改写成“NPC 曾这样说”；不得把 NPC 陈述本身升级为客观命题已获证实。

上述标准与 Runtime §14.19 的玩家已知信息准入门槛共同适用：来源/引文审计不能放宽披露权限，披露权限也不能替代原话精度核验。



## 10. T0 原始污染证据与传播链（P0 第三轮补充）

本节处理的是 **GM 运行/记录层的事实污染**，不是 NPC 或玩家在虚构世界中犯错的通用处罚机制。

**不自动触发 T0 的正常虚构情况：** NPC 有依据地相信错误消息、误记细节、作出错误推断、隐瞒事实、故意撒谎，或玩家角色形成错误判断。这些是正常的信息与人物事件；按其实际来源、陈述、行动和后果记录即可。NPC 说出错误内容，仍可能是一次真实的 NPC_STATEMENT 事件，但其内容不得因此升级为客观 Claim。

**可能触发 T0 的 GM 运行错误：** GM 无依据地编造受保护的既有事实/来源/经历并将其当成权威事实；把 NPC 的主观信念或陈述写入客观 Claim；把同源转述当作独立证据；把未发生的传播/观察登记为已发生；或让错误命题污染玩家选择、调查路线、Runtime State、任务状态或其他后续状态。是否触发 T0 取决于 GM 层错误及其影响，不取决于虚构人物是否说错话。

经允许且明确标记为 GM_ADAPTATION 的即兴内容，不因其“此前未在模组中出现”自动构成 T0；但不得越权改写模组核心事实、规则、已确认 CANON 或玩家已依赖的既有事实。发现越界时按实际影响进入纠错/事故流程。

当错误命题可能影响调查方向、规则裁定、任务状态或玩家选择时，不能只保存审计结论。每个污染入口至少保存以下原始证据，便于独立复盘：

| 字段 | 含义 |
|---|---|
| incident_id | 稳定事故 ID |
| entry_path | LIVE_DISCOVERY / STRUCTURAL_IMPROVISATION / POST_SESSION_AUDIT |
| earliest_bad_event_id | 最早出现错误的事件 |
| original_bad_record_ref | 最初坏记录的原始定位；保留写入前原文 |
| original_bad_claim | 当时实际写入/表达的错误命题，逐字或精确字段值 |
| source_statement_ref | 触发该错误的 NPC 陈述、文件、规则或模型生成内容 |
| field_path | 错误进入的具体字段路径 |
| field_scope | GM_ONLY / PLAYER_VISIBLE / RECIPIENT_SCOPED |
| before_state_ref / after_state_ref | 写入前后状态快照或差异 |
| detection_event_id | 发现并触发审计的事件 |
| trigger_basis | 为什么此处触发 T0 |
| derived_event_ids | 由错误命题派生的事件 ID |
| derived_claim_ids | 由错误命题派生的命题 ID |
| propagation_edges | source_event → derived_event/claim 的有向关系 |
| player_presentation_refs | 已向玩家呈现的相关内容 |
| containment_status | OPEN / CONTAINED / DISPUTED / RESOLVED |
| resolution_ref | 追加更正或解决事件 |

执行要求：
- 三条入口路径分别建立事故记录，不将不同路径合并成一个泛化案例。
- 保存原始坏命题、原始字段、最早写入位置和派生链；仅保存最终结论、摘要或“发生过偏移”不算完整证据。
- 原始记录只追加引用，不静默修订；纠正通过新事件完成，并保留玩家实际看到过的内容。
- 找不到原始写入证据时，标记 EVIDENCE_GAP / NOT TESTABLE，不得用事后重构冒充原始记录。
