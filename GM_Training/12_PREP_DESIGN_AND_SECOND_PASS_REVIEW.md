# 模组备团设计与二次审核规范

> 本文件是 GM-only 的 Prep QA（备团质量审核）规范，供备团阶段按需调用。Prep QA 是可选流程：如执行，必须在该模组第一次 Session Preflight 之前完成；第一次 Preflight 一旦执行，该模组的 Prep QA 窗口即关闭，之后不得补做或重开。Preflight 不依赖 Prep QA，跳过 QA 不影响新对话的资源加载与开团就绪检查。

## 1. 适用范围与原则

适用于官方模组、社区模组及原创模组。对原作已有明确结构的内容，先忠实理解，再决定是否适配；对 GM 扩写内容，必须检查其因果、信息价值和后续影响。

备团不是写死玩家路线，而是提前建立足以支持自由行动的世界结构。玩家可以偏离预设路线，但 GM 不应因为没有准备偏离路线就临时制造无效调查或不自洽的解释。

备团成果的分类、运行索引、Prep QA 与最终 Preflight 的衔接、现场按需调用和效率要求，统一见[备团—带团联动与运行效率规范](./13_PREP_TO_RUNTIME_HANDOFF_STANDARD.md)。本文件负责备团设计质量与第二轮审核，不重复定义运行交接流程。

## 2. 重要调查链的预设计

对预计会占用明显游戏时间、跨越多个地点/人物/行动节点，或被模组明确突出为重要方向的调查线，备团时建立调查链简表。

每条调查链至少记录：

| 字段 | 必须回答的问题 |
|---|---|
| 调查目标 | 玩家最终想查明什么？ |
| 起始依据 | 玩家为什么会追查它？最初可见的事实是什么？ |
| 节点与转移 | 可能经过哪些地点、人物、物证或事件？节点之间如何合理连接？ |
| 节点功能 | 每个重要节点提供什么：独特线索、独特遭遇、交叉验证、有效证伪、资源/盟友/机会或局势变化？ |
| 预期回报 | 这条线对主目标、人物关系或后续局势有什么贡献？ |
| 结束条件 | 找到目标、确认遭遇、完成验证、排除假设或达到其他什么条件时，调查可以结束？ |
| 中断与失败 | 玩家放弃、错过、检定失败或目标不可达时，世界会发生什么？哪些信息仍可通过其他合理途径获得？ |
| 因果约束 | 哪些事实必须保持一致？哪些解释只是可能性，不能提前当作 CANON？ |

### 调查节点的回报标准

长调查链中的重要节点必须具有可识别的功能。允许暂时没有直接线索，但应当至少提供以下一种价值：

- **独特线索**：提供其他路线难以获得的新信息。
- **独特遭遇**：出现有独立意义的人物互动、危险、异常或事件。
- **交叉验证**：确认、修正或补全已有信息。
- **有效证伪**：排除某种假设、路线或嫌疑对象。
- **局势价值**：改变时间压力、人物关系、资源、盟友、风险或后续行动条件。

短暂的无结果调查、误导或无关发现可以存在，用于呈现真实世界的不确定性；但不得连续堆叠在一条高投入调查链上。不能把“玩家什么也没找到”当作默认填充内容。

### 重要人物失踪与失联

凡是模组把某个重要人物的失踪、失联或去向作为明确调查方向，备团时必须预先准备其后台真实状态与可收束结果：

- 当前位置或最后已知位置；
- 失踪/失联的真实原因及其因果链；
- 关键时间线与可验证痕迹；
- 生死、被困、逃离、转移、藏匿等可能结果中，哪些是事实、哪些只是玩家可形成的假设；
- 玩家采取不同路线时，如何找到目标、确认其遭遇，或获得有意义的无法抵达/无法确认的证据；
- 若它确实是有意保留的悬案，其未解本身必须具有明确叙事价值或后续用途。

除非原作明确设计为有意义的悬案，不应让重要失踪人物长期停留在“没有找到、没有解释、没有线索、没有后续”的状态。

## 3. NPC 与环境行为一致性审计

对重要 NPC、失踪者、目击者及关键互动对象，检查其行为、外观、台词和行动是否能由已知状态解释。特别检查：

- **生理/环境状态**：冷热、饥渴、疲劳、伤病、衣着、饮食、行动能力是否相互协调？若存在矛盾，它是刻意异常信号，还是无意疏漏？
- **时间与位置**：人物何时出现/离开、移动距离、交通方式和目击时间是否可能？
- **动机与知识**：人物为什么这样做？他实际知道什么？是否误用了 GM 才知道的信息？
- **行为与能力**：其行为是否符合年龄、身体状态、资源、权限和能力？
- **因果解释**：若异常/敌对势力影响了人物，已准备的能力与触发条件是否足以解释结果？不能仅因“故事需要”就把任何现象归因给主异常。
- **可推理性**：如果矛盾是线索，玩家能否通过观察或交叉验证识别它？矛盾是否有后续解释或用途？

发现矛盾时，必须明确分类：
1. 已确认的刻意线索；
2. 有待玩家调查的未知；
3. GM 已知但暂不揭示的真相；
4. 需要在开团前修正的设计错误。

不得让一个没有设计意图、没有解释、没有后续的矛盾伪装成神秘感。

## 4. 备团后的二次审核（高强度审查）

完成第一轮备团草稿后，根据模组复杂度、风险与实际需要决定是否启动 Prep QA。若启动，必须在该模组第一次 Session Preflight 之前完成；不得等到 Preflight 后再补做。审查者应以“挑错者”身份工作，而不是替原备团寻找合理化借口。

优先使用用户可访问的高能力/高思考强度模型进行第二轮审核，重点审查：

1. **事实与来源**：原作事实、规则、GM 扩写、推断、未知是否清晰分层？有没有把推断写成事实？
2. **因果闭合**：异常能力是否足以解释相关现象？NPC 行为、失踪、伤害、物品变化和时间线是否自洽？
3. **线索结构**：重要线索是否有可发现路径？是否过度依赖单一检定/单一 NPC/单一地点？长调查链每个重要节点是否有价值？
4. **调查回报**：是否存在投入很大却没有独特线索、遭遇、交叉验证、证伪或局势价值的长支线？
5. **人物与环境一致性**：衣着、温度、饮食、身体状态、动机、知识和行动是否互相矛盾？矛盾若有意，是否能被识别并最终解释？
6. **路线适配**：单人桌/角色能力/玩家可能采用的非预设路线是否有合理响应？是否存在明显的软锁或无意义死胡同？
7. **收束能力**：重要 NPC、失踪者、支线、危险和结局是否有合理的结束条件？是否留下了无意的悬空事项？
8. **剧透与权限**：GM-only 与玩家侧内容是否隔离？是否把隐藏信息泄露进简报或玩家便笺？

审核输出只需列出：
- 必须修正的问题（阻断本轮 Prep QA 通过/备团质量确认）；
- 建议修正的问题（不阻断，但应说明取舍）；
- 已确认合理的设计；
- 尚无法确认的资料缺口；
- 修订后仍需在游戏中观察的风险。

### 模型与审查边界

- 高强度审查是第二道质量关，不替代 GM 对规则、原文和 CANON 的责任。
- 若产品允许在当前工作流中使用更高能力/思考强度模型，优先采用；若无法切换，则执行明确标注的同模型第二轮审查，不得声称已获得独立模型意见。
- 当前助手不能在后台自行切换模型或保证自动调用另一个模型；需要时应由用户在产品界面选择相应模型/思考强度，或把 GM-only 备团草稿交给可用的高能力模型审查。
- 允许对 GM-only 备团草稿进行这项审查；正式游戏 LOG、玩家行动记录及其他战役私有档案仍遵循原有保密约定，不自动转交外部模型或第三方服务。
- 审查者提出的建议必须回到规则、模组原文和已建立事实核验；不能因为模型更强就自动采纳。

## 5. Prep QA 完成标准

若本轮选择执行 Prep QA，完成审核后 GM 必须确认：

- [ ] 重要调查链已建立节点、功能、回报与结束条件；不适用时注明原因。
- [ ] 重要失踪/失联人物已有后台状态、时间线、因果解释与可收束路径。
- [ ] 重要 NPC 的行为、衣着、身体状态、动机、知识和行动能力已完成一致性检查。
- [ ] 异常能力与已发生/计划发生的现象之间存在可解释的因果关系。
- [ ] 长调查链不存在无意设计的长距离无回报节点；有意的死胡同具备证伪或其他明确价值。
- [ ] 已完成高强度二次审核，或明确记录当前无法使用高能力模型并完成同模型第二轮审查。
- [ ] 审查提出的阻断问题已修复；未解决项已标记为未知/待验证，不伪装成已解决。
- [ ] 玩家侧材料未泄露 GM-only 内容。

未通过关键项时，不标记本轮 Prep QA 通过；必要时先修订备团，再重新审核。此处的完成状态仅属于 Prep QA，不代表或替代任何一次实际开团的 Preflight。

## 6. 跑团期间的调查增量检查：暂存规则

本机制目前**暂不作为每个调查节点的强制流程**，以免现场判断负担过重、过早终止有延迟回报的线索，或把调查变成机械打卡。

仅保留为未来的风险应对工具：如果实战再次出现长调查链连续无回报、玩家明显投入却没有获得信息/变化，或调查方向迟迟无法收束，GM 应重新取出本规则，检查节点价值、替代路径和结束条件，并及时修补。

不要因为某个单独节点暂时没有直接线索，就机械触发警报；调查价值可能延迟出现。当前优先改进备团质量，运行时机制留待真实案例再次触发后再迭代。
