# TRPG 叙事训练题库

> 维护者：Casey
> 性质：训练候选题库，不是自动训练日程。
> 启动规则：Casey 自主准备下一道完整训练题；每次正式训练前先提交用户检查、确认或修改。用户确认前不开始正式训练。训练过程由 Casey 独立完成，结束后再交付成果与自评供用户集中审核。
> 题库题目均为原创训练情境；如需研究小说片段，应另外记录作品与章节定位、分析目的和引用边界，不复制长段受版权保护文本。

## 一、使用规则

1. **题目由 Casey 主动准备**：按当前能力短板、近期用户反馈、训练历史和领域覆盖选择题目，不把出题责任转交给用户。
2. **正式训练前审题**：Casey 自主准备完整的新题，并在每次正式训练前提交用户检查；用户确认或提出修改后，才开始训练。不得把“题目由 Casey 出”误解为“可以跳过用户审题”。
3. **一次交付完整训练单元**：完成样本拆解（适用时）、初稿、独立诊断、修订稿、对照和 Skill 沉淀判断。过程中不逐步打断用户索取反馈。
4. **训练后交用户审核**：展示成果与自评，记录用户对效果、节奏、表达和适用边界的反馈；不把沉默或一次认可当作稳定掌握证据。
5. **审题是每次正式训练的固定前置步骤**：无论题目是否改变训练方向，都必须先提交用户检查。若题目涉及重大方向变化、明确排除内容或关键用户决策，还需在题面之外单独说明并等待决定。
6. **题目不等于训练成果**：训练结束后记录实际表现、用户反馈、缺陷、反例和后续验证；不能因做过题就标记能力掌握。
7. **维护题库**：记录已用题目、难度、暴露缺陷和修订；避免近期重复同类题。用户提供的新题也进入题库，并保留其来源标记。
8. **可以改题，不必守题**：若玩家行动、小说样本或实战复盘暴露新问题，Casey 可以设计新题替换旧题，并在训练记录中说明调整理由。

## 二、单题格式

每道题至少维护：
- ID 与领域；
- 训练目标；
- 情境与完整题面；
- 难度与训练形式；
- 关键约束；
- 预期交付；
- 评价重点；
- 主要应用位置（Prep / Runtime / Both / Continuity）；
- 状态（待练 / 已练习 / 需重练 / 暂缓）；
- 训练结果与后续验证记录。

## 三、初始题库

### SCN-001｜第一次进入旧公寓地下室

- **领域**：场景构建与空间呈现
- **难度**：基础
- **形式**：独立叙述 + 自我诊断
- **应用**：Runtime
- **题面**：

  玩家第一次进入一栋仍有人居住的旧公寓地下室。这里有储物隔间、公共洗衣区、供暖设备和通往停车场的门。当前没有已确认的异常或线索。请写出玩家跨过门槛后最初能感知到的场景，并明确空间关系与可行动入口。

- **约束**：不得擅自增加线索、危险或异常；避免逐项罗列五感；不要替玩家决定注意力或情绪。
- **交付**：现场描述、空间锚点标注、删除/保留细节的理由。
- **评价重点**：空间是否清楚、细节是否有选择、是否自然交还行动权。

### SCN-002｜熟悉环境出现可验证的异常

- **领域**：场景构建、异常呈现
- **难度**：中等
- **形式**：对照实验
- **应用**：Runtime
- **题面**：

  玩家已经进入一个熟悉的办公楼层。走廊尽头的饮水机突然发出一段像有人轻敲玻璃的声音，但周围没有人靠近。玩家尚未检查饮水机。请写出第一次异常出现时的描述，并设计玩家从远处观察、靠近、触碰三种行动的反馈原则。

- **约束**：不得直接解释异常来源；三种反馈必须保持同一事实基础；不得强行升级危险。
- **交付**：初次叙述、三种行动反馈、事实/未知分层。
- **评价重点**：异常是否具体可感知、可调查、反馈是否一致。

### NPC-001｜L1 模组人物的首次介绍

- **领域**：NPC 人物塑造、首次出场
- **难度**：基础
- **形式**：多版本对照
- **应用**：Prep + Runtime
- **题面**：

  一名 40 岁左右的夜班药房主管是本模组的重要调查对象。她工作认真，不喜欢浪费时间，但并不敌视调查人员。玩家第一次走进药房后，她正核对一批退货药品。请为她建立 L1 人物卡，并写一段首次出场介绍。

- **约束**：外貌、声音、着装细节可自行设计为明确的 GM ADAPTATION，但必须少而有用；不得逐项完成人物外貌清单；避免把“认真”写成皱眉、叹气等空泛动作。
- **交付**：L1 人物信息卡、首次出场描述、后续互动时能兑现的两个角色特征。
- **评价重点**：是否形成初步人物印象、外表是否简洁、动作是否服务人物。

### NPC-002｜同一句话，不同人物状态

- **领域**：NPC 对话、情绪与动作
- **难度**：中等
- **形式**：对照实验
- **应用**：Runtime
- **题面**：

  玩家用夸张的敬礼动作开玩笑，说“全听你的指挥”。NPC 需要回应：“先别急，我们还有一件事没确认。”分别写出她正在忍笑、全心投入工作、带着一点考校意味三种状态下的回应。

- **约束**：三版必须体现同一句话背后的不同状态；动作要提供额外信息，不可只写“看了你一眼”；每版控制在短段落内。
- **交付**：三版对白与动作、每版的意图解释、最适合当前关系/场景的判断。
- **评价重点**：状态能否从具体行为看出、动作是否有信息价值、篇幅比例是否合理。

### NPC-003｜有理由的拒绝，而非剧情阻碍

- **领域**：NPC 自主性与即兴对白
- **难度**：中等
- **形式**：互动模拟
- **应用**：Runtime
- **题面**：

  一名 L1 证人知道玩家正在调查的事实，但拒绝把私人通讯记录交给陌生调查员。她并不敌视玩家，也没有被模组设定为必须阻挠调查。玩家先礼貌解释、再提出正式手续、最后尝试提供交换条件。请分别回应，并维护她的目标和边界。

- **约束**：不得因为玩家尝试三次就机械松口；不得为证明 NPC 独立而刻意刁难；不得新增没有依据的秘密。
- **交付**：三轮回应、人物策略变化条件、可能的后续选择。
- **评价重点**：拒绝是否可信、策略是否因玩家行动变化、信息公平是否保留。

### ACT-001｜玩家采取未预设的环境行动

- **领域**：玩家行动反馈
- **难度**：中等
- **形式**：情境推演
- **应用**：Prep + Runtime
- **题面**：

  玩家发现一扇自动门每次关闭前都会停顿半秒。他没有按预设方式寻找门禁卡，而是把一件普通物品放在门缝附近，观察门的反应。请根据已给出的现象回应这项行动，并说明后续如何保持因果一致。

- **约束**：不得直接把玩家物品变成万能工具；不得无依据判定危险或成功；区分可观察结果与机制推断。
- **交付**：即时反馈、可能的后续实验、状态变化记录。
- **评价重点**：是否认真处理玩家意图、反馈是否可验证、世界是否保持一致。

### ACT-002｜玩家提出聪明但不在预案中的解决办法

- **领域**：即兴响应、世界因果
- **难度**：高
- **形式**：多路径推演
- **应用**：Prep + Runtime
- **题面**：

  玩家发现异常每次只在房间里某台设备通电时出现。他没有摧毁设备，而是提出先断电、再用独立电源逐项测试房间内其他设备，以确定异常是否跟随电源、设备或空间。请设计 GM 如何回应这一方案。

- **约束**：不预设玩家必须成功或失败；区分玩家已经观察到的事实与尚待验证的假设；结果依当前虚构场景的规则与事实，不临时改写异常机制。
- **交付**：行动拆解、风险提示、逐步反馈框架、可能的后果与状态更新。
- **评价重点**：方法是否公平、风险是否预先说明、非预设方案是否得到认真处理。

### CLUE-001｜关键事实的多条合理获取路径

- **领域**：线索与信息公平
- **难度**：中等
- **形式**：备团设计
- **应用**：Prep
- **题面**：

  模组的一个关键事实是：某名员工在事故发生前曾私下联系过设备供应商。玩家需要有机会查明这段联系，但不应被迫依次访问三个固定 NPC。请设计合理的获取路径、各自的信息来源和验证方式。

- **约束**：不同路径必须有真实来源与不同代价/信息角度；不机械复制三份完全相同的线索；不得用单次失败永久锁死主线。
- **交付**：线索与来源卡、替代路径、验证与误导边界。
- **评价重点**：信息是否公平、来源是否可信、路径是否能适应不同玩家计划。

### CLUE-002｜再次访问同一个信息来源

- **领域**：调查增量与 NPC 知识
- **难度**：中等
- **形式**：多轮访谈设计
- **应用**：Prep + Runtime
- **题面**：

  玩家第二次找到一位此前已经提供过证词的护士。这次玩家问的是“你当时为什么会离开护士站”，而第一次问的是“你看见了什么”。请设计护士能够提供的信息，并区分重述、补充、矛盾和真正不知道的内容。

- **约束**：不得把来源视为一次性线索机器；不得为了每次访问都有新情报而编造；记住她实际在场和能观察到的范围。
- **交付**：来源知识卡、两轮问答、增量记录。
- **评价重点**：人物知识边界、信息增量、重复对话压缩。

### PACE-001｜把机械调查流程压缩到合适长度

- **领域**：叙事节奏
- **难度**：基础
- **形式**：改写
- **应用**：Runtime
- **题面**：

  玩家连续检查三份格式相同、内容相近的办公室登记表。第二份只增加一个时间差，第三份完全没有新增信息。请分别写出第一次查阅、第二次查阅和第三次查阅的 GM 表达。

- **约束**：不得跳过第二份的新增时间差；第三份不得重复完整演出；保留玩家可以继续深挖的入口。
- **交付**：三段现场表达与压缩理由。
- **评价重点**：新增信息是否突出、重复内容是否压缩、节奏是否尊重玩家意图。

### ATM-001｜先建立日常基线，再制造不安

- **领域**：氛围与异常递进
- **难度**：中等
- **形式**：分阶段写作
- **应用**：Prep + Runtime
- **题面**：

  玩家在一家夜间营业的洗衣店等候烘干。店内只有两名顾客和一名店员，设备运转正常。随后玩家注意到一台空烘干机的玻璃门内侧出现一圈水汽手印。请写出异常前的日常场景、第一次发现和玩家靠近观察时的反馈。

- **约束**：日常段不得提前渲染成恐怖场景；异常先呈现可观察事实；不得擅自说明手印来源。
- **交付**：三个阶段的描写、情绪强度变化说明、可调查入口。
- **评价重点**：基线与异常的对比、节奏递进、信息留白。

### CONT-001｜中断后从正确叙事节点续接

- **领域**：连续性与上下文恢复
- **难度**：高
- **形式**：冷启动测试
- **应用**：Continuity
- **题面**：

  提供一份包含时间、地点、在场人物、已呈现入口、最近行动、NPC 已知信息和待处理选择的 Runtime State。模拟一次新对话恢复。请确认当前是 CONTINUE 还是 NEW START，并写出续接时第一条 GM 回复。

- **约束**：不得重演已经呈现的场景入口；不得把 GM-only 信息交给玩家或 NPC；不得补造缺失状态；若关键字段冲突，必须指出并回查。
- **交付**：恢复判定、关键锚点核对、续接回复、未解决风险。
- **评价重点**：是否从最后有效节点继续、是否出现重演/穿帮、玩家与 NPC 知识是否隔离。

### CONT-002｜跨地点移动与时间连续性

- **领域**：世界状态与因果维护
- **难度**：高
- **形式**：状态追踪模拟
- **应用**：Prep + Runtime + Continuity
- **题面**：

  玩家、长期同行 NPC 和一名联络人分别位于三个地点。事件日志记录了通话、出发、交通延误和一次物品转交。请根据给定事件顺序更新 Runtime State，并判断下一场景中每个人能合理知道什么、携带什么、在哪里。

- **约束**：不允许人物瞬移、物品复制、知识自动共享；未知的交通耗时不得装作精确事实。
- **交付**：更新后的状态表、事件增量、下一场景可用信息。
- **评价重点**：时间/位置/物品/知识一致性与来源追溯。

### MIX-001｜综合场景：玩家行动、NPC 策略与氛围同步变化

- **领域**：综合主持
- **难度**：高
- **形式**：完整互动模拟
- **应用**：Prep + Runtime
- **题面**：

  玩家进入一家深夜便利店，打算询问店员关于附近一名失踪者的消息。店员认识失踪者，但不愿随便谈论。交谈中，一名常客进门，店员的注意力明显转移。玩家可以继续追问、观察常客、改变话题或离开。请主持一个保持开放选择的短场景。

- **约束**：NPC 必须有自己的目标和知识边界；常客的出现必须有合理现场原因；不得预设玩家一定追问；场景氛围不依赖突然袭击或强制反转。
- **交付**：场景备团卡、现场模拟、行动后状态变化、自我复盘。
- **评价重点**：NPC 自主性、玩家回应、空间调度、节奏、信息公平和状态一致性。
