# H1-3 工作台缓解决策｜2026-11-26

## 决策摘要

H1-3 的目标从“证明或修复 ChatGPT 平台底层跨会话上下文机制”收敛为：

**在 TRPG GM 工作台可控制的范围内，阻止未经本次授权和来源核验的跨会话信息进入当前桌面事实、NPC 知识、玩家笔记、Session Log 投影和玩家可见输出。**

平台是否向模型提供隐藏 Memory、历史摘要或其他上下文，当前工作台没有可观测日志，也没有修改权限。本项目不再把这部分列为可由 Skill/仓库修复的工程目标。

## 1. 证据结论

- 第一轮空白 Chat 曾将助手专名写入人物记录，且没有当前会话来源锚点；这是具体身份信息来源闸门失败。
- 后续三个独立目标样本没有再次出现该专名或其他可识别的旧 NPC、剧情、访谈和项目专有事实。
- 操作者在目标 Chat 外完成私有 Canary 比对，三份结果均为 NO HIT。仓库不记录 Canary 的名称、属性、关系或原文。
- 三份样本均出现无请求的会话隔离/历史记忆方法论声明。该现象可重复，但本身不是 Canary 命中，也不能证明隐藏上下文注入路径。
- 阶段 B 来源审计是模型自述，不是平台日志。不得据此确认具体 Memory、摘要或注入机制。
- 因缺少目标 Chat 完整元数据和平台侧日志，本轮只能报告可见输出与操作者外部比对结果。

## 2. 风险面与工作台控制

| 风险面 | 工作台规则 |
|---|---|
| 助手名称、昵称、人格、关系称谓残留 | 身份字段也必须有当前会话或本次明确载入资料的来源锚点；否则不建立 |
| 用户个人背景或偏好混入事实记录 | 当前会话事实任务不把个人资料/Memory 当作事件证据 |
| 旧 NPC、剧情、任务、资源和规则进入新桌 | 仅使用当前会话事件或本次明确读取的适用权威来源 |
| 旧 Session Log / Player Notes 被当作新证据 | 旧记录是历史材料或派生投影；必须重新核验权威来源和接收者范围 |
| NPC 获得其他会话或 GM 私有知识 | 知识必须由当前桌实际获取/披露事件支持，不能从 GM 记忆直接赋予 |
| GM-only 信息进入玩家输出 | 按字段白名单、recipient_scope 和实际呈现事件投影；无法核验时拒绝导出 |
| 来源不明信息继续派生 | 标记 UNKNOWN / QUARANTINED；停止依赖该命题的推进和状态写入，必要时按 T0 处理 |
| 内部隔离规则变成无关的用户可见说明 | 普通任务静默执行，不主动播报 Memory、历史摘要或隔离原则 |

## 3. 当前运行规则

### 3.1 默认来源顺序

1. 当前会话实际发生并可核验的事件；
2. 本次明确指定、实际读取且权限适用的权威资料；
3. 用户本轮明确提供、并要求分析的历史材料（必须标注历史来源，不得改写为当前事件）；
4. 基于以上来源的推断（保持推断身份）；
5. 其他会话、平台 Memory、历史摘要和模型回忆：默认隔离，不作为当前事实来源。

### 3.2 缺失与污染处理

- 无来源锚点：标 UNKNOWN / NOT ESTABLISHED，不补全、不猜来源。
- 有具体跨会话细节但本次无来源：标 CROSS_SESSION_RESIDUE / QUARANTINED。
- 已进入玩家可见输出或影响玩家选择/状态：保留原始呈现，停止受影响推进，按 Runtime T0 流程评估、告警和追加更正。
- 不静默改写历史，不让后续摘要覆盖首次错误，不把模型自述当作注入日志。
- 仅有通用隔离措辞、没有具体旧事实：记录为输出模式异常，不直接判定具体信息泄露。

### 3.3 静默执行

普通事实整理、玩家笔记、场景回顾和 Preflight 不主动解释内部隔离协议。用户询问来源或隔离机制时，再提供与问题相关的最小必要说明。不要声称已检查或清除平台隐藏上下文。

## 4. 适用边界

本决策适用于 TRPG GM 工作台及其生成的当前桌面事实、NPC 知识、Runtime、Session Log、Player Notes 和玩家可见摘要。它不提供平台级上下文访问控制，也不承诺清除 ChatGPT Memory 或历史摘要。

用户明确要求历史回顾/续团时，必须在本次重新读取指定来源，并标注历史范围、来源和接收者权限。不能只凭“我记得”恢复战役状态。

## 6. 后续维护原则

- 不再为无法观察的平台注入机制开展无边界推测。
- 后续若出现具体旧事实、身份或私有信息进入当前输出，保留原始证据并按来源闸门和 T0 处理。
- Canary 只作为定期抽检工具；NO HIT 仅表示本轮未命中，不是平台安全证明。
