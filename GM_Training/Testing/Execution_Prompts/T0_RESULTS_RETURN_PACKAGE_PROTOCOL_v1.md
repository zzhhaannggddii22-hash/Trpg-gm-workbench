# T0 盲测结果回寄 ZIP 协议 v1

## 目的
规定 Pro 操作者完成 T0 自然语言盲测后，如何保存完整证据、打包并交给独立复核者。此文件不替代目标 Chat 隔离协议或操作者评分夹具。

## 1. 结果包结构
建议文件名：`T0_Natural_Language_Blind_Test_Results_YYYY-MM-DD.zip`。

压缩包内部必须包含：
- `README_RESULTS.md`：测试结论、实际执行数量、环境、限制、有效性结论。
- `manifest.json`：每个文件的相对路径、大小（bytes）、SHA-256、类型/用途；记录仓库 main commit 和所有源文件 blob SHA。
- `execution/A01/` 至 `execution/A08/`：每轮一个文件，包含逐字玩家输入、完整目标 Chat 输出、时间戳和轮次序号。
- `environment/`：模型、Thinking 档位、客户端/浏览器、执行日期、可见工具和设置。
- `evidence/A01/` 至 `evidence/A08/`：空白 Chat 证据、Chat URL、附件加载、规范读取、工具轨迹等。
- `scoring/`：逐轮五维评分、每试次小计、五维汇总、总分、硬失败登记与评分理由。
- `deviations/`：协议偏离、缺失证据、污染事件和无法判定项。

## 2. 原始证据
- 保留完整原始输出，不得只写摘要或重述。
- 不对原始记录做润色、纠错或截断；如需摘要，另存文件。
- 截图按试次和轮次编号，并在 manifest 中说明证明内容。
- 不收集或打包密码、Cookie、访问令牌及其他凭据。
- 未执行的轮次必须标记 NOT RUN，不得生成虚构输出。

## 3. 哈希与完整性
- 每个纳入 ZIP 的文件在打包前计算 SHA-256 和字节大小。
- 生成 ZIP 后计算 ZIP 本身 SHA-256。
- 使用解压测试确认压缩包无损，并逐文件复算 SHA-256，与 manifest 对照。
- 若任一文件校验失败，修复后重新生成 ZIP 和 manifest。

## 4. 交付
- 将 ZIP 作为附件交回发起任务的用户/独立复核者，确保其能实际取得文件。
- 在 GitHub 的 `GM_Training/Acceptance_Reports/` 新建结果报告，注明 ZIP 文件名、SHA-256、测试基线 commit、执行范围、证据等级、评分结果和限制。
- GitHub 报告可引用 ZIP，但不能用报告摘要代替原始 ZIP 交付。
- 保留 2026-11-24 的 PREPARATION / NOT STARTED 历史报告，不覆盖其事实。

## 5. 验收结论
结果必须分开陈述：
1. 目标 Chat 行为是否真实执行；
2. 测试隔离是否成立，是否存在 CONTAMINATED；
3. 证据等级（E0–E3）；
4. 行为评分及硬失败；
5. 是否达到总分、分维度、单试次门槛；
6. 仍未覆盖的风险。

性能优化只能在结果 ZIP 已交付、独立复核完成且达到预设准入标准后另行启动。
