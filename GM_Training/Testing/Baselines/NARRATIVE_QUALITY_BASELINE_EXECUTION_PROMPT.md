## 二、按投入等级选择执行方式

NQB-01 的完整基准执行属于 L2。L1 只能回答一个局部问题，不得将局部结果写成完整 NQB-01 通过或基准校准完成。

### L1：定向 Spot Check

**目的：**低成本检查单一修改直接影响的叙事行为。

1. 只选择一个与修改风险直接相关的场景切入点或既有短行动序列。
2. 可以使用单会话自测；若使用合成玩家，必须明确标记为合成模拟。
3. 只审查基础正确性硬门槛及本次相关的少量质量维度；其他维度标记为未测试，不强制评分。
4. 保存每个相关 ACTION 的完整 A 线玩家可见原文及对应 B 线 GM 观察；可以省略无关状态账本，不得用摘要替代 A 线原文。
5. 验收结论仅限本次定向观察：PASS / FAIL / PARTIAL / BLOCKED / NOT_ACCEPTED / INSUFFICIENT_EVIDENCE；执行完成状态与验收结论分开记录。不得声称完成 NQB-01 完整基准或证明稳定性。

### L2：完整低压基准

**目的：**评估普通日常互动下的完整叙事质量。

有两种证据模式，必须分开记录：

#### 模式 A：单会话自动化自测

用于快速诊断和版本比较，不等同于真实玩家验证。

1. 在内部明确分离两个角色：
   - **模拟玩家**：依据玩家启动提示和预先确定的普通玩家行动倾向，生成自然、合理、非最优解导向的行动。
   - **GM**：只依据 GM 可用资料、当前场景状态和玩家已采取的行动进行主持；不得因提前知道模拟玩家的后续计划而预置回应。
2. 开始前确定简短行动倾向并记录。行动应有自己的兴趣、犹豫和临时转向；不得为了触发评分项而刻意逐项测试，也不得只采取容易处理的行动。
3. 逐轮交替生成玩家行动与 GM 回复。每轮先确定行动，再生成回应；不得先写完整 GM 故事再倒推玩家行动。
4. 以至少 8 个有意义的模拟玩家回合作为覆盖目标。场景自然收束或行动意愿变化时可以提前结束；少于 8 回合只表示覆盖较窄，不构成执行失败。
5. 每个 ACTION 按顺序保存 A/B 两线：A 线为完整玩家可见 GM 回复原文；B 线为对应的内部观察（来源/信念变化、行动与状态变化、未知项）。B 线不得混入 A 线，也不得替代 A 线。玩家行动与 GM 回复逐轮完整保存，明确标记为合成内容，不得伪装成真实用户输入。
6. 如需比较两次自动化运行，第二次必须改变玩家关注点或互动方式，而非只替换措辞。
7. 证据等级标记为“单会话合成模拟／自动化自测／非独立盲测”。评分属于模型自评，必须引用原始回合并检查自我宽容风险。

#### 模式 B：真实玩家逐回合验证

这是完整 NQB-01 的优先证据模式。

1. 由真实玩家逐回合输入行动，GM 每次只回应当前行动。
2. 不得代写、预测或补齐玩家后续行动；不得在一条 GM 回复中模拟多个玩家回合。
3. 以至少 8 个有意义的真实玩家回合作为覆盖目标。玩家可以随时结束、离开或改变方向；少于 8 回合只表示覆盖较窄，不得补造行动或强留玩家。
4. 行动自然覆盖观察、普通交谈、日常互动、预案外行动、停顿／等待，以及继续或离开的决定；不得强迫玩家走固定路线。
5. 完整保存真实玩家原始输入、每轮 GM A 线原始回复及对应 B 线观察；B 线作为测试审计记录，不属于玩家可见回应。 B 线必须保存在独立的 GM/操作者审计记录中，不得在玩家对话里展示；若无法提供独立记录通道，可在玩家会话结束后单独归档，不能为了即时记录而向玩家泄露。
6. 证据等级标记为“真实玩家逐回合交互”。这仍不等于真实线下团、长期稳定能力证明或独立第三方盲审。

完整基准至少需要两组明显不同、但都符合场景的玩家行动序列，并经过审核，才可讨论跨行动序列稳定性。若当前只完成一组，照实标记样本数与未覆盖边界。

## 三、共同主持规则

- 本次为独立测试，不继承其他跑团、战役或训练场景的事实。
- 不绑定具体规则系统，不掷骰，不引入其他系统机制。
- 先完成资料读取和内部准备，然后自然呈现玩家启动场景。
- 不主动制造谜题、危机、倒计时、强制冲突或必需线索。
- 不把玩家的观察、推断、情绪或行动替玩家决定。
- 普通细节可以自然补全；一旦玩家观察、验证、操作或依赖某项细节，就维护该细节及其后续因果的一致性。
- 不向玩家输出评分表、GM 状态表、隐藏事实或测试内部检查项。
- 不要因为“这是基准测试”而刻意展示全部能力；只需像成熟的叙事型 GM 一样主持。
- 不以减少互动、压缩所有描写、扣留合理可得信息或降低 NPC 自主性来换取表面上的正确率。

## 四、结束与交付

按实际投入等级和执行模式记录，不为未执行的项目补填分数。

1. **执行元数据**
   - L1 或 L2；
   - 执行模式 A 或 B；
   - 证据等级；
   - 模型／版本（能够确认时）；
   - 工作台 commit SHA、质量标准版本、场景资料包版本；
   - 实际回合数、完整行动序列数；
   - 是否完整读取适用资料。
2. **原始记录**
   - 模式 A：模拟玩家行动与 GM 回复逐轮交替，明确标记合成内容；每个 ACTION 保存完整 A 线原文和对应 B 线观察；
   - 模式 B：真实玩家原始输入、GM A 线原始回复与对应 B 线观察；
   - B 线是内部审计材料，不属于玩家可见叙事；不得用 B 线摘要或执行摘要替代 A 线。
3. **基础正确性硬门槛**
   - 对适用检查项判定 PASS / FAIL / UNKNOWN；
   - 提供原始回合证据；
   - 区分轻微错误、重大失败、致命失败，并说明计数口径。
4. **交互质量与叙事表现质量**
   - L1：只评价与本次风险直接相关的维度，其余标记未测试；
   - L2：对有足够证据的适用维度按 0–4 分评价；
   - 每项评分引用 A 线原文中的具体句段/行动，并说明其如何满足评分锚点；只引用摘要、B 线、状态账本或执行者意图不构成叙事证据；证据不足或未触及的维度不得猜分；
   - 不得用平均分掩盖核心短板。
5. **证据限制**
   - 区分直接观察与解释性判断；
   - 说明合成玩家配合、自评偏差、行动序列简单或覆盖不足等限制；
   - 明确本次不能支持的结论。
6. **结论**
   - 分别给出三道独立门禁：基础正确性、叙事质量、双线一致性/可审计性；
   - 任一适用门禁 FAIL，整体验收不通过；任一门禁证据不足，整体标记 `NOT_ACCEPTED / INSUFFICIENT_EVIDENCE`；不得使用 `PASS_WITH_LIMITS`；
   - `PASS_WITH_LIMITS` 只适用于所有门禁均已通过、但样本泛化范围有限的情况；
   - 不得把“完成运行”写成“测试通过”；
   - 不得把单次样本写成稳定能力证明。

若出现玩家信息通道泄露或重大事实矛盾，不得以整体氛围良好冲销。

## 五、三道独立验收门禁

1. **基础正确性**：检查事实、规则、信息权限、玩家行动权与关键连续性；重大/致命失败不可由其他表现抵消。
2. **叙事质量**：所有适用核心维度达到 NQB 3 分，且每项评分都有 A 线原文证据。缺少原文时标记 NOT_VERIFIABLE，不得根据摘要推测分数。
3. **可审计性**：每个 ACTION 均保存完整 A 线和对应 B 线，能够核对两线一致性、信息边界与来源版本。缺少任一必要记录即 NOT_VERIFIABLE。

三道门禁彼此独立。纯状态/规则测试且明确不评价叙事时，叙事门禁可标记 N/A；不得把 N/A 当作通过。逐 ACTION 双线记录只用于测试审计，不改变正式跑团的玩家可见输出。

## 六、启动与读取失败处理

启动前核对当前 ref 与 commit，并读取质量标准、适用场景资料和审核表。若无法读取任何关键资料，报告具体缺失并停止，不得凭本提示补造 GM 专用内容。

- L1 局部验证：只读取与该风险相关的必要场景资料和标准条目。
- L2 完整基准：读取上述四份资料。
- 用户要求自动化自测或未指定模式：使用模式 A，并明确其证据边界。
- 用户明确要求自己扮演玩家：使用模式 B。
- 用户明确要求比较两种模式：分别执行并分开记录，不得混合证据等级。

资料读取成功后，直接开始场景，不要先向玩家展示测试说明。
