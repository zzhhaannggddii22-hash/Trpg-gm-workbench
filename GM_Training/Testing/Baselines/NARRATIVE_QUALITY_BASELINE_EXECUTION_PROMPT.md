## 二、两种自动化执行模式

### 模式 A：同会话自动化自测（默认）

**目的：**检验 GM 是否能在当前执行会话内，无需用户逐回合输入，自主运行一段完整、连贯的合成测试场景，并留下可审核的逐轮证据。

执行要求：

1. 在内部明确分离两个角色：
   - **模拟玩家**：依据玩家启动提示和一个预先确定的普通玩家行动倾向，生成自然、合理、非最优解导向的玩家行动。
   - **GM**：只依据 GM 可用资料、当前场景状态和玩家已采取的行动进行主持。GM 不得因为自己知道后续模拟玩家打算做什么而提前布置回应。
2. 开始模拟前，先确定本轮玩家行动倾向或简短行动计划，并记录下来。行动应像真实玩家一样有自己的兴趣、犹豫和临时转向；不得为了触发评分表项目而刻意逐项测试 GM，也不得为了让 GM 得高分而只采取容易处理的行动。
3. 逐轮交替生成玩家行动与 GM 回复。每个回合必须先确定玩家行动，再生成该回合 GM 回复；不得先写完整 GM 故事，再倒推玩家行动来配合它。
4. 通常以至少 8 个有意义的模拟玩家回合作为覆盖目标；但场景自然收束或玩家行动意愿发生变化时，可以提前结束。少于 8 回合不构成用户或执行者的失败，只代表覆盖范围较窄；不得为了达到数量而强行延长场景。
5. 模拟玩家行动与 GM 回复必须逐轮完整保存。记录中要清楚标记每条内容的角色归属，不得把模拟行动写成真实用户输入。
6. 至少进行一次不同的行动序列，才能讨论两次自动化自测之间的稳定性。不同序列应改变玩家关注点或互动方式，而不是只替换措辞。
7. **证据等级必须标记为“单会话合成模拟／自动化自测／非独立盲测”。** 不得称为真实玩家多轮交互、真实桌面 Session 或独立第三方评估。
8. 自动化自测的评分属于模型自评。必须主动检查自我宽容风险；评分证据要引用原始回合，不能只凭整体印象打分。

### 模式 B：干净目标会话自动化 + 独立审核（专项）

**目的：**检验 GM 在不继承当前审查会话上下文的干净目标 Chat 中，能否自动完成同一类合成测试，并由另一个审核会话独立检查原始结果。

执行要求：

1. 操作者建立真正空白的新 Chat；不得从旧会话分支，也不得把历史摘要、其他测试结果或 Oracle 放入目标 Chat。
2. 目标 Chat 只接收本提示、指定版本的权威资料、GM Packet 与允许提供的测试输入；不得提供审核 Oracle、隐藏答案或评分标准。
3. 目标 Chat 按模式 A 的自动化方法逐轮模拟玩家行动与 GM 响应；不要求用户逐回合输入。
4. 目标 Chat 完成后输出完整原始行动/回应、状态账本、版本信息和实际读取证据；不得自称独立审核通过。
5. 操作者将完整结果粘贴到与目标 Chat 分离的审核会话。审核者在收到原始结果后再读取 Review Checklist，独立检查硬门槛、评分和证据边界。
6. 证据标记为“干净目标会话合成自动化 + 独立结果审核”。它仍不是真实玩家逐轮交互、真实线下团或隐藏平台内部机制证明。

### 模式 C：真实玩家逐回合验证（非自动化补充证据）

**目的：**观察 GM 面对真实玩家自主行动时的实际表现。此模式是实战互动证据，不属于两种自动化测试模式。

执行要求：

1. 由真实玩家逐回合输入行动，GM 每次只回应当前行动。
2. 不得代写、预测或补齐玩家后续行动；不得在一条 GM 回复中模拟多个玩家回合。
3. 通常以至少 8 个有意义的真实玩家回合作为覆盖目标；但玩家可以随时结束、离开或改变方向。少于 8 回合不构成用户或执行者的失败，只代表覆盖范围较窄；不得为了凑回合数强留玩家。
4. 完整保存真实玩家输入与 GM 原始回复。
5. 证据等级标记为“真实玩家逐回合交互”。这仍不等于真实线下团、长期稳定能力证明或独立第三方盲审。
6. 如果玩家没有完成足够回合，照实记录实际回合数，不得补造玩家输入。

**NQB-01 的正式真实玩家校准**仍以模式 C 为准。模式 A/B 的合成测试可用于常规回归与独立环境抽检，但不能冒充真实玩家回合，也不能单独证明长期稳定能力。
## 三、三种模式共同遵守的主持规则

- 本次为独立测试，不继承其他跑团、战役或训练场景的事实。
- 不绑定任何具体规则系统，不掷骰，不引入其他系统机制。
- 先完成资料读取和内部准备，然后自然呈现玩家启动场景。
- 不主动制造谜题、危机、倒计时、强制冲突或必需线索。
- 不把 NPC 内心、未说出口的记忆、私人意图直接交付给玩家。只呈现玩家能够感知的行为；人物选择说出口的信息时，再通过对白交付。
- 不把玩家的观察、推断、情绪或行动替玩家决定。
- 普通细节可以自然补全；一旦玩家观察、验证、操作或依赖某项细节，就维护该细节及其后续因果的一致性。
- 不向玩家输出评分表、GM 状态表、隐藏事实或测试内部检查项。保持自然的实际跑团体验。
- 不要因为“这是基准测试”而刻意展示全部能力；只需像成熟的叙事型 GM 一样主持。
- 不以减少互动、压缩所有描写、扣留合理可得信息或降低 NPC 自主性来换取表面上的正确率。

## 四、结束与交付

场景自然收束或达到合理结束点后，生成测试记录。记录至少包含：

1. **执行元数据**
   - 执行模式 A、B 或 C；
   - 证据等级；
   - 模型/版本（能够确认时）；
   - 工作台分支、提交版本和夹具版本；
   - 实际回合数；
   - 是否完整读取指定资料。
2. **逐轮原始记录**
   - 模式 A：模拟玩家行动与 GM 回复逐轮交替，明确标记为合成内容；
   - 模式 B：干净目标 Chat 中的合成行动/回应原文，以及独立审核会话的审核结果；
   - 模式 C：真实玩家原始输入与 GM 原始回复。
3. **基础正确性硬门槛**
   - 逐项判定 PASS / FAIL / UNKNOWN；
   - 对每项提供原始回合证据；
   - 区分轻微错误、重大失败、致命失败，并说明计数口径。
4. **交互质量与叙事表现质量**
   - 各维度 0–4 分；
   - 每项评分必须引用至少一段原始证据；
   - 说明低分、未触及维度和证据不足，不得为了填满表格而猜分；
   - 不得用平均分掩盖核心短板。
5. **自评偏差检查**
   - 指出哪些判断来自直接证据，哪些是解释性判断；
   - 指出可能存在的自我宽容、模拟玩家偏向配合、行动序列过于简单等局限；
   - 明确本次不能支持哪些结论。
6. **结论**
   - 分别给出基础正确性、交互质量和叙事表现质量的判断；
   - 不得把“完成运行”写成“测试通过”；
   - 不得把单次样本写成稳定能力证明。

测试记录必须保留足够的原始对话证据，不得只写摘要。若出现玩家信息通道泄露或重大事实矛盾，不得以整体氛围良好冲销。

## 五、启动与读取失败处理

收到执行请求后，先读取本提示指定的三份主持资料，并核对精确 commit。若无法读取任何一份关键资料，明确报告具体缺失，不要凭本提示补造 GM 专用资料。Review Checklist 只在执行结束后由模式 A 自审或模式 B/C 的独立审核者读取。

- 用户要求自动化自测或未指定模式：使用模式 A。
- 用户明确要求干净目标 Chat 执行并回传独立审核：使用模式 B。
- 用户明确要求自己扮演玩家或需要真实玩家逐轮证据：使用模式 C。
- 用户明确要求比较模式：分别执行并分开记录，不得混合证据等级。

资料读取成功后，直接开始场景，不要先向玩家展示测试说明。
