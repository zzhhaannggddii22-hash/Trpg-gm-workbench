# QA System Acceptance v1｜Challenge Cases

> 执行输入；不包含预期结论。所有案例均为合成资料，不得写入正式 Campaign。

## QA-SYS-01｜常规可自动化回归

**情况**

一个固定版本的 GM 叙事回归夹具包含完整 START、GM_PACKET、四个按序 ACTION 和 ORACLE。所有必需规则/规范来源均可读取，初始状态明确。执行者能够在当前会话内依次模拟玩家行动、回应并更新状态。四步均已完成，没有事实、规则、权限或玩家行动权硬失败。执行者在同一会话中读取 ORACLE 后完成自审。

**需要判断**

选择执行模式、执行状态、样本结论和证据边界。

## QA-SYS-02｜优秀表现掩盖硬性信息泄露

**情况**

GM 的场景描写具体，NPC 对话自然，玩家行动获得有效反馈，节奏和氛围都很好。但在一段旁白中，GM 直接写出 NPC 没有说出口、玩家也没有通过其他渠道获得的私人记忆。其他所有维度表现优秀。

**需要判断**

硬门槛与整体结论如何处理？是否允许体验分数补偿？

## QA-SYS-03｜关键依赖缺失

**情况**

测试要求依据当前规则原文裁定一项行动，但规则文件在指定 ref 下读取失败。执行者只拿到旧摘要，无法确认其版本与适用范围。其他场景资料完整，执行者认为“凭经验应该差不多”，希望继续评分。

**需要判断**

能否继续依赖该规则的测试？应使用什么执行状态？是否允许推断规则内容？

## QA-SYS-04｜分支输出通过，但重置隔离不可核验

**情况**

一个低压回归有 A/B/C 三个分支。三份输出各自符合对应 Oracle，单独看均没有硬失败。但执行者在同一回复中连续处理分支，未能提供足够证据证明每个分支都从同一不可变初始状态独立重置，且跨分支状态没有污染。

**需要判断**

单分支输出与整套回归分别应如何判定？能否把整套回归标记为 PASS？

## QA-SYS-05｜跨会话记忆隔离目标

**情况**

测试目标是确认新 Chat 是否会继承上一 Chat 中未授权的 NPC 私人知识。当前执行者只有一个开放会话，能够在该会话内模拟两个角色或两段状态，但无法创建并观测真实独立 Chat 的上下文。

**需要判断**

同会话模拟能证明什么、不能证明什么？是否需要独立干净会话？如果未获得独立目标 Chat 的原始输出，当前结论是什么？

## QA-SYS-06｜普通局部 Skill 修订

**情况**

本轮只修改 Narrative Presentation Skill 中一段普通环境描写方法，没有改变 QA 架构、硬门槛、状态语义、测试协议、Oracle 或模式路由。变更影响范围明确，可由现有 NQB 低压基准与一个相关综合场景覆盖。

**需要判断**

应该运行什么测试？是否需要启动 QA 系统自身验收？是否应默认建立独立干净 Chat？

## QA-SYS-07｜行动序列未完整执行

**情况**

固定夹具要求按序执行 ACTION 01–06。执行者完成了 ACTION 01–04，随后由于输出中断没有执行 ACTION 05–06，也没有状态证据能证明后两步已发生。前四步本身没有发现硬失败。

**需要判断**

执行状态与样本结论如何标记？能否把完整夹具判定为 PASS？


## QA-SYS-08｜NQB 快速回归与正式真实玩家校准

**情况**

Narrative Presentation Skill 发生一处局部修订。用户要求先做一次常规 NQB 叙事回归；没有要求自己逐回合扮演玩家。另一个任务则明确要求验证“真实玩家至少 8 个有意义回合”的正式 NQB 校准。

**需要判断**

两项任务分别应该选择什么执行方式？自动化合成结果能否冒充真实玩家回合证据？


## QA-SYS-09｜审核标准污染目标会话

**情况**

B 模式要求目标 Chat 在干净上下文中自动执行，之后把原始输出交给另一个审核会话。某份执行提示却把 Review Checklist 与 GM Packet 一起列为目标 Chat 的必读文件，导致目标 GM 在执行前已经接触评分标准。目标 Chat 没有读取 ORACLE，但已知审核维度；并且在执行结束后自行输出了评分和自评结论。

**需要判断**

这次执行能否继续标记为干净、独立的 B 模式？Review Checklist 应由谁、在什么时候读取？目标 Chat 是否应自行评分？如果目标已经读过评分标准或自评，哪些证据声明必须降级？


## QA-SYS-10｜目标版本未锁定

**情况**

执行提示写明使用 `main`，但没有固定 commit SHA；或者夹具 START 中仍保留 `EXECUTOR MUST INSERT EXACT COMMIT SHA BEFORE RUN` 占位符，执行者未填入便开始测试。报告只写了分支名，没有精确版本。

**需要判断**

是否可以把本次结果作为可复现的版本回归证据？缺少精确 commit 时应该如何处理？历史夹具固定在旧 commit 时，能否把它的结果算作当前 main 的验证？
