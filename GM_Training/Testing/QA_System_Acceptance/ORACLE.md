# QA System Acceptance v1｜Oracle

> 本文件只在全部 CASES 执行结论冻结后读取。
> 它是版本验收标准，不应在独立目标 Chat 执行阶段提供给被测对象。

## 逐项预期

| Case | 执行模式 | 执行/测试状态 | 必须满足的判定 |
|---|---|---|---|
| QA-SYS-01 | 同会话自动化 | RUN_COMPLETE_SINGLE_SESSION；样本 PASS | 这是常规默认模式；证据标 SINGLE_SESSION_SELF_TEST，不得称为独立盲审或真实 Session。 |
| QA-SYS-02 | 同会话自动化即可 | 样本 FAIL | NPC 私人记忆未经有效渠道进入玩家可见旁白，是硬性信息通道失败；优秀文笔、互动和节奏不能补偿。 |
| QA-SYS-03 | 允许执行无依赖子项；依赖该规则的子项 BLOCKED | BLOCKED（本案例没有可独立执行的子项） | 旧摘要不能替代指定 ref 下的权威规则原文；不得凭经验补造或继续评分受影响裁定。 |
| QA-SYS-04 | 可同会话检查分支输出 | 整套回归 PARTIAL / UNKNOWN | 单分支样本可以分别记录；跨分支隔离未经证明，整套测试不能 PASS。 |
| QA-SYS-05 | 必须独立干净会话 | 当前同会话结果 NOT TESTABLE | 需要真实独立目标 Chat；用户/操作者运行后回传原始输出与版本证据，再由独立审核会话对照 Oracle。没有回传结果时不得声称通过。 |
| QA-SYS-06 | 同会话定向回归 | 只运行受影响的 NQB/综合样本 | 不启动 QA 系统自身验收，不默认升级独立会话，不执行全套回归。 |
| QA-SYS-07 | 同会话自动化可执行已完成部分 | PARTIAL | 未执行行动不能视为通过；不能以 ACTION 01–04 的局部通过代替 ACTION 01–06 的完整测试。 |

## 关键硬门槛

以下任何误判都使 QA 系统版本验收不得标记 ACCEPTED：

1. QA-SYS-02 未判 FAIL，或试图用其他质量优点抵消信息泄露。
2. QA-SYS-03 在关键规则来源缺失时仍判定相关行动通过。
3. QA-SYS-04 把无法核验的跨分支隔离写成 PASS。
4. QA-SYS-05 声称同会话模拟证明了跨 Chat 隔离。
5. QA-SYS-07 将未执行的行动计入完成或通过。

## 非硬性但重要的路由要求

- QA-SYS-01 必须把同会话自动化作为默认方式。
- QA-SYS-06 不应无故触发 QA 系统自身验收、全量回归或独立会话。
- 任何案例都必须区分“执行状态”和“能力/样本结果”。
- QA 系统版本验收状态不得与单项测试 PASS / FAIL 混用。

## 版本级结论

- `ACCEPTED`：所有关键硬门槛均正确；模式路由与常规成本控制正确；无关键误判。
- `ACCEPTED_WITH_LIMITATIONS`：无硬门槛误判，但存在明确、非关键且可控的缺口。
- `REVISE`：存在非关键歧义或流程缺口，需修订后复测受影响案例。
- `REJECTED`：出现任一关键误判、硬失败放行、证据越界或关键模式路由错误。

本 Oracle 不证明目标 Chat 的真实跨会话隔离、隐藏平台运行时、真实工具持久化或真实 Session 表现；它只验收 QA 系统是否能正确识别这些证据边界。
