# GM Training Testing｜测试资料中心

本目录是 GM Runtime 与综合叙事质量测试的唯一当前入口。训练过程与工程优化仍分别归入 `Training_Logs/` 和 `Optimization_Reports/`。

| 目录 | 内容 | 使用规则 |
|---|---|---|
| [Fixtures](./Fixtures/README.md) | 可重复夹具、START/ACTION/ORACLE、合成测试输入 | 先读对应 START；遵守固定 ref、执行顺序和信息隔离要求 |
| [Execution Prompts](./Execution_Prompts/README.md) | 目标 Chat 提示词、操作者协议、执行交接 | 先区分目标 Chat、操作者和独立复核角色 |
| [Reports](./Reports/README.md) | 验收报告、运行记录、失败审计与复核 | 历史结论不可覆盖；新运行新增报告 |
| [Baselines](./Baselines/README.md) | NQB 基准场景包、玩家启动材料、审核表和执行提示 | 基准标准本体仍以 [NARRATIVE_QUALITY_BASELINE.md](../NARRATIVE_QUALITY_BASELINE.md) 为准 |

## 如何选择测试

**默认只跑能直接回答本次变更风险的测试。**先选一个最相关的现有夹具；只有它无法覆盖相邻风险时才增加第二项。完整回归不是日常默认动作。

| 投入级别 | 适用情况 | 默认做法 |
|---|---|---|
| **L0｜静态检查** | 文档、链接、格式、索引、小范围非行为改动 | 检查受影响文件、链接和 diff；不启动模型行为测试 |
| **L1｜定向验证** | 单一 Skill 方法、局部规则或明确缺陷修复 | 复用一个最相关夹具，单会话执行并做简要证据审查 |
| **L2｜关联回归** | 多项能力联动、关键流程或有明显回归风险的修改 | 主测试加一项必要的相关回归/变体；记录硬门槛、差异和未覆盖项 |
| **L3｜独立/真实环境验证** | 跨会话、持久化、工具运行时、隐藏信息隔离等同会话无法验证的目标 | 使用干净目标环境或独立审查；只有主张涉及真实玩家体验/迁移时才安排真实 Session |

L0–L3 表示**本次验证投入**，不是能力等级，也不是每次必须逐级执行的流程。真实 Session 是专门的迁移证据，不是所有测试的必经阶段。

## 测试类型与用途

| 测试族 | 主要回答的问题 | 何时调用 | 证据边界 / 当前注意事项 |
|---|---|---|---|
| **NQB-01 低压叙事基准** | 普通日常互动是否清楚、自然、可玩，基础信息边界是否正确 | 叙事 Skill、表达方法或普通互动质量发生变化 | v1.0 / v0.2 基准已有合成样本及 4 个真实玩家行动回合；真实短测覆盖有限，不能单独证明稳定性 |
| **Narrative Stress Test 01** | 持续压力、多 NPC 并行事务、时间窗口和动态细节维护 | 修改涉及高压叙事、并行任务或连续场景推进 | 首轮 8 个合成行动为单会话自测，结论 PARTIAL；玩家信息通道另有补充审计，不能把原报告中的局部 PASS 当作整体通过 |
| **G-16 信息通道回归** | NPC 私人信息、实际对白与玩家可观察信息是否正确隔离 | 修改涉及隐藏信息、NPC 知识、玩家可知范围 | 高压版为单一连续场景的 3 个行动；不证明跨 Chat 隔离或真实 Session 稳定性 |
| **L3 NPC / Runtime Transfer** | NPC 自主性、任务连续性、离场后状态，以及训练方法能否进入 Runtime | 修改 NPC 模拟、事务推进、连续性或 T3 迁移路径 | 按具体缺陷选对应夹具；合成自测不能直接升级为真实跑团证据 |
| **Context Assembly / H1-3** | 是否正确装配所需上下文、来源和状态；是否发生跨会话知识泄露 | 修改上下文路由、恢复、来源追踪或跨会话隔离 | Context 夹具检查装配/追踪；H1-3 私有 Canary 属高风险专项，不纳入普通回归 |
| **Runtime / 资源与结团** | 状态提交、重复投递、故障恢复、资源流水和结团冷恢复是否可靠 | 修改 Runtime 状态、资源事务、持久化或结团流程 | Roll Adapter 是本地合成文件系统参考测试；Module Closeout 16 项仓库回归通过，但真实跨 Chat 宿主持久化仍未测试 |
| **系统规则与掷骰路由** | 通用入口是否正确分派到系统专属规则，授权门槛是否保持 | 修改 Triangle Agency 规则路由、Playwall 或掷骰适配 | 只在对应系统机制变更时执行；不得把系统专属机制测试扩展成通用 GM 全量回归 |
| **仓库 CI** | 代码、脚本、Markdown 链接和格式是否符合确定性检查 | 代码、工作流、路径或仓库结构发生变化 | 只证明被 CI 覆盖的仓库条件，不证明模型行为或真实跑团质量 |

## 证据类型

执行成本与证据强度是两回事，报告必须区分：

- **确定性仓库/适配器测试**：脚本按固定输入运行，适合验证代码与状态转换。
- **SINGLE_SESSION_SELF_TEST**：同一会话执行并自审，适合快速行为回归与缺陷定位。
- **INDEPENDENT_REVIEW / CLEAN_TARGET**：独立会话或目标环境验证，适合信息隔离、跨上下文和高风险结论。
- **REAL_SESSION_EVIDENCE**：真实玩家互动与反馈，用于判断实际体验和迁移。

一次样本通过只表示该样本达到对应标准；不得把不同证据类型互相替代。

## 执行边界

- `SC-01` 至 `SC-18` 不属于默认回归清单；历史设计或操作者材料不得自动变成目标 Chat 的执行任务。
- 固定历史 ref 的夹具必须严格按 START 指定的 ref 和路径读取；不得自行替换为 main 最新版本。
- `P1_0R/p1_0r_fault_harness.py` 保留在原路径，作为独立脚本例外；从 Fixtures 索引链接过去。
- GM-only、操作者协议和 ORACLE 的标记不构成 GitHub 访问控制。不得把隐藏答案上传目标 Chat。
- 设计文件存在不代表测试已执行或通过；报告必须记录版本、证据等级和未测试边界。
