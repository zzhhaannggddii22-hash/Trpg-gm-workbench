# G-16 Player Information Channel Regression v1

> 类型：专项硬门槛回归 / SINGLE_SESSION_SELF_TEST
> 目标：检查 GM 是否将 NPC 未说出口的记忆、想法或私人知识错误写入玩家可见旁白。
> 范围：只验证 GM 输出的信息渠道；不评价完整叙事能力，不替代真实多轮平台测试或真实 Session。
> 隔离：全部内容为 TEST_ONLY_NON_CANON，不得写入 Campaign、NPC 正式档案或 Session Log。

## 文件

- START.md：目标 Chat 唯一启动输入，包含场景事实和三个独立分支。
- ORACLE.md：执行后审查标准。执行全部分支前不得读取或向目标 Chat 提供。

## 执行方式

1. **默认 A 模式：**在当前执行会话中读取 START.md 与必要的权威 Skill/Runtime 资料，固定被测 Workbench commit SHA；在一条回复内依次执行 Branch A、B、C。
2. 只向执行会话提供 START.md 和必要主持资料；不得提供 ORACLE.md、评分断言或本 README 的审查细节。
3. 每个分支按 START 的固定初始快照执行，只回应指定玩家行动，不自行增加调查、追问或额外场景。
4. 全部分支完成后，A 模式执行者才读取 ORACLE.md 自审，报告标记 SINGLE_SESSION_SELF_TEST。
5. **专项 B 模式：**若需要干净目标上下文与独立审核，操作者建立空白目标 Chat，按相同方式执行全部分支；目标 Chat 只交付原始输出与版本/读取证据，不读取 ORACLE、不自评。操作者把完整结果粘贴到独立审核会话，由审核者在收到结果后读取 ORACLE。
6. A/B 都能检查三个分支各自的输出；但当前单回复结构没有外部可观察的分支重置机制，不能证明同一 Chat 内部确实隔离了分支状态。若“同会话分支重置隔离”本身是验收目标，当前夹具不足，必须另行设计可观察的状态隔离测试或外部状态注入/读回机制。不得把三份输出都符合 Oracle 推断为隔离通过。

## 证据边界

本夹具可检查三种渠道在固定输入下的呈现差异。一次 PASS 只能说明本样本没有观察到对应泄露，不能关闭 G-16，也不能证明所有 Runtime 输出均可靠。G-16 只有在低压与高压针对性回归均通过、并在后续真实 Session 持续观察后，才可考虑关闭。

## 执行模式与隔离证据边界

- 同会话 A 模式可以检查 A/B/C 三个分支各自的玩家可见输出是否符合信息通道要求。
- 但在同一助手回复中声称“从相同初始状态重置”，本身不能独立证明分支间没有状态污染。若验收目标包含跨分支隔离，必须使用模式 B：每个分支在独立干净目标 Chat 中执行，回传原始输出后再由独立审核者对照 Oracle。
- 未取得上述独立隔离证据时，分支输出可分别记录 PASS，但整套跨分支隔离结论必须保持 UNKNOWN / PARTIAL；不得以三份输出都符合 Oracle 推断隔离已通过。
