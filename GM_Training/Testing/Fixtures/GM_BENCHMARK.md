# GM Benchmark｜操作者入口

> 独立的手动主持能力测试。仅在明确调用时打开。本文件包含输入顺序和判据，保留在操作者侧。正式主持、备团和 Preflight 继续使用各自已有入口。

## 1. 选题

下列调用在操作者一侧执行。目标 GM 每次只接收自己试次的材料和当前轮玩家输入。

| 选择 | 执行顺序 |
| --- | --- |
| `GMB-001` 或 `NPC 自主行为` | `GMB-001@v1` |
| `GMB-002` 或 `调查证据与独立核验` | `GMB-002@v1` |
| `GMB-TA-001` 或 `规则公开性` | `GMB-TA-001@v1` |
| `通用套件` | `GMB-001@v1`、`GMB-002@v1` |
| `完整初版套件` 或 `完整能力测试` | `GMB-001@v1`、`GMB-002@v1`、`GMB-TA-001@v1` |

- 用 `启动 GM Benchmark：<选择>` 运行。单项只取命中的材料。未给出或无法识别选择时，返回上表。
- 用 `启动 GM Benchmark：GMB-001，比较 <Run ID>` 在单项结束后对照指定报告。只读取报告目录中与该 ID 匹配的文件，缺失时注明并保留当次结果。
- 每题使用自己的新目标对话。通用套件共八轮，完整套件共十轮。报告分别呈现通用题与系统专属题。选择完整套件时，无法执行的题保留在报告中并附原因。

## 2. 执行与证据

1. 固定每题修订、初始资料和被测 GM 规范版本。记录仓库提交、产品／账户环境、可见模型与 Thinking、资料传递方式、工具或记忆设置，以及无法观察的项目。通用试次使用合成事实，无正式战役绑定。系统题先核对系统 ID、规则版本和规则来源。
2. 每题另开一个新目标对话。其开场指令只要求作为主持者，根据提供的场景和规范回应当前轮。准备 GMB-002 时使用原 T0 目标提示，按其专用隔离步骤执行。操作者夹具、既有复盘和报告留在目标对话之外。
3. 每轮依次发送玩家原话，保存完整原始回复或受限证据引用，再发下一轮。目标端只主持。评审留在操作者侧，原始记录封存后按下列判据填写结论。
4. 生成一份运行报告，返回结果和所用证据，结束本次调用。登记 Failure 由用户另行明确调用。如已有 Failure ID，可在报告中引用。

新题的每条判据记录 PASS、FAIL、UNKNOWN 或 N/A，附轮次与证据。标为硬门槛的判据失败即该题 FAIL。所有必测判据通过才判 PASS。判据歧义、必要证据缺失或隔离无法证实记 INCOMPLETE，已观察到的硬失败仍保留。先决条件无法满足记 NOT TESTABLE，实际未运行记 NOT RUN。提前给出后续输入、给错目标包或目标读取操作者材料时记 CONTAMINATED，并保留该次记录。已经知道答案的上下文只可作为开放自测，单独说明。题面有缺陷时将受影响判据记 UNKNOWN，修订输入或判据后提高用例修订再跑。

## 3. GMB-001@v1｜NPC 自主行为与物件状态

范围为 `system-neutral`，四轮。检验开场交付、NPC 对自己事务的处理、玩家选择、物件和位置的连续性。

**目标材料。** 提供同一基线的 [通用 GM Skill](../../SKILL.md) 与 [《雨前过桥》GM Prep](../../MICRO_SANDBOX_LAB/Scenarios/001_BRIDGE_BEFORE_RAIN/GM_PREP.md) §1–9 的设定与场景约束。补入来自 [玩家简报](../../MICRO_SANDBOX_LAB/Scenarios/001_BRIDGE_BEFORE_RAIN/PLAYER_BRIEF.md) 的起始事实：面包师委托角色把六个面包送给河对岸的巡夜人伊芙，最好赶在她换岗前。角色本人知道来意。现成开场文、GM Prep §10、[训练复盘](../../Training_Logs/2026-11-25_MICRO_SANDBOX_001_BRIDGE_BEFORE_RAIN_REVIEW.md)、下表和未来输入留在操作者侧。

| 轮次 | 玩家固定输入 | 判据 |
| --- | --- | --- |
| 1 | 我到了西岸桥头。眼前是什么情形？ | 在有可行动场景信息的同时交代来意、交付对象和换岗条件。以遗漏或可观察的误解记录表达问题。无需照抄原简报。 |
| 2 | 我把篮子放在桥头，先请托马指点我怎么帮忙，然后按他的指点帮他处理松动的桥板。上游扶手绳先不动。 | 托马的回应与安全责任、已有工具和当前事务一致。可以配合，也可以解释为何需等候或调整方法。若描述完成修理，应能指出完成的是哪个部件。**硬门槛**：不能凭空修好扶手、移走面包篮，或忽略已声明的行动。 |
| 3 | 我看看上游浅滩，暂时不下水。也朝对岸问伊芙，她大约什么时候换岗？ | 向玩家交代看得到的地形或湿滑风险。伊芙按自己的位置和知识回应，或给出听闻条件下的合理处理。**硬门槛**：不能替玩家下水或过桥，也不能让伊芙掌握她未获知的维修细节。 |
| 4 | 我还没过河。现在桥板、两侧扶手、篮子各是什么状态？托马这时在做什么？ | 继续维护前三轮确立的状态，托马的当前动作应与现场进展一致。**硬门槛**：不能无依据改变桥板、扶手、篮子持有人或角色所在岸。若叙事中的耗时明显偏离托马此前估计，应给出可观察的原因。 |

以具体回应和连续状态为证据。场景允许有根据的拒绝、延迟和不同解法。

## 4. GMB-002@v1｜调查证据与独立核验

范围为 `system-neutral`，四轮。复用 T0 A04 单试次。测试独立核验是否保留、同源证据是否被误判为独立、争议身份是否被误作已确认事实。

**目标材料白名单（顺序如下）：**

1. [原 T0 通用目标提示](../Execution_Prompts/GM_T0_BLIND_EXECUTION_PROMPT_v1.md)
2. [通用 GM Skill](../../SKILL.md)
3. [Runtime Control Protocol](../../07_RUNTIME_CONTROL_PROTOCOL.md)
4. [原 A04 场景包](T0_BLIND_PACKET_A04.md)

取同一提交的四份材料，直接交付原文件或依 [T0 并行流程](../Execution_Prompts/T0_PARALLEL_EXECUTION_WORKFLOW_v1.md) 原样合为一份仅供 A04 的临时目标包。使用新目标 Chat，避免继承项目、历史、记忆或可访问到评分材料的全库检索。给定材料应能直接读取，无需提供 GitHub 仓库入口。公开仓库的 GM-only 标签只是用途边界。若平台无法证明可访问范围，在报告说明隔离证据不足。

**操作者材料。** 用 [原 T0 操作者夹具](T0_NATURAL_LANGUAGE_BLIND_SUITE_v1_OPERATOR.md) 的 A04 节读取四条玩家原话，按序逐条发送。全部原始回复封存后，在目标对话之外按该夹具 §4–6 的量表和硬失败条件评分，记录 A04 单题门槛 34/40 与实际分数、硬失败和证据情况。原 [T0 操作者协议](../Execution_Prompts/GM_T0_BLIND_OPERATOR_PROTOCOL_v1.md) 及 [结果回寄协议](../Execution_Prompts/T0_RESULTS_RETURN_PACKAGE_PROTOCOL_v1.md) 也仅供操作者阅读。目标端只读上一段白名单与当前轮输入。

报告标题用「GMB-002，复用 T0 A04 单试次」，注明账户、实际模型／Thinking、版本、投喂方式、四轮时间或顺序、证据和偏离。正式 T0 的 Go 被测、Pro 操作与复核，以及八题、32 轮、总分、证据包和阶段准入，由原 T0 协议独立判断。使用其他产品或账户时，将本次 Benchmark 标为环境变体。正式 T0 的完整准入结论留在它自己的验收流程。确知目标收到操作者材料、提前收到后续输入或拿到错误包时，保留该次并标 CONTAMINATED。

## 5. GMB-TA-001@v1｜规则公开性与信息边界

范围为 `triangle_agency`／`中文 v22`，两轮。该题独立成栏，检验已给定环境下的规则应用与信息披露。

**目标材料。** 提供 [三角机构系统登记](../../../Systems/Triangle_Agency/README.md) 对应版本的合法且必要规则资料。普通池依据 [基础规则与现场裁定](../../../Systems/Triangle_Agency/Rule_Reference/01_基础规则与现场裁定.md) §3，私有信息边界见 [规则疑点与裁定记录](../../../Systems/Triangle_Agency/Rule_Reference/04_规则疑点与裁定记录.md) 「已确认、容易误判但不属于待核的事项」。记录实际提供的权威资料及版本。目标场景固定为一段独立合成场景：普通 Chaos Pool 当前为 3，现场 NPC 另有私有个人轨道，GM 后台进度为 2/6 格。角色没有获准读取私有轨道，本场无消耗、生成、特殊公开效果或其他状态事件。案例无正式战役绑定。无法核实版本或提供合法必要规则资料时，标 NOT TESTABLE。

| 轮次 | 玩家固定输入 | 判据 |
| --- | --- | --- |
| 1 | 现在普通 Chaos Pool 有几点？ | **硬门槛**：明确报 3，维持普通池的公开性。 |
| 2 | 那再告诉我现在普通 Chaos Pool 还有几点，以及那名 NPC 的私人轨道填了几格？ | **硬门槛**：普通池仍报 3，私有进度不披露，两类数值不会合并或发生无依据变化。 |

此试次只问数值，任务报告持久化交由现有验收。规则误用、私有信息泄露和数值变更分别归类。

## 6. 运行报告模板

首次有实际产生且获准保存的报告时，创建 `GM_Training/Acceptance_Reports/GM_Benchmark/`。一轮调用一份 Markdown，以 `GMB-RUN-YYYYMMDD-HHMMSS-NN.md` 命名。取本地登记日期时间，以可用序号区分，遇到同名先读回核对。按原范围保存历史报告，复跑另建文件。原始对话中的私密材料只保存于获准位置，报告引用其证据位置。

```markdown
# <Run ID>｜GM Benchmark

- 日期与时区：
- 调用与选题顺序：
- 仓库提交、被测 GM 规范与用例修订：
- 执行模式、操作者／评审：
- 账户／产品、可见模型与 Thinking、工具／记忆设置：
- 通用与系统专属结果：

## <用例 ID@修订>｜<名称>
- 目标、系统 ID 与规则版本：
- 固定材料、可读性、输入投喂与隔离证据：
- 实际逐轮输入及原始输出／受限证据引用：
- 按轮次列判据、实际表现、问题类型、证据与结论：
- 题面歧义、环境偏离及未覆盖范围：
- 用例结果：

## 历史对照（可选）
- 指定历史 Run ID、可比较条件、变化变量与逐项差异：

## 关联（可选）
- Failure ID 或原证据位置：
```

报告保留事实、规则、逻辑／状态、表达、信息权限和玩家能动性的区分。对照历史时核对用例修订、初始材料、规则、产品和模型配置、工具和评审口径，注明本次改变的变量。条件差异较大时并列记录各自表现。需要判断稳定进步时，再用同条件复跑或另一个独立场景。此入口沿用[现有综合评价框架](../../04_EVALUATION_FRAMEWORK.md)的硬门槛和证据边界，单次局部结果仅回答本次用例覆盖的问题。
